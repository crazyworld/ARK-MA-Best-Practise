# 阻断上报规范

> **层级**: L3 规范层
> **加载**: 需阻断并上报时加载
> **行数上限**: ~50行

---

## 一、阻断条件

以下情况必须阻断：
- 数据来源不可信或无法验证
- 核心结论存在根本性错误
- 涉及合规/法律风险
- 超出Agent能力范围
- 意图理解严重偏离

---

## 二、阻断输出格式

```markdown
## 阻断 - {文件名/项目ID}

**原因**: {一句话}
**处理**: 人工介入 / Supervisor决策 / 重新研究
```

---

## 三、原因描述规范

**要求**：一句话，≤20字

**正例**：
```
核心结论与数据矛盾
数据来源无法验证
用户需求理解严重偏离
涉及未公开财务数据
```

**反例**：
```
❌ 经过仔细审查，发现报告中的核心结论部分存在与前文数据不一致的情况，建议重新核实
```

---

## 四、处理方式判定

| 处理方式 | 适用场景 |
|----------|----------|
| **人工介入** | 涉及合规、法律、敏感信息 |
| **Supervisor决策** | 需求理解分歧、优先级判断 |
| **重新研究** | 数据错误、结论错误需重做 |

---

## 五、上报流程

```
1. 输出阻断报告
2. 停止当前审计流程
3. 等待处理方响应
4. 处理完成后重新审计
```

---

## 六、阻断记录

每次阻断需记录：
- 阻断时间
- 阻断原因
- 处理方式
- 最终结果
