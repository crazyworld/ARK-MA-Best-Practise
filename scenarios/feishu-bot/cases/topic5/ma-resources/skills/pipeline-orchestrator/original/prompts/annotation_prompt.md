## 任务说明

对每条社媒内容进行二维标注。每条内容独立判断，输出结构化 JSON。

---

## 输入字段

- `content`：正文内容（必填）
- `title`：标题（可选，辅助判断）
- `视频封面内容识别` / `音频内容识别` / `视频文本识别`：下载数据已有的识别文本；分别保留，非空时必须传入并参与活动相关性判断，缺列或空值不代表噪音，不重新识别或伪造结果
- `platform`：发布平台（可选，辅助情感判断）
- `campaign_name`：本次复盘的活动名称（项目启动时填入，见「项目配置区」）
- `campaign_context`：确认后的活动主体、事件/期次、时间和排除范围
- `activity_keywords`：实际活动取数表达式，保留 OR/AND 分支关系；不是产品分析词

---

## 标注任务

### 1. 情感倾向（sentiment）

判断该条内容的整体情感倾向：

| 标签 | 判断标准 |
|------|---------|
| 正面 | 明确表达积极评价、推荐、喜爱、支持 |
| 中性 | 纯信息传递、无明显情感、内容展示/介绍 |
| 负面 | 抱怨、批评、质疑、失望、负面情绪 |

> 正负并存时，以主导情感为准。

### 2. 是否活动相关（campaign_relevant）

判断该条内容是否与「`{{campaign_name}}`」这次活动直接相关：

| 标签 | 判断标准 |
|------|---------|
| 是 | 内容明确提及、参与、响应或评价本次活动；**赞助型活动（播客/节目/IP合作）中，提及被赞助内容（节目名/播客名/合作话题）也视为活动相关，无需同时提及品牌名** |
| 否 | 品牌一般内容、其他品牌讨论、行业泛讨论等与本次活动无关 |

---

### 标注前置条件与相关性上下文规则

同时读取 `视频封面内容识别`、`音频内容识别`、`视频文本识别`：字段有关键词时也看命中句和前后各一句，无句界则看整段；每个字段独立取窗口，标明证据来源，不跨字段拼接句子。正文很少或只有标签时，封面中的真实活动信息可作为保留依据。识别错字或证据冲突时结合其他字段核查；不能仅据封面命中判相关，也不能仅据正文无关判噪音。该字段缺失只记录无信息，不自动剔除。完整规则见 `KS_Noise_Review.md`。

先定位实际关键词的每处命中，查看**关键词当句、前一句、后一句**，判定是否在讨论本次活动。三句信息不足则扩读标题、全文和其他命中；不要求 AND 分支中的词连续或同句出现。任一窗口存在真实活动关联时，不能仅因另一处撞词而剔除。

同名歧义、无关正文挂活动话题、其他期次/其他活动、超出本次范围的品牌日常讨论，判为“否”，Producer 默认剔除，无需用户确认。真实活动投诉或差评仍为“是”，情感与相关性独立。纯图文、无命中、正文缺失不能仅据此判为噪音，应按 `KS_Noise_Review.md` 扩查；标注前证据不足的内容保留进入本轮正式判断，并在独立审核记录中说明，不编造关联证据。

执行本标注任务前，Producer 必须已完成高互动与峰值去噪；本轮仅接收 `denoised_data.xlsx` 的保留行，已剔除内容不再做相关性或情感标注。不得先跑本轮再做去噪；本轮完成后进入类别发现。下述标注 JSON 仍只有两个字段，命中句证据及噪音审核结论另存审核记录。

## 输出格式

仅输出以下 JSON，不附加任何解释文字：

```json
{
  "sentiment": "正面|中性|负面",
  "campaign_relevant": "是|否"
}
```

**每个新项目开始前，由 Producer 填入以下内容，然后将本文件路径传入 pipeline：**

```yaml
campaign_name: "{{待填入 — 本次复盘的活动名称}}"
```

## 轮次二新增字段：ugc_category + discussion_dimension

> **执行时机**：轮次一完成、Phase-发现与 Phase-ugc-discovery 中**适用项**均经独立 Validator 来源审核通过后执行（与观点标注并行，但为独立任务）。
> **路由**：同轮次一（< 1000 行 → 直接 API；≥ 1000 行 → DataHub）
> **任务编排（P0）**：这两个字段作为独立的「属性标注」任务提交，输入为**全部活动相关行（含中性）**；**禁止**并入正面/负面观点任务（正/负面任务只含部分行，并入会导致中性行漏标）。多活动时按活动分别提交，各用自己确认的 `ugc_category_list`。

---

### 字段 3：ugc_category（UGC 参与方式）

**适用范围**：`内容类型` = UGC 且 `是否活动相关(AI)` = 是 的行
**其余行**：直接填 `N/A`，不进入标注

> ⚠️ **本字段使用动态类别列表，不使用固定标签**
> 类别列表由 Phase-ugc-discovery（见 `KS_Data_Processing.md`）自主发现后注入，
> 每个项目的类别名称和定义均不同，执行前必须先完成发现步骤。

#### 标注规则

**执行前提**：Producer 已完成 Phase-ugc-discovery，并将发现的类别表注入本 prompt（见「项目配置区」）。

判断该 UGC 内容属于 `{ugc_category_list}` 中的哪一类（选 1 个）：
- **分类依据是用户做了什么动作、采用什么内容形式**，不是情感、态度或观点倾向——同样的参与动作与内容形式，无论内容是夸是骂，都归入同一类（情感另有 `sentiment` 字段）
- 优先按内容的**主要行为意图**分类，而非关键词匹配
- 若内容同时符合多类，取**篇幅最重/意图最明显**的一类
- 若所有类别均不符合，填 `其他`

#### 输出格式

```json
{
  "ugc_category": "{类别名称，取自 ugc_category_list，或 N/A，或 其他}"
}
```

---

### 项目配置区（ugc_category 相关）

**Phase-ugc-discovery 完成后，由 Producer 填入以下内容：**

```yaml
ugc_category_list:
  - name: "{{类别名称1}}"
    definition: "{{判断标准1}}"
    examples:
      - "{{原文示例1}}"
      - "{{原文示例2}}"
  - name: "{{类别名称2}}"
    ...
```

> ⚠️ `ugc_category_list` 未填入时禁止开始 ugc_category 标注。

---

### 字段 4：discussion_dimension（讨论维度）

**适用范围**：`是否活动相关(AI)` = 是 的行（PGC + UGC 均适用）
**其余行**：直接填 `N/A`，不进入标注

#### 标注规则

判断该条内容的**主要讨论焦点**属于以下哪个维度（选 1 个，取主导维度）：

| 维度 | 判断标准 | 典型特征 |
|------|---------|---------|
| 品牌 | 内容主要讨论品牌形象、品牌价值观、品牌历史、品牌合作背景、品牌联名意义等 | 品牌名频繁出现；讨论品牌定位/调性；情感指向品牌整体 |
| 产品 | 内容主要讨论具体产品功能、使用体验、成分/材质、外观设计、性价比等 | 有具体 SKU 名称/型号；描述使用后感受；产品功能评价 |
| 活动 | 内容主要讨论活动机制、参与体验、活动规则、抽奖/奖励、打卡流程等 | 提及活动流程词汇；讨论"怎么参与""奖品是什么"；情感指向活动体验本身 |

> **多维度并存时**：取篇幅最重、情感表达最强的维度作为主维度。

#### 输出格式（discussion_dimension 单独标注时）

```json
{
  "discussion_dimension": "品牌|产品|活动|N/A"
}
```

---

### 合并输出格式（ugc_category + discussion_dimension 在「属性标注」任务中一次标注时）

「属性标注」任务（见上方任务编排）对两个字段一次标注，输出格式如下：

**输入字段**：title / content / campaign_name / content_type（内容类型）/ campaign_relevant（轮次一结果）

```json
{
  "ugc_category": "{取自 ugc_category_list 的类别名称} | N/A | 其他",
  "discussion_dimension": "品牌|产品|活动|N/A"
}
```

> ⚠️ `ugc_category` 的实际取值来自项目配置区注入的 `ugc_category_list`（Phase-ugc-discovery 发现），每个项目不同。旧枚举值「模仿打卡|创意改编|测评分享|自发安利」已废弃，禁止直接使用。

**过滤逻辑（标注前由 pipeline 处理，不依赖 LLM 判断）**：
- `campaign_relevant` = 否 → 两个字段均填 `N/A`，不进入 LLM
- `campaign_relevant` = 是 且 `content_type` = PGC → `ugc_category` 填 `N/A`，仅标注 `discussion_dimension`
- `campaign_relevant` = 是 且 `content_type` = UGC → 两个字段均标注
- `campaign_relevant` = 是 且 `content_type` = 未知 → 两个字段均标注（`ugc_category` 按正常规则判断）
- **与情感无关**：以上过滤只看 `campaign_relevant` 与 `content_type`；`sentiment` = 中性的内容**同样标注**，不得跳过

---

### 易混淆场景处理

| 场景 | 正确处理 |
|------|---------|
| 内容同时提及产品和活动 | 看主要篇幅和情感指向；活动参与流程为主 → 活动；产品使用体验为主 → 产品 |
| 内容行为意图多重叠加 | 取**篇幅最重/情感表达最强**的一种参与行为作为 ugc_category 主类；模糊时优先参考 `ugc_category_list` 中各类别定义 |
| 所有类别均不符合 | 填 `其他`，不得强行归入最接近的类别 |
| 纯图片无文字 | 有明确活动标签/话题 → 参照 ugc_category_list 中描述参与行为的类别；无标签 → `其他` |

## 各轮共同的证据边界（2026-11-11）

每个观点标签须指向原帖中针对该对象的实际评价；仅IP/品牌/商品名称、价格列表、赠送规则、CTA或OCR识别不新增观点。相同评价不能机械同时归入形象、包装及赠品多个类别。抱怨第三方的情绪不转成品牌负评，商品自带褒义名称不等于作者正面态度。未能辨认评价对象时记录证据歧义，使用现有兜底规则，不强配标签。媒体不可用不假装已看、不自动判无关；已有识别文本注明来源。属性仍按实际适用范围填动态类别及N/A，不因中性而跳过。
