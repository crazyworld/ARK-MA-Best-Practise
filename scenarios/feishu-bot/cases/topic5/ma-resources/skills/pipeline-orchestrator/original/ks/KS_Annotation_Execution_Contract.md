# Topic5 标注执行与有限审核契约

> 版本：v1.0 · 2026-11-11。适用于所有活动；用户本次确认的500条上限取代历史“必须审核全量10%”要求。保留正确率最低90%、目标95%及既有合法性、覆盖门槛。程序检查不代替语义审核。

## 1. 每轮单独校准，先拦结构错误

轮次一、正面观点、负面观点、属性标注分别校准；前一轮通过不能代替后一轮校准。小样本覆盖正常内容、否定/反讽/转述、对象歧义、多观点、媒体缺失及该任务特殊标签，数量按类别与歧义实际需要确定，不为凑数量重复收费。优先复用已有原帖和已核实证据。

校准前冻结任务适用范围、允许类别、边界、输出格式和版本。观点每个标签须有对应的实际评价证据；品牌/IP/SKU名称、价格数字、赠送规则、话题及CTA的出现本身不形成独立评价。对特定物品的同一句评价不机械重复分配给形象、包装、赠品等类别。可用任务输出依据或审计侧表保存证据，不强制改变通用API结构。

先执行全量程序预检：稳定ID、输出解析、字段合法性、动态类别枚举、标签数量、重复标签及适用范围。未知/PGC/活动无关行不得填UGC参与方式；活动无关行不得填主讨论对象。不适用占位按当前元数据规则执行，不能为了结构通过强行分类。入口为 `tools/check_annotation_structure.py`；允许类别来自本轮已审核配置，不使用案例类别作默认值。与现有覆盖脚本共同使用。

校准发现错误时按错误类型修边界，再用未参与修改的新样本检查。同一样本修好只证明修复完成，不证明泛化准确率。每个任务连续两次校准或复审仍出现同类系统错误时，必须进入原因诊断：证据不足、类别定义不清、传参/解析问题或模型能力；记录下一种处理办法后再执行，不自动全量重跑或新增付费任务。

## 2. 人工语义审核每活动、每轮最多500条

每活动、每轮按帖子去重，首次审核的基础数量为 `min(ceil(应标注帖数×10%), 500)`；小数据全部不超过总体。轮次二正负观点合用额度，不分别各取500。属性任务另属一轮，仍最多500。校准、类别发现来源核验、随机抽查、重点核查与返工复审共用对应轮最多500个不同帖子额度；同帖复看不新增帖子，但记录次数。校准样本不混入独立验收正确率，预算须预留独立验收新样本。不用拆任务、换文件或给同一轮改名绕过上限。

`tools/plan_annotation_review.py` 生成计划；传入本活动本轮所有已审ID的并集，并按实际情况设置 `--reserve`（工具默认预留100条，可调整，不能突破总上限）。首次样本受剩余额度及预留数限制，记录实际计划。轮次二/属性须传当前已审核类别与适用性配置：观点仅取相关正负面且该方向发现适用；属性仅取活动相关内容，主对象与UGC参与方式分别记录适用总体，UGC不适用时不计入UGC分母。配置缺失先补齐，不猜适用性。

配置键为 `positive_labels`、`negative_labels`、`ugc_labels`（已审核允许类别数组），`positive_applicable`、`negative_applicable`、`ugc_applicable`（当前发现阶段是否适用），以及按当前定义记录的 `dimension_labels`、`max_opinion_labels`、`opinion_not_applicable`。不适用方向的类别数组可为空，必须显式设置对应applicable=false；类别和“其他”的可用性不从待审结果反推。

输入采用现有JSON行对象列表或 `{columns, rows}` 表格结构；Excel来源先用既有导出转换，工具不新增Excel依赖。调用示例：`python tools/check_annotation_structure.py --input <当前标注JSON> --stage full --config <已审核类别JSON> --output <结构审计JSON>`；`python tools/plan_annotation_review.py --input <当前标注JSON> --stage round2 --config <已审核类别JSON> --reviewed-ids <本轮已审ID数组JSON> --reserve 100 --output <本轮审核计划JSON>`。生成计划不等于已经完成语义审核。

在额度内按当前标签分层、层内固定种子随机抽取，优先覆盖不相关、负面、其他、空值/非法及证据歧义，同时保留相关、正面、中性与主要正常类别。稀少特殊类可全查，但不得挤掉全部正常样本；小总体确实没有某类时记不适用。各层计划数量、总体数量、实际名单及未覆盖层必须留存。重点核查已知疑难/高互动帖与随机样本分开记录，不为追加重点样本突破500条；高点专项核查沿用自身流程，但不能包装成新增标注审核额度。

不相关与负面可重叠，先去重再分配额度。优先特殊类意味着非等概率抽样：披露分层抽样方法、各层样本及错误率，不称全量真实准确率。验收沿用各字段独立样本正确率最低90%、目标95%；校准/定向核查不计入该比率。可另报按总体层权重计算的估计，不能用估计替换未达标的验收结果。分层结果用于定位问题，不新增每类独立门槛。

500为语义审核上限，程序仍扫描全量合法性及适用性。全量扫描不会读取媒体或请求LLM，不产生全量人工审核。空值/其他比例仍用全量适用帖计算，不由500条估算。

## 3. 退回须给出可执行修复范围

每次退回记录：错误类型、原帖证据、受影响字段/类别、受影响范围确定方法、精确ID或筛选条件、修复办法及复核办法。个别错误修对应行；系统错误修边界并处理受影响总体，不只修改抽样错帖，也不默认重标所有数据。程序可修的范围或解析错误优先程序修复并保留原结果；语义错误不能靠字符串替换假装修好。

缓存以原帖内容/媒体证据指纹、任务定义/类别版本、审核字段为键。只改变格式或无关字段时复用原语义记录；原文、证据、规则或目标标签发生变化时，失效对应缓存。保存修复前后差分及下游影响，不让源版本变化触发无关模块重复审核。

返工复核在该轮500个不同帖额度内完成，已修错帖用于修复验证，尚未用于校准的新样本用于独立验证。额度用完仍无法达到门槛时记录 `blocked_quality` 和已完成诊断，停止受影响下游、继续不受影响工作；不得降门槛、声称通过或自动改为全量人工审核。需要扩大人工额度或新增收费处理时给出具体范围与费用，取得当前项目授权后执行。

## 4. 跨工具媒体证据入口

先检查实际能力并保存：已有正文/OCR/ASR等识别文本是否可用、图片/视频工具是否可用、外部识别服务是否可用及预算范围。读取成功不等于API或媒体可用，不把Codex工具名作为必需依赖。

1. 完整文本与已有识别结果足够时直接判断，保存对应原句及来源。
2. 文本不足且有真实媒体能力时核验媒体；完整图片、视频帧、完整视频及已有OCR分别记录，不相互冒充。
3. 本地工具无能力但有已配置的媒体识别服务时，可在现有授权及预算内补证；保存服务、输入媒体、识别结果及来源，识别文本不是独立真值。
4. 两者都没有时，优先把影响高点、热门榜、相关性剔除或关键口碑的疑难帖转人工/用户辨识；仅请求必要条目，不要求全量看图。未完成者记待核实。

能力缺失不等于噪音，也不能用强制中性或无关掩盖未知。去噪保留资格、正式标签、热门展示资格及结论边界分别记录；无法核实的审核样本不计正确，适用分母不缩小。用户辨识注明来源，不冒称模型已看。按 `KS_Report_Scope_Contract.md` 执行补证后的最小更新链。
