## PGC / UGC 分类规则

| 平台 | UGC 条件 | PGC 条件 |
|------|---------|---------|
| 微博 | 粉丝 < 10万 且非黄V/蓝V/金V | 黄V/蓝V/金V，或粉丝 ≥10万 |
| 抖音 | 粉丝 < 10万 | 粉丝 ≥10万 |
| 小红书 | 粉丝 < 1万 | 粉丝 ≥1万 |
| 新闻 / 微信公众号 | 无 | 全部视为 PGC |
| 知乎 / B站 | 粉丝 < 10万 | 粉丝 ≥10万 |

## 达人层级（kol_level）分层阈值表

> **用途**：Step 5 清洗时，由 `粉丝数` + `平台标签` 派生 `kol_level` 字段。
> **执行规则**：禁止使用统一数值——不同平台粉丝体量不同，必须按平台查此表。

### 各平台分层阈值

| 平台 | 头部 | 腰部 | 尾部 | 素人/KOC |
|------|------|------|------|---------|
| 抖音 | > 100W | 10W–100W | 1W–10W | < 1W |
| 小红书 | > 50W | 5W–50W | 1W–5W | < 1W |
| 微博 | > 100W | 10W–100W | 1W–10W | < 1W |
| B站 | > 100W | 10W–100W | 1W–10W | < 1W |
| 快手 | > 100W | 10W–100W | 1W–10W | < 1W |
| 视频号 | > 50W | 5W–50W | 1W–5W | < 1W |
| 知乎 | > 10W | 1W–10W | 1000–1W | < 1000 |
| 新闻 / 微信公众号 | N/A | N/A | N/A | N/A |

> **新闻 / 微信公众号**：全部为 PGC，无粉丝数概念，`kol_level` 填 `N/A`，不参与达人层级统计。
> **粉丝数为空或 0**：`kol_level` 填 `未知`，统计时单独计数，不并入四个层级。

### kol_level 与 PGC/UGC 的对应关系

`kol_level` 和 `内容类型`（PGC/UGC）是两个独立字段，但粉丝数阈值有关联：

| 平台 | kol_level = 素人/KOC | 内容类型 |
|------|---------------------|---------|
| 抖音 | 粉丝 < 1W | 通常为 UGC（PGC 阈值 ≥10W） |
| 小红书 | 粉丝 < 1W | UGC（PGC 阈值 ≥1W，即尾部及以上为 PGC） |
| 微博 | 粉丝 < 1W | UGC（PGC 阈值 ≥10W，即腰部及以上为 PGC）|

> ⚠️ 两字段独立存在：原始数据的 `内容类型` 字段已标注 PGC/UGC，`kol_level` 由 `粉丝数` 派生，两者不互相覆盖。统计时**以原始 `内容类型` 字段为准**，`kol_level` 仅用于达人效能分析（2.N.4）。

### 达人层级效能分析范围说明

- 报告 2.N.4「达人层级效能」分析时：**建议仅统计 PGC 内容的层级分布**，UGC 内容以素人/KOC 为主，层级差异无分析价值，可单独注明「UGC 内容以素人为主（占 XX%）」，不展示 UGC 的层级分布柱图。
- `kol_level` = 未知 的行：在图表注释处说明占比，不纳入层级柱图。

## 内容主题标签设计原则（MECE）

> **来源**：内部规范文档《数据维表制作注意事项》
> **适用范围**：所有 Topic 内容主题分类标签的设计与审查

### 四条基本规则

| # | 规则 | 说明 | 常见违规示例 |
|---|------|------|------------|
| 1 | **同级标签不交叉、覆盖全集** | 同级分类之间内容不应重叠，所有内容能归入某一标签 | "美食推荐"与"探店内容"存在交叉 |
| 2 | **标签只涉及分类，不涉及情感倾向** | 每个标签都应能被打上正面/中性/负面情感；情感判断由独立「情感倾向」字段承担 | "负面反馈"（把情感混入内容主题）|
| 3 | **根据行业/品类/品牌提取特征** | 标签应能区分该类目特有的内容话题，不宜过于泛化 | 全部标签通用于任何行业，无法体现品类特征 |
| 4 | **明确决策目的** | 标签设计前须了解报告的决策用途，避免提取了无法指导决策的维度 | 提取"内容长度"维度但无对应决策动作 |

### 维度隔离原则

以下维度**禁止**混入内容主题标签（每个维度有独立字段承载）：

| 禁止混入的维度 | 正确字段 | 违规示例 |
|-------------|---------|---------|
| 创作者类型（KOL/KOC/UGC） | `作者类型` / `PGC/UGC` 字段 | ~~KOL/达人种草~~ |
| 情感极性（正面/负面/中性） | `情感倾向` 字段 | ~~负面反馈~~ |
| 平台来源 | `平台` 字段 | ~~小红书种草~~ |
| 发布时间 | `发布时间` 字段 | ~~节日相关内容~~ |

### 适用框架

| 框架类型 | 适用场景 | 重点维度 |
|---------|---------|---------|
| 舆情分析框架 | 品牌/事件监测 | 讨论主体、情感倾向、传播渠道 |
| 社交聆听框架 | 产品/用户研究 | 内容主题、使用场景、用户需求 |

## 观点类别 与 UGC 参与方式 的定义边界（P0，v0.7 新增）

> 两者都是**标注类别**，各自回答不同的问题；情感、态度、观点倾向由独立的「情感(AI)」字段承载，**不得写进类别**。

| 项 | 回答的问题 | 类别由什么构成 | 命名方式 | 不得出现 |
|---|---|---|---|---|
| **观点类别**（`观点(AI)`，2.N.3） | 用户**在讨论什么**？ | 讨论的话题 / 对象 / 方面 | 名词性短语 4–10 字：口感风味、价格优惠、联名周边、门店排队 | 情感或态度词（好评、差评、吐槽、喜欢、失望、满意、推荐）；评价句（口感好、价格贵） |
| **UGC 参与方式**（`ugc_category`，2.N.4②） | 用户**做了什么**？ | 参与**动作**，以及采用的**内容形式** | 动词或形式短语 2–4 字：到店打卡、开箱测评、晒单分享、二创改编、提问求助 | 情感、态度或观点倾向（好评分享、吐槽避雷、种草安利） |

**关键理解**：
- 观点类别的正/负面方向来自「情感(AI)」。正面观点列表里的类别是“用户在**夸**什么话题”，类别名只写话题（如“口感风味”），“夸”这层意思放在判断标准里（如“提到口味并表示认可”）
- 同样的动作和内容形式，无论内容是夸还是骂，**归入同一参与方式**；参与方式不反映满意度
- 倾向类的表述若确有分析价值，应通过「情感(AI)」与类别交叉分析得到，而不是增加带倾向的类别

### MECE 要求（两类标注共用）

| 要求 | 含义 | 自查方法 |
|---|---|---|
| **互斥** | 各类边界清晰，不包含、不交叉 | 任取两类，能否用一句话说清区别 |
| **穷尽** | 类别合起来覆盖绝大多数内容，余者归「其他」 | 「其他」占比 ≤ 20%（`check_coverage.py` 会提示） |
| **同一维度** | 不把不同维度的类别混在一套里 | 观点：都按话题，不混入人群/平台；参与方式：**动作与内容形式可并列**（如 到店打卡、开箱测评、晒单分享、二创改编），但不得混入话题、情感、人群；并列的类别须互斥，一条帖子按主要参与方式归一类 |

- **一条内容标几类**：参与方式（`ugc_category`）每条只归 1 类；观点允许一条内容兼有两个**不同话题**时标 1–2 类（互斥针对**类别定义**，不是针对帖子）。观点占比以“命中该类的帖子数 ÷ 该方向帖子总数”计算，此时各类占比之和可能超过 100%，报告中需写明口径
- **违规示例**：观点类别“口感好 / 口感差”（把情感拆成两类）；参与方式“好评分享 / 吐槽避雷”（按倾向分）；“探店打卡 / 美食推荐”（动作与话题交叉）
- 本节与上方「内容主题标签设计原则（MECE）」同源，规则 2「标签只涉及分类，不涉及情感倾向」在这里落实到观点与参与方式

## 2.N.2 品牌声量 & 产品声量计算定义

> **数据来源**：三次 SSJH-Social-Stat 取数，不依赖 DataHub 标注字段

### 计算方式

| 指标 | SSJH 查询关键词 | 说明 |
|------|--------------|------|
| 活动总声量 (A) | `{活动关键词}` | 活动相关全部帖子 |
| 品牌声量 (B) | `{活动关键词}+{品牌词}` | A 中正文同时含品牌词的帖子（AND） |
| 产品声量 (C) | `{活动关键词}+{产品词}` | A 中正文同时含产品词的帖子（AND） |
| 品牌声量占比 | B ÷ A | 活动中品牌被提及的渗透率 |
| 产品声量占比 | C ÷ A | 活动中产品被提及的渗透率 |

> B 与 C 可重叠（同一帖子可同时含品牌词和产品词），不做互斥处理。

### 示例（三养·春日来信活动）

```
活动总声量 (A) = SSJH query("春日来信")           → 12,400 条
品牌声量   (B) = SSJH query("春日来信+三养")      →  3,800 条（31%）
产品声量   (C) = SSJH query("春日来信+五感辣拉面") →  2,100 条（17%）
```

### 注意事项

- `{品牌词}` 取需求确认单中的 `brand_keyword`
- `{产品词}` 取需求确认单中的 `product_keyword`（若多个产品，每个产品单独一次查询后求和）
- 三次查询须使用**相同的时间范围和平台范围**

## 活动类型推断规则（第三方监测视角）

> **触发条件**：需求确认单中 `campaign_type = "待数据推断"` 时，Planner 在方案阶段根据以下规则推断活动类型。

### 信号矩阵

| 活动类型 | 强信号 | 佐证信号 |
|---------|--------|---------|
| **新闻公关稿传播** | 新闻平台/微信公众号占比 ≥50%；PGC 占比 ≥80%；内容高度同质（标题相似度高） | 话题标签稀少；无明显互动引导；发布时间高度集中（1-2天内） |
| **KOL/KOC 种草** | PGC 占比 ≥40%；作者粉丝数中位数 ≥1万；内容含"推荐""安利""测评"等关键词 | 小红书+抖音占比高；情感偏正面（≥60%）；话题多为产品功能/体验相关 |
| **话题活动** | 内容含统一话题标签（#xxx#）；UGC 占比 ≥60%；参与式内容（"打卡""参与""抽奖"） | 内容量有明显时间峰值；互动量较高（评论/点赞比正常高）；情感分布较分散 |
| **直播活动** | 内容含"直播""主播""直播间"关键词；发布平台集中于抖音/微博；时间集中在某几天 | 互动量峰值明显；含购买引导词（"链接""点击""下单"） |
| **线下活动** | 内容含"打卡""线下""到店""展览""现场"；配有现场图片描述；地点关键词集中 | 发布时间分散（陆续打卡）；UGC 占比高；情感偏正面 |
| **品牌联名** | 内容同时出现两个及以上品牌名称；话题含联名关键词 | 粉丝覆盖面广（两品牌受众叠加）；媒体报道比例较高 |

### 推断步骤

1. **平台分布**：统计各平台占比 → 新闻/公众号高 → 倾向公关稿；小红书/抖音高 → 倾向种草或话题活动
2. **PGC/UGC 比例**：PGC ≥80% → 公关稿；PGC 40-80% → KOL种草；UGC ≥60% → 话题活动/线下
3. **关键词提取**：从标题+正文提取高频词 → 比对各活动类型的特征关键词
4. **时间分布**：声量高度集中（1-3天）→ 公关稿/直播；分散分布 → 话题活动/线下打卡
5. **综合判断**：至少 2 个强信号 → 确认该类型；仅 1 个强信号 + 佐证 → 标注"较可能"；信号不足 → 标注"待确认"

### 输出格式

```
campaign_type（推断）：KOL/KOC 种草（高置信度）
推断依据：
- 小红书+抖音合计占比 72%（强信号）
- PGC 占比 58%，粉丝中位数 3.2万（强信号）
- 高频词：测评/安利/推荐/初体验（特征关键词匹配）
```

### 示例（优衣库大师T）

| 信号类型 | 观察值 | 解读 |
|---------|--------|------|
| 平台分布 | 新闻平台占比 68%，微信公众号 21% | 公关稿传播特征显著 |
| PGC 比例 | 92% | 机构/媒体主导，非用户自发 |
| 内容同质性 | 标题高度相似（"探访大师T原料/溯源"） | 统一口径的稿件传播 |
| 话题标签 | 几乎无统一话题标签 | 非话题活动特征 |
| **结论** | **新闻公关稿传播（高置信度）** | — |
