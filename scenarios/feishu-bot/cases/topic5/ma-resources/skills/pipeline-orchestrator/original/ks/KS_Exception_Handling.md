## 常见异常与处理规则

| 异常场景 | 处理方式 |
|---------|---------|
| 某平台数据量极少（<50条） | 单独说明数据量，降低该平台结论权重，备注"样本量有限" |
| 互动量字段全为空 | 仅统计声量（发帖量），不输出互动量指标，报告中注明 |
| 发布时间格式不统一 | 统一转换为 YYYY-MM-DD，无法解析则标记为"日期异常"并排除 |
| 重复内容（同一帖子多次采集） | 按内容 ID 去重，无 ID 则按"作者+发布时间+正文前50字"去重 |
| AI 标注返回空/异常 | 标记为"标注失败"，不纳入情感/主题统计，在报告中注明排除量 |
| 数据量超出预期（>10万条） | 告知用户，确认是否分批处理或抽样分析 |
| **`粉丝数` 字段缺失** | 见下节「粉丝数字段缺失」专项处理规则 |
| **纵向对比基准期含节假日** | 见下节「纵向对比基准期落在节假日高峰月」专项处理规则 |
| **Excel 含多个 Sheet** | 见下节「原始 Excel 边界情况」 |
| **`内容` 字段存在空值** | 见下节「原始 Excel 边界情况」 |
| **`内容类型` 出现 PGC/UGC/未知 之外的值** | 见下节「原始 Excel 边界情况」 |
| **`数据类型` 出现映射表外的新值** | 见下节「原始 Excel 边界情况」 |

## 数据质量下限

- 有效数据量 < 100 条 → 告知用户，建议扩大采集范围后再出报告
- 情感标注有效率 < 80% → 检查标注 prompt 是否需要调整

## 粉丝数字段缺失（kol_level 无法派生）

> **触发条件**：原始 Excel 数据不含 `粉丝数` 字段，或该字段全部为空/0。

**处理步骤**：

1. Step 5 清洗时检测 `粉丝数` 字段是否存在且有有效值（非空非零）
2. 若缺失：`kol_level` 全列填「未知」，记录到执行日志
3. Step 7 统计时：`kol_level` 统计仅输出「未知: 全量」，不生成层级分组图表
4. 报告 2.N.4 达人层级效能子模块：**跳过图表**，改用以下替代说明文字（灰色斜体样式）：

   > *注：本次活动监测数据未包含账号粉丝数字段，无法执行达人层级分层分析。如需此维度洞察，建议后续项目在数据导出时要求平台补充粉丝数字段。*

5. **不影响其他子模块**：UGC 参与方式分布、维度词云、热帖配方解构正常执行

**对下游步骤的影响**：
- `KS_Chart_Spec.md` 中 `2_4_kol_tier.png` 不生成
- 经验总结章节：若无达人层级数据，「成功经验」中达人相关条目改为基于 PGC/UGC 效率对比（已有数据）撰写，不强行补充达人层级经验

## 纵向对比基准期落在节假日高峰月（2.{N+1} 活动拉升效果；v2.24 前称 3.1）

> **触发条件**：`brand_stats_baseline.json` 总声量或总互动量显著高于活动期（差距 >20%），且基准期（活动前30天）包含以下节假日之一：
> 五一黄金周（5/1–5/7）、国庆黄金周（10/1–10/7）、春节（通常1月下旬–2月上旬）、618购物节（6/1–6/20）、双十一（11/1–11/15）

**问题本质**：固定「前30天」基准期的方法对季节性强的零售/消费品品牌存在系统性偏差——节假日驱动的声量高基数使「活动拉升效果」计算结果失真，无法客观反映联名活动本身的传播贡献。

**处理步骤**：

1. **自动检测**：比较 `base_total_volume` 与 `act_total_volume`，差距 >20% 时触发本规则
2. **补充日均声量**（必须计算，用于替代绝对量对比）：
   ```python
   # 天数 = 结束日 - 开始日 + 1（含首尾），两期各用自己的实际天数，不写死 30
   base_daily_avg = base_total_volume / base_days
   act_daily_avg  = act_total_volume  / act_days
   daily_lift_pct = (act_daily_avg - base_daily_avg) / base_daily_avg * 100
   # 以上由 lift_compare.py 统一计算
   ```
3. **报告措辞约束（P0，强制执行）**：

   ❌ 禁止写法：
   - 「活动期声量较基准期下降 X%」
   - 「活动带来声量增长 X%」（相关性≠因果，且数据本身不支持正向归因）

   ✅ 正确写法模板：
   > 活动期（{campaign_period}）品牌声量 {act_vol:,} 条，日均 {act_daily:,} 条。
   > 基准期（{base_period}）声量 {base_vol:,} 条，受{节假日名称}影响，月度声量处于年内自然高峰，
   > 两期不在同等可比基准上，建议以**日均声量**作为参考：
   > 活动期日均 {act_daily:,} 条 vs 基准期日均 {base_daily:,} 条（{daily_pct:+.1f}%）。

4. **图表标注**：2.{N+1} 活动拉升对比柱图的副标题或注释区必须标明「⚠ 基准期含{节假日}，声量基数高于日常水平」
5. **可选补充**：若时间允许，额外拉取同期上一年（如去年同期30天）的品牌数据，提供年同比基线

**典型案例（固化依据）**：
> 沃尔玛×玩具总动员联名活动（2026-06），基准期 2026-05 恰含五一黄金周，
> 月度声量 142,220 条 vs 活动期 89,417 条（-37.1%）；但日均声量对比（4,588 vs 2,980，-35%）
> 更具参考意义，且活动期叠加两次食品安全事件干扰，净联名活动声量贡献难以直接量化。
> 报告以「两期不在同等可比基准」说明并提供日均数据作为补充。

## 原始 Excel 边界情况（Step 5 清洗阶段）

### A. Excel 含多个 Sheet

> **触发条件**：`pd.read_excel()` 读取时发现文件有多个 Sheet。

**处理方式**：
1. 优先读取名为「数据」「监测数据」「Sheet1」「活动数据」的 Sheet
2. 若所有 Sheet 名均不匹配上述关键词，读取**第一个 Sheet**（index=0）
3. 在执行日志中记录：「已读取 Sheet：{sheet_name}，共 {n} 个 Sheet，如数据不完整请手动核查」
4. 如果多个 Sheet 包含结构相同的数据（如按月拆分），告知用户合并后再提供，暂停处理

---

### B. `内容` 或 `标题` 字段存在空值

> **触发条件**：`内容` 列 NaN 占比 > 5%，或 `标题` 列 NaN 占比 > 50%。

**处理方式**：
- `内容` 为空的行：**保留**（用于声量统计），但 AI 标注时跳过该行，`情感(AI)` 等字段填 `标注跳过_无内容`，不纳入情感/观点统计
- `标题` 为空：正常处理，热门内容表格中该列留空（`标题` 字段是可选的）
- 执行日志记录：「内容字段为空 {n} 行，已跳过 AI 标注」

---

### C. `内容类型` 出现 PGC/UGC/未知 之外的值

> **触发条件**：`内容类型` 出现第四种及以上取值（如「官方」「媒体」「爬取异常」等）。

**处理方式**：
1. 打印异常值清单及数量
2. 若数量 < 全量的 5%：归入「未知」，在执行日志中记录「内容类型异常值已归并为未知：{异常值列表}」
3. 若数量 ≥ 5%：暂停，告知用户说明该取值含义，由用户决定归 PGC/UGC/未知 或排除

---

### D. `数据类型` 出现映射表外的新值

> **触发条件**：`KS_Data_Processing.md` 平台映射表无法覆盖某个 `数据类型` 值。

**处理方式**：
1. 打印未匹配的 `数据类型` 值和对应的 `站点名称` 样本（最多 5 条）
2. 自动映射为「其他」平台标签
3. 「其他」类内容**纳入声量统计**但**不单独展示平台饼图**（饼图只展示小红书/抖音/微博等有足够样本量的平台）
4. 执行日志记录：「发现未知数据类型：{新值}（{n}条），已归为其他平台」
5. 如未知类型数量 > 全量 10%，告知用户说明来源平台

## AI 标注输入文本长度截断规则（Producer Step 6 / KS_Data_Processing.md 内部 Step 2）

> **编号说明**：本节标题括号内"Step 6"指 Producer 系统提示词中的步骤编号（Step 6 = AI 标注）；KS_Data_Processing.md 内部将同一操作称为"Step 2"。两套编号均指同一处理阶段，读者按自身参照文件理解即可，两者等价。

> **背景**：AI 标注的输入是「标题 + 内容」拼接，长微博/知乎等平台的内容字段可能极长，超出 Token 限制会导致标注失败或截断。

**截断规则**：

| 字段 | 最大保留长度 | 截断策略 |
|------|-----------|---------|
| `标题` | 200 字 | 超出则截断，不影响主体 |
| `内容` | 800 字 | 超出则截取**前 800 字**（帖子核心观点通常在开头） |
| 拼接结果 | 1000 字（含标题） | 先截标题，再截内容 |

```python
# 拼接前截断示例
title = str(row.get('标题', ''))[:200]
content = str(row.get('内容', ''))[:800]
input_text = f"{title}\n{content}".strip()[:1000]
```

**注意事项**：
- 截断不影响声量统计，只影响标注质量（长尾内容可能因截断损失部分观点信息）
- 如果某批次标注失败率 > 20%，排查是否因内容过长导致 Token 超限
- DataHub 批量任务的单条输入建议不超过 2000 Token（含 prompt）

## 基准期数据量不足（Step 4 品牌数据拉取）

> **触发条件**：`brand_stats_baseline.json` 的 `total_volume` ≤ 100 条，或 SSJH-Social-Stat 返回的基准期声量明显异常偏低（如为活动期的 1/10 以下）。

**常见原因**：
- 品牌/账号上线不足 30 天，无历史数据
- 基准期（活动前30天）恰好是品牌关键词更换前的旧命名时期
- 监测平台数据采集存在历史缺口

**处理方式**：
1. 在 Step 4 完成后检查 `brand_stats_baseline.json` 的 `total_volume`
2. ≤ 100 条 → 告知用户基准期数据不足，询问是否：
   - 延长基准期（如改为活动前60天）→ 重新拉取
   - 跳过纵向对比（删除 2.{N+1} 节的基准期对比表格，改为仅呈现活动期数据）
3. 若用户选择跳过：在 2.{N+1} 节头部加灰色说明段：「基准期（{period}）监测数据量不足（{n}条），不具纵向可比性，本节仅展示活动期表现。」

## cdn_url_map.json 更新规则（图表重新渲染时）

> **触发条件**：Validator 审计或用户反馈发现某张图表数据有误，需要重新生成图表并替换。

**正确更新流程**：

```
1. 重新渲染图表 PNG（blueai-echarts-skill）
2. 上传 COS（版本号递增，如 v1 → v2，避免 CDN 缓存旧图）
   cos_uploader.py -f <新png> -p <project> -v v2 -s charts ...
3. 获取新 CDN URL → 更新 cdn_url_map.json 中对应 key 的值
4. 更新报告 MD 中该图的引用 URL（搜索旧 URL 替换为新 URL）
5. 在飞书文档中用 block_replace 替换对应图片 block（见 KS_Feishu_Format.md §十.10.1）
```

**禁止操作**：
- 上传时沿用旧版本号路径（CDN 缓存会导致显示旧图）
- 只更新 cdn_url_map.json 但不更新报告 MD 里的 URL 引用
- 只更新 MD 但不更新飞书文档里的图片 block

## 发布前 QC：正文与配图数据一致性核查

**核查步骤**：
1. 定位本次修改的数字/结论落在哪个 section（如 1.1 / 2.N.1）
2. 该 section 若有配图，回答：图上是否也出现了刚才改动的这个数字（趋势线数值、占比标注、callout 摘要百分比等）
3. 是 → 必须重新渲染该图表并按 §十（`KS_Feishu_Format.md`）替换流程原地更新，不能只改文字
4. 否（图表展示的是其他维度，不含被改动的数字）→ 可仅改文字，但需在自查记录中写明"已核实配图不含该数字，无需重渲染"，不能默认跳过不写

**判定**：文字修改后凡涉及数字类内容，若未明确核实并记录配图是否需要同步更新，视为自查未完成，不得进入下一步（发布/交付确认）。
