## 1. Validator 总原则

Validator 负责轮次一标注审核、D1/D2 类别及来源审核、轮次二观点标注审核，以及报告质检；不负责重写报告或生成图表。

Validator 只输出结构化质检结论：

- P0：阻断，必须修复。
- P1：建议修复，不阻断。
- P2：记录即可。

## 3. 修复循环

```text
Validator 返回 P0
→ Producer 修复
→ 版本号递增
→ Validator 复检
→ 无 P0 后进入步骤 12（飞书导出）
```

**质检通过后又改动数字（P0 规则）**：Validator 判定通过后，Producer 若再修改报告中的**数字、结论或图表**（包括修复 P1/P2 引起的改动），必须对改动处重新提交 Validator 复检，并在质检报告中新增一轮记录；仅修改措辞、不涉及数字与结论的，不需要。禁止“质检已通过”后静默改数。质检报告的 `generated_at` 必须是实际生成时间，不得用 00:00:00 等占位值。

**用户返工后的复检**：输入为飞书文档回读文本，不是旧 MD（飞书是最终版本，返工只改飞书）；有回读内容时，飞书文档层检查项按正常级别判定。

最多 3 轮；超限触发 **HC-7**，暂停并由 Supervisor 通知用户，三选一：①放宽该项并留痕；②补充数据后重做；③终止项目。

最多 3 轮复检。超过 3 轮仍有 P0 → 触发 HC-7，暂停流程，等待人工介入。

## 4. 质检输出字段

每条问题必须包含：

| 字段 | 说明 |
|---|---|
| severity | P0/P1/P2 |
| artifact | 问题所在产物（报告 MD / 图表 / 数据文件） |
| location | 章节编号（如 `2.N.2`）、图表文件名或字段 |
| issue | 问题描述 |
| fix_required | 是否必须修复 |
| suggested_fix | 修复建议 |

`report_qc_report.json` 顶层必须包含 `qc_metadata`：

| 字段 | 说明 |
|---|---|
| actor_role | 必须为 `Validator`（禁止 Producer 自行写入 `Producer` 或留空） |
| mode | 必须为 `independent` |
| validator_id | 本次审计的子代理标识 |
| generated_at | 生成时间戳 |
| input_artifacts | 本次质检读取的输入产物路径清单 |

`qc_metadata` 缺失或字段不完整，视为 P0 阻断——不能证明是独立审计的产物，不允许进入飞书导出。

## 5. 标注审核：已确认规则（2026-11-05）

`validate` 是独立 Validator 审核节点，用户所称 Validata 对应本项目既有 Validator 角色；不是词云 Skill 的同名输入格式校验命令。审核包括轮次一、D1/D2 发现后、轮次二三个阶段。

### 5.1 轮次一：情感与是否活动相关

轮次一标注完成后，Producer 保存本轮数据及抽样记录，通过既有 Agent 工具发起独立 Validator。对本轮**应标注情感/相关性的全部帖子**，按活动依标注执行契约§2，在本轮500条共用额度内分层抽查，基础数量为min(应标注数×10%向上取整,500)，预留校准和复审额度；同一组帖子可同时审核两个字段，但正确率分别计算。抽查包括正面/中性/负面，以及相关性“是”和“否”，不能先筛掉“不相关”帖子再检查相关性。仅按既有约定记录的真实无内容跳过项不进入应标注分母；模型失败、空值、未知或缺少字段不得作为跳过理由缩小分母。

Validator 先读原帖完整上下文和需求确认单的活动、时间、内容范围及已有标签定义，独立判断后与原标签比较：
- 情感：是否忠实表达用户对当前分析对象的态度，是否误读否定、反讽、转述、褒贬并存或其他对象的情绪；遵守现有情感定义。
- 活动相关性：是否确实属于本次活动及分析范围；不能只据关键词/话题标签判断，也不能把真实投诉当噪音；对被标为“否”的帖子同样核对。

分别满足正确率最低90%及空值/“其他”占比低于10%，并完成既有字段合法性/覆盖检查后，才进入 D1/D2。95%正确率及低于5%的空值/“其他”为目标；达到最低线但未达目标须披露，不自动视为不通过。情感只能取正面/中性/负面，相关性只能取是/否；“其他”、N/A及非法值不能因为占比低于门槛而成为合法标签，仍按原覆盖规则补标。

轮次一的全量字段及空值/其他检查入口：`python ../../Skills/blueai-stats-aggregation-skill/scripts/check_coverage.py --input annotated_data.xlsx --round1-only --campaign-filter "<活动名>" --json-out round1_coverage.json`。此模式不要求轮次二字段，输出两字段各自的适用数、历史10%计划数及全量空值/其他指标；实际名单与500条额度以tools/plan_annotation_review.py和审核台账为准；正确率仍由独立 Validator 对照原帖审核。

### 5.2 D1/D2：来源帖子与类别审核，替换人工确认

轮次一审核通过后，D1 正/负观点发现与 D2 UGC参与方式发现按活动执行。发现脚本 `status=ok` 只表示发现完成，`hc_required=false, validator_required=true, review_status=pending`，不表示审核通过。不适用场景沿用现有 min_posts/content_scope 判断，记录原因，不等待人工确认。

将类别名称、定义、观点总结（若有）、来源帖子定位信息、原文和 warnings 提交独立 Validator。审核不能只看类别名称：
- **单帖到观点**：总结是否忠实于原帖，有无扩大原意、漏掉条件或误读反讽、转述、否定。
- **多帖到类别**：支撑帖子是否讨论同一主题，是否将不同观点硬合并，或用个别帖子概括整个样本；区分“价格优惠”等主题名称与“用户认可优惠后的价格”等实质判断。
- **D2**：参与方式是否符合来源帖实际动作/内容形式，遵守现有类别边界与 MECE 定义。
- 除代表帖外，抽看归入该类别的其他发现样本，核对归纳是否有充分支持；此阶段未另设审核比例或正确率阈值。标注后按当前500条共用上限及特殊标签优先规则抽查；类别发现/校准的已读来源纳入对应轮次的已审ID台账。

Validator 只提出结论与修改意见；Producer 修改类别/总结、必要时扩样重新发现，再提交复审。适用项均审核通过后，才将对应列表注入轮次二。不适用项记录原因并沿用填“无”/N/A规则。缺少来源、不能核实原意或审核未完成不得写为通过。不套用报告质检三轮上限；连续两次同类系统错误按标注执行契约§1诊断，不机械循环。

### 5.3 轮次二：观点标签抽查

观点标注的分母为**活动相关=是，情感为正面或负面，且该方向观点发现适用**的帖子。排除中性、活动不相关及已判定不适用内容；应标注但标签为空或“其他”的帖子仍计入分母，并可能被抽到。

按活动在本轮500个不同帖共用额度内抽查；基础数量为min(应标注数×10%向上取整,500)，正负方向合用额度，优先负面/其他/空值等特殊类并保留正常类，层内随机抽样，记录抽样方法和实际名单，避免只检查高互动帖或方便核查的帖子。多标签帖子只计一条，不因标签个数改变分母。类别稀少或样本量不足以覆盖全部类别时如实披露未覆盖类别，不伪称已核查。对“其他”、歧义和多观点内容可补充重点核查，补充检查与随机样本分别记录，不混入随机样本正确率，不突破本轮500条额度。

Validator 先对照原帖及已审核的类别定义作独立判断，再与原标签比较。标签准确且没有明显漏标、多标或错标的帖子才计为正确；不能只检查关键词是否命中。“其他”若确实无匹配类别可以判为正确，但仍计入“其他”占比；空值属于未正确标注。

### 5.4 计算、通过条件及错误处理

| 指标 | 计算口径 | 最低通过线 | 目标 |
|---|---|---|---|
| 抽查数量 | 基础量min(各轮应标注帖子数×10%向上取整,500)，按已审台账预留复审额度 | 完成当前冻结计划且累计不同帖≤500 | — |
| 标注正确率 | 标对的抽查帖子数÷抽查帖子总数 | ≥90% | ≥95% |
| 空值/其他合计占比 | 全部应标注帖子中，空值或含“其他”标签的帖子数÷应标注帖子数，按帖子去重 | <10% | <5% |

空值与“其他”分别统计并给出合计；空白字符串按空值，“标签A,其他”也计为“其他”，同一帖只计一次。多标签按现有逗号分隔规范解析。适用范围内的“无”、N/A等非法占位仍按原合法性规则处理，不能用来规避空值/“其他”指标。样本正确率是抽查结果，不能表述为全量真实正确率。

情感、是否活动相关、观点三个字段分别判定，不能用综合平均值掩盖某字段未达标。正负面及各标签分别披露抽查数、正确数和错误类型，作为问题定位信息，不新增每类单独通过阈值。全部不适用时记录不适用原因，正确率为不适用而非100%。空值/“其他”占比用全量应标注数据统计，不用抽查样本估算。观点覆盖脚本 `check_coverage.py` 输出该全量指标；它不代替独立语义审核。

发现空值须补标；“其他”须检查是确实无匹配类别、分类遗漏还是标错，不能为了降低比例强行归类。发现错误时区分个别错误与共同问题：修复抽到的错帖；若类别边界或提示词导致系统性错误，修正规则并重标受影响数据，按本轮剩余500条额度复核，修复验证与独立新样本分开；额度不足且质量未达标按契约§3记录blocked_quality，不自动扩查。轮次一修改影响相关性/情感时，更新 D1/D2 的样本范围及其下游标签；类别变更后重新审核、重标受影响类别。任一最低线未满足或审核未完成，不进入下一阶段；不使用旧通过结论替代修改后的复审。

### 5.5 审核记录及报告质检衔接

逐活动、逐阶段保存 `annotation_qc_round1_{活动名}.json`、`discovery_qc_{活动名}.json`、`annotation_qc_round2_{活动名}.json`。由独立 Validator 返回 `actor_role=Validator, mode=independent`、实际审核实例与时间、输入文件版本、总体/适用/排除数量及原因、样本数和抽样方法、每条抽查帖的ID/链接/Excel行号、原标签、审核判断、是否正确和错误原因；记录各字段正确数/正确率、空值数/其他数/去重合计及占比、通过状态、修改意见和复审情况。D1/D2记录每类总结及来源证据、通过/退回修改/不适用。

报告 Step 11.5 的独立 Validator 读取这些审核记录，核对当前报告所用数据和类别是否对应已审核版本；原报告质检规则及 HC-T5-2 最终飞书文档确认继续执行。原报告质检的三轮上限不扩展至本次新加入的标注审核。

## 6. 声量高点与互动量高点：内容相关性检查（2026-11-05）

本节追加按KS_Report_Scope_Contract§4—6核查：实质关联不限具体餐品/周边，完整媒体及用户补充辨识分别留痕；未知不直接判噪音，也不能永久沿用未知排除。高点正文解释已核实内容构成而不推断机制；补证后检查关联、情感、主对象、UGC/观点标签是否真的需变动，并按影响矩阵更新。只修改展示资格且统计标签不变时不要求重算无关总体；确有源变化则复检对应更新及全文引用。

Validator 在 Step11.5 对两个指标分别检查，不能以标注正确率抽查通过或 Producer 已做去噪代替。活动高点范围沿用 `KS_Noise_Review.md` 现有范围，并核查报告实际解释的高点；品牌层核查品牌趋势高点及报告中的高点解释。声量与互动量高点日期可能不同，不共用一个指标的日期列表代替另一个。

| 检查点 | 原帖核查方法 |
|---|---|
| 声量高点 | 阅读当天主要讨论及来源帖子，按平台、内容类型兼顾不同讨论和低互动帖，确认新增声量是否来自当前品牌或活动相关讨论 |
| 互动量高点 | 重点阅读当天主要互动贡献帖，核对其互动量及真实内容，确认高互动是否由当前品牌或活动相关内容贡献，而非无关热点、引流挂标签或同名歧义 |

**按分析层级判断关联**：品牌层按已确认品牌、时间及业务范围判断 `brand_related`；活动层按本次活动边界判断 `campaign_related`。可分别记录是/否/证据不足，不要求品牌和活动同时成立。品牌日常内容可能与品牌相关但与本次活动无关；不能用于活动高点归因。赞助活动等按已确认的特殊范围判断，不能仅因正文未出现品牌名而否定活动关联。负面评价本身不构成无关。

**输入与证据**：需求确认单、品牌/活动每日声量及互动量趋势、对应高点日期的原帖与互动贡献明细、当前去噪记录，以及报告高点解释。先查命中句及前后句，不明确则扩读全文和可用识别字段。逐帖记录分析层级、对象、指标、高点日期、平台、ID/链接/行号、原文依据、品牌/活动关联判定、理由及该帖互动量；记录已核查范围和主要讨论/贡献帖。仅拿到部分帖子时不声称已验证全天全部内容，缺少完整分母时不编造贡献占比。

品牌聚合数据不能用活动原帖替代核验。未取得对应品牌高点原帖时，记录“证据不足，未核实”，交 Producer 补充可获得的证据或收回无依据的高点归因；不能写成已确认相关。保留客观高点数值与“原因未能确认”的说明，不将证据不足直接判为无关。

**明确噪音的回退路径**：Validator发现明确噪音 → 退回Producer Step5.5去噪（`KS_Noise_Review.md`）→ 剔除噪音、保存证据并更新保留集及下游标注数据 → 重新执行受影响的类别/标注审核及Step7全部相关统计 → 重生成受影响图表、更新报告数字与高点解释 → 独立Validator复核。修复期间不进入导出或交付；不能只改报告文字或仅从榜单删除。以本轮修复后的数据和图表为复审输入，旧审核结论不能用于本轮放行。

活动噪音从统一活动分析总体剔除，声量、互动、情感/NSR、平台/PGC-UGC结构、达人、UGC、漏斗和榜单等受影响数据一并重算；类别样本或定义受影响时，回到对应发现/标注及审核环节。品牌层同样回到按其查询口径的去噪处理，再重新获取/计算该品牌数据；外部聚合数须从品牌独立来源重新查询或生成，不从活动本地帖子贡献机械扣减。重算改变高点日期时核查新的高点。报告仅以已核实的相关内容解释高点；把无关帖子当作归因证据、未经核实却声称已确认相关、剔除后沿用旧数字/图表，沿用既有峰值归因及去噪 P0 规则处理。

将两类高点检查分别写入 `report_qc_report.json` 的 `peak_relevance_checks`，包括品牌/活动层级、日期、原帖证据、审核范围、判定、问题及修复/复核情况；明确噪音时注明 `return_to=Step5.5`、受影响产物、剔除及重算记录、当前复审状态。本检查为专项内容核查，记录与§5的有限分层标注抽查分开，不另新增正确率、贡献率或固定抽查数量门槛。

## 7. 执行优化与传播概况必检项（2026-11-11）

- 核对每轮结构预检、独立校准、允许类别版本、退回错误归因和受影响范围，不能只审核格式。
