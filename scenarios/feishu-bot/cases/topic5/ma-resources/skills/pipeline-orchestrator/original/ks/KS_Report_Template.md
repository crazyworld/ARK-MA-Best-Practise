## 零、文档头部数据说明（固定，标题之后，正文之前）

**位置**：`<title>` 之后第一块；之后紧跟「整体洞察 Callout」；再进入「一、品牌传播表现」。

> **篇头结构固定顺序**：`<h1>报告标题</h1>` → `<h3>数据说明</h3>`（本节）→ `整体洞察 Callout（📊）` → `<h2>一、品牌传播表现</h2>`

**格式**（用户定稿版，纯文字段落 + 表格，不使用 callout）：

```xml
<h3>数据说明</h3>
<p>数据平台：{平台1}、{平台2}...</p>
<p>时间周期：{YYYY.M.D}-{YYYY.M.D}</p>
<p>取数关键词：</p>
<table>
<thead><tr><th>分析对象</th><th>关键词</th><th>过滤词</th></tr></thead>
<tbody>
<tr><td>品牌</td><td>{品牌关键词，"|" 连接同义词}</td><td>{品牌层过滤词，"|" 连接，无则留空}</td></tr>
<tr><td>{活动名称}</td><td>{活动关键词表达式}</td><td>{活动层过滤词，无则留空}</td></tr>
<!-- 如有「产品」等更细分析对象，逐行补充 -->
</tbody>
</table>
```

**内容要求**：
- 数据平台 / 时间周期：取自本项目实际取数范围，禁止编造
- 取数关键词表：每个「分析对象」（品牌 / 各活动 / 产品等）一行，关键词与过滤词均来自实际取数配置；「分析对象」列填实际名称（如「沃尔玛×玩具总动员联名活动」），禁止用通用标签「活动」代替
- **禁止**在此区域出现：版本号、修改日志、内部字段名、Skill/脚本名、方法论说明（如"活动层情感采用 AI 标注"类口径注释——此类注释放在 1.2/2.N.3 节用灰色斜体标注，不在此处）
- 若某分析对象无过滤词，对应单元格留空，不写"无"或占位符

## 一点一、内容范围条件呈现（`content_scope` ≠ 全部时生效）

**背景**：需求确认单可指定 `content_scope`（全部/仅UGC/仅PGC），默认「全部」。非默认取值时 Step 4/7.3 取数已按单一 `content_mode` 拉取，报告中涉及 PGC/UGC 对比或分表展示的内容需相应调整，否则会出现"只有一种类型的数据却展示对比图/两张表"的矛盾。

**规则**（仅 `content_scope` 为「仅UGC」或「仅PGC」时生效）：

| 章节 | 「全部」（默认） | 「仅UGC」/「仅PGC」 |
|------|----------------|---------------------|
| 1.1/2.N.1 传播概况 ②③ | 平台分布饼图 + PGC/UGC 结构对比 grid 并排展示 | 跳过 PGC/UGC 结构对比块，仅展示平台分布饼图（无需并排 grid） |
| 1.4/2.N.5 热门内容 | PGC Top10 + UGC Top10 两张表 | 仅展示对应类型榜单一张表（默认 Top20，可按用户要求调整），字段规范不变 |
| 2.N.4① 达人层级效能 | 展示 | 「仅UGC」时无 PGC 达人内容，保留标题，不出图，注明「本次仅分析 UGC 内容」 |
| 2.N.4② UGC 参与方式分布 | 展示 | 「仅PGC」时无 UGC，保留标题，不出图，注明「本次仅分析 PGC 内容」 |

`content_scope` 为「全部」（默认）时，维持本文件原有规则，不受本节影响。

**数据不足时的不适用呈现**（与 `content_scope` 无关；判定规则见 `KS_Data_Processing.md`「多活动、抽样与 Validator 审核适用性规则」）：
- 2.N.4② UGC 参与方式：活动相关 UGC 为 0 或 < 10 条 → 不出饼图/代表性内容，保留小节标题，用一句灰色斜体说明：*本活动未采集到活动相关 UGC / 活动相关 UGC 仅 N 条，样本不足，暂不做参与方式分类。*
- 2.N.3 观点 TOP5：某情感方向（活动相关）< 10 条 → 该方向栏位不列观点，注明：*{正面/负面}内容仅 N 条，不做观点提取。*
- 以上均**不得删除章节标题**，也不得留空或写占位符；说明文字属客户可见文本，不出现脚本名、状态码等内部细节。

## 一点五、全文禁止内部技术细节泄漏（贯穿全篇，所有 Section 均适用，非仅「零、数据说明」）

> 背景：数据说明区曾多次泄漏内部技术细节（Skill 名称、内部文件字段名如 `meta.keyword`），修复后又在 1.3/2.N.4 内容分析区发现新的泄漏——把本模板"布局：单个双栏 grid（左词云/右议题解读）"这类**写给生成者看的操作指令**原样复制进了客户可见的报告正文。说明这是系统性问题，不是单点笔误，必须建立全篇自查机制。

**禁止清单**（报告正文任何位置，不限于数据说明区）：
- Skill / 脚本名称、内部文件名（`*.py`、`*.json`、`*.md`）、内部字段名（如 `meta.keyword`、`情感(AI)`、`相关性(AI)`）、版本号
- 本 KS 模板或任何规范文档中的"布局说明"、"格式规范"类自述文字（如"布局：XX grid"、"固定包含三块"、"双栏 grid 并排展示"等）——这些是生成时给自己看的操作指令，不是报告内容，禁止原样写入 `parts.append(...)` 后进入正文
- 内部角色名（Producer/Planner/Supervisor/Validator）、handoff/task_id 等系统机制词汇

**自查方法**：报告生成后（写入 XML/发布飞书前），对全文内容做一次关键词扫描，覆盖上述禁止清单中的典型词根（如 `meta.`、`.py`、`.json`、`布局：`、`Skill`、`skill`、`_TRUSTED` 等），任何命中都必须改写为纯客户视角的说明文字或直接删除（若该文字对客户无信息价值，如纯布局说明，直接删除而非改写）。

## 二、Section 通用格式规范

**飞书文档必须使用 XML 创建，详见 `KS_Feishu_Format.md`**。禁止使用 `drive +import` Markdown。

每个分析 section 统一遵循以下顺序，**不得颠倒**：

```
[h2] X.X 节标题

[callout 💡 light-orange/orange]
  一句话：判断 + 数字证据写在同一句里，不写意味着什么，不写建议（规则见 §Callout 写作规则，P0）
```

### 2.N.2 提及漏斗分析

> 每个活动均包含本节。

**范围与方法（P0）**：先按`KS_Report_Scope_Contract.md`§2确定关键词提及或AI主讨论对象方法，并绑定需求来源。两种方法均以最终活动相关全量为起点，不使用原始检索量、送标量或品牌同期大盘替代。

| 方法 | 下层 | 比例名称 | 能说明什么 |
|---|---|---|---|
| 关键词提及 | 在已记录提及范围中命中品牌的帖子；有确认产品词时再在品牌层取产品词交集 | 品牌提及率、产品提及占比 | 品牌/产品名称在对应范围内的出现比例 |
| AI主讨论对象 | 主讨论对象为品牌的帖子 | 品牌主导讨论占比 | 活动中的讨论焦点，不是名称出现率 |

品牌同期总声量只作独立量级参考，不能替代漏斗。三种主讨论对象标签不是递进子集，不能将产品主导帖接在品牌主导层下。

**提及方法的退化规则**：品牌提及层接近全量时沿用95%提示：产品词存在则分析活动全量中的产品提及；无产品词时保留活动全量及简短范围说明，另列参考比较。不得自动切换到主对象方法或拿大盘比值充当漏斗。用户已明确主对象方法时不套用提及方法的退化判断。

**⚠️ 多活动：合并为一份报告还是拆分（先判断，再动手）**

**默认合并**：同一品牌的多个活动写成一份报告，第一章品牌数据取覆盖所有活动的**合并窗口**（最早开始日到最晚结束日），活动拉升基准期取合并窗口开始日之前的 30 天；第二章每个活动按各自的活动期、各自的数据分节（2.1、2.2…）。

**合并窗口必须在需求阶段由用户确认**：需求确认单记录各活动自己的活动期，以及合并窗口、基准期的起止日。用户未确认前不得开始取数。

**"间隔过远"拆分提示（不是硬性规则）**：按开始日排序，若相邻两个活动之间的间隔 **> 30 天**（后一活动开始日 − 前一活动结束日；有重叠或相接记为 0），合并窗口里会夹着大段与活动无关的时间，品牌数据与活动拉升会被稀释。此时 Producer 向用户给出提示并建议拆成多份报告，由用户决定；用户坚持合并则合并，并在报告数据说明区注明各活动间隔。

| 情形 | 处理 |
|------|------|
| 同一品牌，活动间隔 ≤ 30 天（含重叠） | 合并，用户确认合并窗口 |
| 同一品牌，间隔 > 30 天 | 提示并建议拆分；用户决定 |
| 不同品牌或不同客户 | 必须拆成不同项目 |

**合并后的口径**
- 第一章与「2.{N+1} 活动拉升效果」针对整个合并窗口，不针对单个活动（它是品牌整体口径，虽编号位于二内，不属于任一活动的 2.N 节）；该节须注明对应的是合并窗口。
- 第二章各活动的数据按各自活动期筛选，不用合并窗口筛选（避免把 A 活动期外的内容算进 A）。
- 活动期有重叠时，沿用下方“时间重叠处理规则”（合计声量不可相加）。
- 整体洞察以合并窗口的整体表现为主，不把单个活动的结论当作整体结论。

发现各活动活动期不同、而需求确认单只有一个 `campaign_period` 时，在 Step 1 就停下，请用户确认上述窗口，不要带到取数之后才发现。

**品牌同期总声量的来源（合并报告，P0）**：声量贡献参考的分母“品牌同期总声量”一律取自**合并品牌数据**（第一章同一份 `brand_stats.json`），按该活动自己的活动期对逐日声量汇总得到；**不得**为单个活动另行拉取品牌数据——两次取数时点不同，晚入库的数据会使同一指标出现两个数值（Manner 双联名测试：3,268 与 3,399）。用该数值作为 `aggregate.py` 的 `--brand-total`；全文同一指标只能有一个数值。

**⚠️ 多活动时间重叠处理规则**

当报告包含 2 个或以上活动且时间段存在重叠时：
1. **禁止计算活动合计声量**：各活动声量分开展示，不汇总相加
2. **各指标独立计算**：每个活动的品牌提及率、声量贡献参考值均独立计算，不相加
3. **数据说明区注明重叠**：在报告头部「数据说明」表格下方增加一行灰色斜体说明：

   > *注：{活动A名称}（{时间段A}）与 {活动B名称}（{时间段B}）时间段存在重叠（{重叠起止日期}，共 X 天），两活动声量为独立计算，重叠期内容可能在两活动中均有计入，合计声量不具可加性。*

**图文分支（按已记录方法）**：

- 关键词提及方法：无产品词为“活动相关全量→提及品牌”；有产品词且未退化为“活动相关全量→提及品牌→同时提及产品”。产品交集另列占品牌提及层和活动全量两个基准的比例。

## §Callout 写作规则（P0，整体洞察与各节 callout 通用；v2.25 重写）

**位置与形式**：整体洞察在 `<title>` 之后、数据说明之后、「一、品牌传播表现」之前，单个 Callout，emoji 📊，light-orange 底色；各节 callout 为 💡，位置见上文各节顺序。

**句数结构**

| 类型 | 结构 |
|---|---|
| 整体洞察 | 固定三句：判断句 → 数字证据 → 意味着什么。不写第四句，不给建议 |
| 各节 callout | 固定一句：判断与数字证据写在同一句里，不写意味着什么，不写建议 |

```xml
<callout emoji="📊">
<p><b>整体洞察</b></p>
<p>{判断句}{数字证据句}{意味着什么句}</p>
</callout>
```

建议统一写在「三、经验总结 / 3.3 后续行动计划」，callout 里不出现。「意味着什么」只陈述这些事实说明了什么，不写“应该”“建议”。

**共用规则**

1. **结论在前，数字是证据，不是主语。** 先给判断，再用数字支撑，不以数字开头。不写“品牌提及率为 7.9%”，写“文字里出现品牌名的不足一成”。
2. **判断不超出数据范围。** 数据显示行为，不推断动机；数据显示相关，不写因果。写完自检：这个判断数据能直接证明，还是推断出来的？推断的改写或删掉。因果/效果类词（带来、驱动、拉动、转化为、有效、说明用户缺乏兴趣）除非数据直接证明，一律不用。
3. **禁用程度副词。** 不写“非常”“极大”“显著”“明显”“大幅”“很少”，换成具体数字或比值（如“约为活动前的 6 倍”“不足一成”）。
4. **禁用口语和隐喻。** 不用比喻性说法（买到、换来、跑赢、撬动、破圈等）。
5. **数据没有明显差异时**，写“无明显差异”或“样本不足，不下结论”，不硬凑结论。**该节数据不支持某一判断层时，直接省略这一层，不硬凑**（如品牌层口碑没有负面归类，callout 不写“负面指向什么”）。
6. **数字口径与正文一致。** 倍数、百分比若正文没有，须能由正文数字直接算出；正文没有的派生数字要先核对再写。

**自检（写完逐条过）**
- 单独拎出来给人看，能不能知道“这件事是好是坏”？不能说明还停留在描述层
- 判断句里的每个词，数据是直接证明的，还是推断出来的？
- 有没有以数字开头？有没有程度副词、比喻、建议、第四句？

**各节 callout 必须回答的问题**

| 节 | 必须回答的问题 |
|---|---|
| 传播概况（1.1 / 2.N.1） | 声量和互动的分布形态：集中还是分散、持续还是回落 |
| 口碑（1.2 / 2.N.3） | 偏正还是偏负，样本有多大，正面集中在哪些话题、负面指向什么（品牌层无观点归类时省略“正面集中在哪、负面指向什么”；观点标签占比可重叠，只引用最大的 1–2 项，不相加） |
| 词云（1.3 / 2.N.4③） | 讨论落在品牌和产品上，还是落在话题、人物、机制上（以比较代替好坏判断） |
| 热门内容（1.4 / 2.N.5） | 高互动内容与品牌/产品相关吗（集中度由传播概况回答，此处不重复）；各节 callout 之间不重复使用同一组数字（整体洞察是全文提炼，可与各节共用数字，不受此限） |
| 漏斗（2.N.2） | 按已记录方法回答：关键词提及时看名称出现情况；AI主对象时看品牌是否为主要讨论焦点，不能套用另一方法的问题 |
| 达人效能（2.N.4①） | 哪个层级单条互动更高，样本是否足以比较 |
| UGC 参与（2.N.4②） | 参与是浅层还是有实质内容 |
| 热帖规律（2.N.4④） | 高互动内容有什么共同点 |
| 拉升效果（2.{N+1}） | 活动期较基准期日均高多少，两期是否可比 |
| 三、四章（总结类） | 不写 callout |

**示例**

```
❌ 描述层
品牌提及率为 7.9%，产品提及率为 0.4%。

❌ 数字作主语 + 推断动机
品牌提及率仅 7.9%，说明用户对品牌缺乏兴趣。

❌ 数字作主语 + 推断因果
品牌提及率仅 7.9%，说明声量没有转化为品牌认知。

✅ 各节 callout（2.N.2，一句）
品牌名在活动内容文字中的出现率不足一成，新品产品词仅出现在 25 条内容中（活动内容共 6,438 条）。

✅ 整体洞察（三句）
活动期间品牌声量高于活动前，但活动内容的文字中出现品牌名的不足一成、出现新品产品词的仅 25 条。活动期品牌日均声量约为活动前 30 天的 6 倍，而活动内容中 82% 除话题标签外没有任何文字。因此活动期声量的提升不能直接读作品牌和产品讨论的增加。
```

**范围一致**：同一句里的比例，分母必须与主语的口径一致（品牌口径与活动口径不混用，如“品牌日均声量……其中 82%”会把活动内容的比例挂到品牌声量上，是错误写法）。

**生成时机**：Step 11 报告撰写完成后，基于全文反向提炼，整体洞察最后写入；各节 callout 随各节写。
**禁止**：出现内部字段名、系统角色名、技术细节。

## §2.{N+1} 活动拉升效果 规范

> 活动拉升效果位于「二、活动传播表现」最后一节，标配必做。
> **编号**：2.{N+1}，N = 活动个数（单活动 = 2.2；两个活动 = 2.3）。标题写「2.{N+1} 活动拉升效果」，不再有下一级编号。
> **口径**：用品牌数据（brand_stats / brand_stats_baseline），针对整个合并窗口，不是某个活动的 2.N 数据；节首一句话说明「以下为品牌整体口径」，避免读者当成单活动指标。
> **位置**：放在所有 2.N 活动节之后、「三、经验总结」之前。飞书中它是 H3，与 2.N 同级。
> **图表文件名**：沿用 `3_1_lift_compare.png` 文件名（脚本与历史项目兼容）；新项目建议命名 `2_lift_compare.png`，两者均可，以 KS_Chart_Spec 为准。

### 2.{N+1} 活动拉升效果（纵向，标配）

**分析逻辑**：品牌关键词 × 活动期 vs 品牌关键词 × 活动前 30 天，对比**日均**声量 / 日均互动量 / NSR 变化（两期天数通常不等，总量仅辅助，详见 `KS_Metrics_Calculation.md`「活动拉升效果——日均对比」）。

```
[callout] 一句话：判断 + 证据（回答「活动期较基准期日均高多少，两期是否可比」，须含两期天数）
{正文段落} 各指标变化率说明
{图表} 对比柱图：活动期 vs 基准期（日均声量 / 日均互动量 / NSR 三组对比；图例或表头标注各自天数，如“活动期（10天）/ 基准期（30天）”）
```

**措辞强制规范（P0）**：
- ✅ 正确：「活动期间品牌日均声量较基准期日均提升/下降 X%（活动期 N 天、基准期 M 天）」
- ❌ 错误：「本次活动带来 X% 声量增长」——禁止将相关性表述为因果
- ❌ 错误：直接以两期总量之比作为变化率（天数不同时失真）
- **品牌关键词补入了活动关键词时（P0，未补入不加）**：2.{N+1} 正文须加一句灰色斜体注：*注：品牌口径含活动关键词，活动期声量包含参与该活动的内容；基准期使用同一套检索词。* 基准期必须与活动期使用同一套关键词和过滤词

**数据来源**：`brand_stats.json`（活动期）vs `brand_stats_baseline.json`（基准期）
