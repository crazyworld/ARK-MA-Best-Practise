## 关键字段使用说明

### `站点名称` → 平台标签

当前19列输入不保留`数据类型`；从`站点名称`按已核实映射派生平台标签，见`KS_Data_Processing.md`。无法确定的平台记录异常，不默认归抖音。原始导出的`平台`等来源列在适配阶段完成映射，后续只使用规范列。

### 供应商`情感`仅在原始产物留存

当前19列输入不含`情感`，不要求派生`情感标签`；原始产物或历史文件的数值情感仅供来源校验。活动分析使用后续`情感(AI)`，品牌情感继续使用品牌聚合数据。

### `分析对象` 字段用途

数据文件中可能包含 2-3 个不同活动，通过此字段区分。Step 3 所有聚合均按此字段分组，每个活动独立输出统计文件。

## 清洗派生字段（Step 5 生成）

> 以下字段由数据清洗步骤从原始字段计算/映射而来，不经过 AI 标注。

| 字段名 | 类型 | 派生来源 | 取值 | 说明 |
|--------|------|---------|------|------|
| `平台标签` | string | `站点名称`的已核实映射 | 抖音/小红书/微博/微信/B站/快手/… | 统一平台名称，供所有统计使用 |
| `情感标签`（历史校验可选） | string | 仅实际含`情感`的历史文件/原始产物可映射 | 正面/中性/负面/未知 | 当前19列输入不生成；活动口碑使用`情感(AI)` |
| `互动量_计算`（可选校验） | number | 仅在分项完整且口径已核实可加总时计算 | 数值 | 不自动替代缺失的`总互动量`，不把缺失分项补零 |
| `kol_level` | string | `粉丝数` + `平台标签` 按阈值表派生；规则见 `KS_Classification_Rules.md`「平台达人分层阈值表」 | 头部/腰部/尾部/素人 | **各平台阈值不同，禁止使用统一数值**；PGC/UGC 行均派生此字段 |

#### `kol_level` 派生注意事项

- 必须先生成 `平台标签`，再按平台查阈值表，两步顺序不可颠倒。
- `粉丝数` 为空或为 0 的行，`kol_level` 填 `未知`，统计时单独计数，不并入四个层级。
- 阈值表由 `KS_Classification_Rules.md` 维护，本文件不重复定义具体数值。

## 标注派生字段（Step 6 生成）

> 以下字段由 AI 标注（DataHub 批量任务）产出，每个字段的适用行范围不同，详见下表。

| 字段名 | 类型 | 适用范围 | 取值 | 说明 |
|--------|------|---------|------|------|
| `情感(AI)` | string | 全量行 | 正面/中性/负面 | Step 6 轮次一；输入文本为「标题 + 内容」拼接；**口碑分析的权威情感来源**，禁止用原始 `情感` 字段替代 |
| `是否活动相关` | string | 全量行 | 是/否 | Step 6 轮次一；热门内容筛选、`ugc_category`/`discussion_dimension` 过滤的前置依据 |
| `观点类别(AI)` | string | `是否活动相关`=是 的行 | 观点标签（由用户确认后定义） | Step 6 轮次二；口碑观点 grid 的数据来源 |
| `ugc_category` | string | `内容类型`=UGC 且 `是否活动相关`=是 的行；其余行填 N/A | **动态类别（由 Phase-ugc-discovery 自主发现后注入，每个项目不同）** | **新增（v0.4）**；Step 6 轮次二合并标注；用于 2.N.4 UGC 参与方式分布 |
| `discussion_dimension` | string | `是否活动相关`=是 的行；否则填 N/A | 品牌/产品/活动 | **新增（v0.4）**；Step 6 轮次二合并标注；用于分组NSR；方案采用AI主对象口径时也可用于品牌主导漏斗，不用于SSJH词云筛选，不能冒充关键词提及 |
| ~~`内容主题`~~ | ~~string~~ | ~~全量行~~ | ~~多标签，`\|` 分隔~~ | ⚠️ **已废弃（Producer v0.4，2026-07-28）**，不再标注，不再使用 |

#### `ugc_category` 分类说明（v0.5 更新）

> ⚠️ **ugc_category 不使用固定类别**，类别由 Phase-ugc-discovery 对活动相关 UGC 样本自主发现后注入 `ugc_category_list`，每个项目的类别名称和数量均不同。
> 执行时见 `annotation_prompt.md` → 项目配置区（`ugc_category_list`）；发现步骤见 `KS_Data_Processing.md` § Phase-ugc-discovery。
> 旧固定4类（模仿打卡/创意改编/测评分享/自发安利）已废弃，禁止使用。

#### `discussion_dimension` 字段约束

- 含义：这条内容的**主要**讨论焦点。原帖可以同时涉及多个对象，本字段每帖只保存最显著的一个主讨论对象；三个分组是按主焦点划分，不是品牌、产品及活动词的全部提及集合。
- 用于主要讨论对象分组NSR；内部枚举仍为品牌/产品/活动。报告展示为“品牌主导讨论”“产品主导讨论”（按实际定义可写“餐品与周边主导讨论”）“活动流程与获取主导讨论”，不将第三类简称为“活动NSR”。各组实际定义须随标注指令保存，详见 `KS_Metrics_Calculation.md`「活动整体与主要讨论对象分组」。
- 活动整体NSR基于全部活动相关帖，不按本字段筛选。分组复用帖子的整体情感，未单独标注对象情感时，不得解释为对具体品牌、产品或流程的情感评分。
- **按方案选用**：关键词提及交集不由本字段替代；方案明确采用AI品牌主对象时，可据本字段准备品牌主导漏斗；品牌词云仍使用SSJH活动中品牌提及查询，不据本字段筛选。词频上游按KS_Data_Processing Step7.3及KS_Report_Scope_Contract，不要求通用词云Skill抽词。

## 首次使用新项目数据时的检查步骤

1. 打印所有列名：`print(df.columns.tolist())`
2. 核查「⚠️待确认」字段的实际列名，更新本 KS
3. 检查 `情感` 字段的值域（应为 1/0/-1 整数）
4. 确认 `内容类型` 字段的取值（PGC/UGC/未知）
5. 确认 `粉丝数` 字段存在且有有效数值（`kol_level` 派生的前提）
6. 确认 `平台标签` 已生成，再执行 `kol_level` 派生（两步有顺序依赖）
