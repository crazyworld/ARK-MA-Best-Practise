## 执行位置与输入

Producer Step 5 清洗 → Step 5.5 本去噪审核 → Step 6 轮次一相关性与情感标注 → 观点/UGC 类别发现 → 轮次二 → 覆盖检查 → Step 7 正式聚合。去噪不依赖任何轮次一标注结果。

输入 `cleaned_data.xlsx`，输出 `denoised_data.xlsx`（保留内容）及 `noise_review_{活动名}.json`（含剔除内容与证据）；轮次一仅接收 `denoised_data.xlsx`。剔除内容不进入相关性、情感或后续标注任务。去噪判断与正式活动相关性字段分开记录，不提前伪造 `是否活动相关(AI)` 或 `情感(AI)` 标签。保存高点日期的来源帖子和互动明细供独立Validator复核，Producer审核记录不能代替Validator的高点内容核查。

逐活动执行，输入为需求确认单中的活动边界、活动期、实际活动取数关键词及过滤词，以及未截断的标题、正文、话题、帖子 ID、平台、发表时间、互动量。关键词表达式中的 `|`、`+` 是检索关系，不是正文中的字面词；保留命中分支和实际命中词。不得用品牌词或产品分析词代替活动取数式，也不得要求 AND 分支的各词连续或同句出现。

本步骤由 Producer 执行语义审核，不把字符串命中直接等同于相关，也不把规则文档当作自动运行的程序。

### 封面、音频及视频文本识别（审核输入）

- 同时读取原始字段 `视频封面内容识别`、`音频内容识别`、`视频文本识别`，清洗及标注传参时保留这三列，非空时必须纳入标注前去噪及后续相关性标注。这里使用下载数据已有的识别文本，不代表已经重新识别或观看视频。
- 在该字段内也定位关键词，优先读取命中句及前后各一句；若识别结果没有句界，则读取整段。记录证据来源字段，不能把封面识别文本冒充正文原句，也不能跨字段拼接“相邻句”。
- 结合标题、正文、话题和封面识别结果判断活动关联。正文很短、只有标签或没有关键词，但封面明确呈现本次活动信息时，应据实际证据保留；不能仅因正文无关就忽略封面中的真实活动关联。
- 识别可能错字、同名误识别或缺少上下文；字段命中本身不等于活动相关。与正文等证据冲突时继续核查，不单凭识别文本判噪音。为空或缺列只记录“无封面识别信息”，不据此剔除，也不编造识别结果。

## 完整媒体与补证（P0）

按KS_Report_Scope_Contract§4复核高点主要贡献帖及拟入榜帖。正文/OCR不足时先按KS_Annotation_Execution_Contract§4检查实际媒体能力；可用时核读完整独立主图和已有视频/公开页，无能力时按已授权识别服务或重点人工核验路线补证；记录实际看到的画面、未能播放的媒体及ID关联，失效链接在现有权限内刷新，不误用另一帖媒体。用户补充辨识独立记来源，不冒称模型已看视频。未展示具体餐品/赠品不自动判无关；符合当前活动边界的IP表达、合作形象及生活情节真实露出可有关联。补证后重审标签与展示资格，不能把“证据不足”永久固化为排除理由。

## 审核范围

- 在清洗数据上执行上下文去噪，重点覆盖高互动与原始趋势峰值；不先做相关性/情感标注。未覆盖或证据不足的内容保留，进入后续正式标注，不宣称全量已核实。
- 高互动：每活动、每平台互动量降序前 30 条（不足取全部），并覆盖拟入选的 PGC/UGC 热门榜单内容。30 为执行默认值，不是用户已验证的最优阈值；如仍有集中噪音，扩大审核范围。
- 峰值：用清洗后的未标注数据生成内部预览，分别检查每日声量、互动量最高的前 3 个有数据日期（不足取全部，并列日期均检查）。该预览不是正式图表。去噪后再次检查主要高点，必要时扩查，之后才提交标注。
- 互动高点查当天主要互动贡献帖；声量高点按平台、PGC/UGC 分层抽查，兼顾低互动内容，每个非空层默认取最多 30 条、固定随机种子 42。发现噪音后，扩查相同命中分支、文案或话题的内容，逐帖判定，不按一个词或账号整批删除。

## 上下文判定顺序

1. 在未截断原文中定位活动关键词的各个命中位置，以中文或英文句末标点、换行切句；话题标签单列保留，不能丢掉标签与正文的关系。
2. **先读“前一句 + 关键词当句 + 后一句”**，首尾缺句时取实际可用内容。相邻窗口可合并；不得只取首个命中，也不得只看帖子开头的固定字数。
3. 判断关键词在这里指向谁、描述什么，是否与本次活动的主体、事件或参与行为相符。噪音指无关传播，不指负面情绪。
4. 三句不足以判断时，继续读标题、全文、其他命中位置、话题与可用原帖信息。长文跨句提及、简称和省略主语不能仅因局部不完整而剔除。没有文本命中或纯图文也不自动判噪音，转全文/原帖核查。
5. 多个命中窗口中只要有真实且符合活动范围的关联证据，即不能因另一个窗口无关而剔除整帖。无法取得足够证据时保留该帖，记录“证据不足”，交后续正式相关性与情感标注，不追加用户确认，也不得把该帖用作已核实的峰值归因证据。

| 情况 | 判定 |
|---|---|
| 同名、词义撞车；正文讨论其他对象 | 噪音，自动剔除 |
| 正文与本次活动无关，只为引流挂活动话题 | 噪音，自动剔除 |
| 其他期次、其他活动，或只有品牌日常内容且不在本次活动范围 | 噪音，自动剔除 |
| 内容属于用户已明确排除的商品/服务范围 | 噪音，自动剔除；不得自行扩大排除范围 |
| 真实参与、介绍、评价本次活动，包括投诉、差评 | 保留 |
| 赞助型活动中讨论被赞助节目/IP且符合本次范围，未提及品牌 | 保留，遵循现有赞助型活动规则 |
| 仅标签可见、正文缺失或纯图片，关联性尚无法核实 | 扩查可用信息；证据不足不等于已确认噪音 |

## 自动剔除与统一口径

- **Producer 判定为噪音后直接执行，无需用户确认，也不新增 HC 节点。** 原始 Excel 保留，剔除指排除出本次活动分析总体。
- 将明确噪音排除出 `denoised_data.xlsx`，保留完整来源行及剔除证据于审核记录。轮次一输入、后续工作簿和所有活动统计均不得重新纳入这些行。ID 不能跨活动直接通用；无稳定 ID 时使用来源文件+工作表+原始行号标识。
- 记录到 `noise_review_{活动名}.json`：来源标识、活动、ID、平台、日期、互动量、命中分支/词、证据来源字段、三句原文窗口、视频封面识别证据（有则记录）、补充证据、去噪判定、理由、处理动作。未命中或缺文本必须如实记录，不编造句子。另记录审核范围、已审条数、剔除条数/互动量及峰值前后变化。
- 轮次一仅标注去噪后的保留行；观点发现及轮次二再使用其中正式标为活动相关的内容。若后续榜单/图表检查或Validator高点核查发现漏网噪音，返回去噪步骤更新保留集和审计记录，同步排除标注工作簿中的对应行，再重跑覆盖检查和全部活动统计；若已影响类别发现，重新检查类别适用性并提交独立Validator审核，不增加去噪确认。
- 声量趋势、互动量、平台/PGC-UGC 分布、情感/NSR、达人、UGC、漏斗和榜单均读同一份最终工作簿。明确噪音不能只从榜单删除而保留其他统计贡献；尚待核实的展示排除与明确噪音统计剔除须分开记录，补证确认相关后撤销旧展示排除、按原快照恢复排序。
- 重算后检查最终主要高点；发现新噪音则继续扩查、回写、重算。只依据审核后保留的真实相关内容解释峰值，无法核实则写明原因未能确认。
- 外部品牌聚合与 API 词云不会因本地逐帖剔除自动改变。不得从这些聚合值机械扣减帖子数；活动词云解读需沿用上下文去噪，不把已确认无关的议题写成活动结论。品牌层按其自身查询口径另行核查。
- 报告用一句话说明已剔除无关内容及数量；技术审计材料留在处理目录。去噪不要求用户逐条审批。

## 出口核对

**Validator退回入口**：高点或其他审核发现明确噪音时，流程退回Producer Step5.5本步骤，剔除噪音并重新生成保留集，更新下游工作簿；重算所有受影响统计及图表、更新报告，然后重新提交独立Validator。去噪改变类别样本、定义或标注范围时重新完成对应发现/标注审核。当前数据修复及复审未完成前不继续导出交付。品牌噪音按品牌自身来源处理并重新获取聚合，不能直接从外部品牌聚合值扣减活动本地记录。

审核记录存在；高互动与峰值范围已覆盖；明确噪音未进入轮次一输入；所有活动统计同源；最终峰值已复核；报告数字和图表为重算结果。证据不足的内容须单列，不得伪称“全量已核实”。统计披露区分清洗后总量、去噪剔除量、送标量、标注后不相关量与最终活动相关量；现有 `stats_scope` 以标注工作簿为输入，去噪前总量须另从清洗数据和审核记录核对，不得把送标量误称去噪前总量。
