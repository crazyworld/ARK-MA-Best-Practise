## 1. 每个模块先绑定范围（P0）

Producer Step1读取当前项目需求、方案及最新更正；Step7计算前、Step8绘图前、Step11写作前核对同一范围记录。已有明确口径直接沿用，不重复询问。确有业务歧义时只澄清该项，继续不依赖它的工作。

每个模块内部记录：需求来源及版本、分析层级、对象、日期、平台集合、帖子/评论范围、PGC/UGC范围、相关性筛选、对象筛选方法、产品包含范围及关键词、指标与分母、实际数据源和指纹。分类定义注明来自文件预设、执行时细化或用户明确更正；不把分析者解释写成用户原话，也不把用户对一个模块的确认扩展为其他模块的确认。

区分原始检索量、清洗后量、明确噪音剔除量、送标量、AI判活动无关量、最终活动相关量。活动整体统计与漏斗起点均取最后一项；“去噪后全量”不得省略是否又排除了活动无关内容。分组统计及PGC/UGC模块在此总体内按各自适用条件筛选，不强求子集帖数等于整体。

## 2. 漏斗：品牌提及与品牌主导讨论分别计算（P0）

| 方法 | 品牌层筛选 | 图表名称及比例 | 产品层 |
|---|---|---|---|
| `keyword_mention`（关键词提及；预设方法，用户明确另一方法时不适用） | 活动相关全量内，按已记录品牌词与文本/标签/媒体提及范围筛选；不能将文本匹配结果称为已验证媒体露出 | 提及漏斗；品牌提及率 | 有已确认产品词时，在品牌提及子集内筛选产品词，保持递进关系 |
| `main_discussion`（AI主讨论对象；需求明确品牌为主要讨论对象时使用） | 活动相关全量内，主要讨论对象标签为品牌；沿用实际定义 | 活动中的品牌主导讨论漏斗；品牌主导讨论占比 | 品牌/产品/流程三个主对象分组不是递进集合，不把产品主导分组接在品牌主导层下；如另做产品词交集，须有独立、明确命名的分析 |

两种方法均以同一活动相关全量为分母；品牌同期大盘仅作另列的量级参考，不进入漏斗。无产品关键词不自动发明SKU词；“产品”主对象标签存在不等于有产品检索词。

默认提及方法不等于用户确认主讨论对象方法。品牌词已包含在检索式中导致提及层接近全量时，解释该结果的信息限制；仍按提及方法的退化规则处理，不能自动改成AI主讨论对象，也不能用大盘比值替代漏斗。已确认主对象方法时，标准工具输出的文本提及列不能直接拿来展示为主对象占比：须从同源已审核标签计算、保存明确方法的结果并复核。

## 3. 词云：章节划分与SSJH查询来源（P0）

- 第一章品牌词云：按实际平台分别展示品牌整体讨论，使用SSJH品牌查询的原始词表，绑定已确认品牌窗口。
- 第二章活动词云：按活动整体、活动中的品牌、产品（有已确认产品词时）展示，综合已选平台，不按平台重复拆图。三者必须有各自范围对应的SSJH实际查询返回值；可复用已保存且完整匹配当前范围的真实返回，不重复无变化的查询。
- 活动整体查询使用已确认活动关键词、过滤词、日期、平台、帖子/评论及内容类型范围；品牌词云查询在活动条件上与已确认品牌词取交集；产品词云在相应品牌/活动条件上与已确认产品词取交集。表达式按SSJH自身契约组织，不机械拼接导致OR/AND优先级错误。
- 品牌词云使用“活动中品牌提及”口径，不自动沿用漏斗的AI品牌主讨论对象方法。AI主对象仅用于已确认的漏斗/分组分析，不作为本模块词表筛选依据。无产品词不从口碑类别发明检索词。
- 禁止合并既有候选词后在本地原帖重计、自由分词或其他非SSJH结果来替代本模块词云；不因无法查询AI子集而换成上述方法。此规定撤销旧版允许的本地候选词重计替代路径。
- 保存查询参数、真实请求结果、执行时间、实际来源路径/指纹及词频定义。API关键词聚合与AI去噪相关集可能不是同一总体：按真实查询范围说明词云，不声称它恰为AI筛选后的全量，不挪用AI帖数作为词频分母。范围不符先核对，不能靠改图标题掩盖。
- 综合平台来源须真实覆盖所选平台；不直接相加未知API权重。只有指标单位、可加性及平台范围经核实才可整理同源返回；不能确认时记录受影响模块阻塞，不用单平台图伪装综合图，也不使用本地重计兜底。
- wordcloud-insight只分析并绘制已有SSJH词表；原词原值保留。正文、OCR/ASR或媒体可用于议题核验，但不替换接口词频。接口不可用、结果缺失或查询范围不支持时，说明阻塞及恢复动作，不自行更换统计方法、不自动新增收费任务。

## 4. 高点、媒体与证据（P0）

区分“已确认相关”“已确认无关”“尚待核实”，并分别裁定品牌关联与活动关联。没有明确餐品/周边展示不等于无关：符合当前活动边界的IP表达、合作形象、参与行为、生活情节中的真实露出均可构成关联；负面内容不因情绪被排除。

主要互动贡献帖或待入热门榜帖若正文/OCR不足，按 `KS_Annotation_Execution_Contract.md` §4检查实际能力；有能力时核对完整图片、公开原帖及可用媒体，无能力时使用已授权识别服务或重点人工核验。能力缺失不直接判噪音。图文应读完整独立主图；封面、裁图、登录遮挡页不能冒称完整媒体；无法播放视频如实记录未观看。链接失效时在现有权限内刷新来源并核对ID，不能误用另一帖的图、把搜索推荐词当原帖证据或绕过访问限制。

用户补充辨识可作为来源明确的补充证据，记录原话与时间，结合当前活动边界复审；不冒称由模型独立看视频确认。未解决的条目不自动判无关，也不能长期沿用旧“证据不足”作为已完成审核；记录补证动作、结果和影响范围。

高点段落回答“哪一天出现什么内容、量级多大、主要内容贡献多少”，用已核实内容构成解释统计现象。贡献分子与当天分母必须同层、同范围、同快照；不能把单帖的量级解释为整天全部实体内容或销售、认知、周边吸引的效果。声量高点还须按平台和内容类型检查讨论构成，不能只拿互动Top帖解释全部声量。

仅有相关性证据不能证明互动机制或因果效果。核查过程留内部记录；正文只保留影响理解的简短限制，不以反复“不可证明/证据不足”代替内容分析。确有未核实关键贡献时保留客观数值并收窄解释，不能为了写出原因而编造。

## 5. 补证后的最小完整更新链（P0）

新证据 → 独立复审关联及可能受影响标签 → 保存新源版本与精确变更 → 重算受影响统计 → 更新榜单、图表、各章节引用 → 独立复检实际交付版本。没有实际标签或范围变化时复用无关模块；不机械重分类、不自动重复付费采集或全量标注。

| 改变内容 | 必须检查的下游 |
|---|---|
| 仅由待核实变为已确认、统计标签不变 | 恢复展示资格及排序、高点叙述、旧限制语、榜单排除清单；整体数值不变 |
| 活动相关性/明确噪音 | 统一总体、声量/互动趋势、情感/NSR、PGC/UGC、主对象、漏斗、词云范围及榜单；按去噪流程重算所有受影响项 |
| 情感 | 整体及分组NSR、情感分布、正负观点统计和引用 |
| 主讨论对象 | 分组NSR；采用主对象口径的漏斗及相关章节引用；不据此改动SSJH品牌提及词云 |
| UGC参与方式/观点 | 对应分类数量、占比、图表、代表帖与引用；不因此改变未受影响的整体情感或主对象 |
| 产品词、品牌筛选方法、平台或日期范围 | 对应范围全部重算；旧图例不能仅换名称而沿用旧结果 |

明确噪音须从活动统一总体排除；尚待核实的展示排除与统计剔除分别记原因。后续确认相关时撤销过期展示排除、按各层自己的原取数快照重新排序，不能混用品牌/活动快照或实时互动数。任一新源变更须全文检查同名指标，防止主图已改、其他段落仍引用旧值。

## 6. 审核与解释责任（P0）

Validator先核对最新需求与实际范围，再核数字和格式；“按旧模板计算正确、但未落实已明确更正”仍需退回。检查范围记录、真实媒体来源、统计方法、分子分母、图例与正文一致性、后续更新完整性；标注审核按当前每活动每轮500条共用上限及特殊标签优先方案，准确率与覆盖门槛沿用既有协议；不自动新增付费任务。

用户问“为什么这样算/是否按文件执行”时，先查本次实际指令、规则及数据，分别说明规则要求、分析者细化和执行错误。不能把业务口径更改误说成算法算错，也不能以符合模板为由忽略用户已明确要求。

NSR整体/子集定义、对象情感边界及正文不展示验算公式，统一遵循 `KS_Metrics_Calculation.md`。本契约与旧模板、图表或流程例子冲突时，按当前用户明确要求及本契约执行，并修正旧引用；不影响无关采集、权限、日期或付费规则。
