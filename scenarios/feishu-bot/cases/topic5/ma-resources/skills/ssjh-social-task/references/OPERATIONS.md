# 详细执行与恢复规则

当前入口见[SKILL.md](../SKILL.md)。以下版本号标明规则引入阶段；当前发布版本为v0.11.6。

# 数说离线任务取数

**取数任务创建接口成功即产生费用。** 先评估查询可比性并取得声量或明确标注的上游估算，再确认条件、数量上限及必要的不确定性接受依据，最后创建一次任务。估算不是账单数量；本地下载上限不能撤销已产生的费用。

v0.10.2以任务接口为主契约，预检不能裁剪任务参数。程序输出MATCHED/UPPER_BOUND/UNCERTAIN/UNAVAILABLE，按关系选择数量规则；未知估算须有上游接受依据，统计不可用可提供逐平台估算而不丢弃任务条件。参数范围、配置与恢复以[任务优先估算规则](ESTIMATION.md)为准。

本能力默认作为ADA工作流中间节点：`observability.delivery_mode: intermediate`，输出供上游消费，交付说明写入本地日志，不要求逐项转述给业务用户。直接面向用户交付时显式设为`user`，再由调用方承接进度通知。中台统一负责真实采集授权、跨请求/拆单费控与费用对账，本Skill不新增这些机制。既有数量确认入参、1000元本地门禁及同请求防误重放继续保留，不把它们称为中台身份审批或统一费控实现。

## 参数和依赖

供应商单价、预计/实际总费用和内部额度属于内部信息，不写入业务用户可见回复、数据文件、共享缓存或可公开的日志。计费确认交由获授权内部角色或上游可信授权流程处理；当前CLI已内置单次请求1000元固定预算门禁，数量确认仍保留；预算通过不替代真实取数授权。用户明确指定的超限话术可披露固定阈值，单价和实际费用仍保密。v0.11.5按用户授权内置内部价表供预算脚本使用；模型不读取费用文件，不得把费用直接放进会显示给业务用户的工具输出。

Python 3.10+、requests、PyYAML；XLSX另需openpyxl。SQLite使用Python标准库。运行目录、共享请求登记库、输出目录应位于有持久写权限的本机文件系统。

凭证从 `SSJH_USERNAME`、`SSJH_PASSWORD`、`SSJH_FIXED_TOKEN` 注入。声量和下载使用同一fixed token，创建使用对应账户。指定来源：[凭证文档](https://bluefocus.feishu.cn/docx/BNSrdHOplop3qCxPFZ0cNoFZnFg)，只按实际授权读取，不输出或打包凭证。默认不缓存token、不发邮件。

内置轻量声量适配器，只调用 `/api/socialmedia/totalVolume`；不再启动SSJH-Social-Stat或依赖其安装文件。接口结构参考v1.7.2源码；v0.9.3已在限定的微博主帖实测中验证该适配器。`query_contract.py` 规范化一份条件，再生成声量和任务请求。按平台、最多3个日历月的连续区间查询，汇总全部成功结果；不添加隐含postTypes，日期显式按Asia/Shanghai处理。预检时效从最早请求开始计算。

v0.11.0已实现13类来源/平台：微博、微信公众号、小红书、抖音、快手、视频号、B站、知乎、腾讯视频、爱奇艺、百度知道、新闻、论坛。各平台的站点、内容枚举、账号和类型由[平台契约](PLATFORMS.md)及platform_contract.py约束；新闻/论坛范围不变。搜狐视频仍待数据超市接入，不能标为已支持；汽车垂媒独立分支仅列入研发待办。

支持历史完整日期、任务200组关键词/排除词、情感子集、适用字段、已接入账号及isFast=0/1；默认不滤广告、不限互动量。新平台估算标为UNCERTAIN，须有上游接受依据；没有对应内部单价则收费前停止，禁止沿用其他平台价格。统计不可用时可以使用既有明确标注的上游估算机制。映射和离线测试不代表供应商真实验收；周期、时分秒及字面转义仍未支持。

## 广告和互动量筛选（v0.9.9）

上游未指定时使用`search.filters: {ad: all, interaction_min: null, interaction_max: null}`；省略整个filters或任一键均按对应默认值处理。`ad`可选all（不限）、exclude（仅非广告）、only（仅广告）；互动上下限只接受非负整数或null，包含边界，禁止布尔/字符串/负数/倒置区间。统一作用于本次已选平台，不接受逐平台覆盖或未知字段。

默认两端都不发送筛选参数，保留广告属性未知和互动缺失内容。**interaction_min=0不是“不限”：只要指定任一互动边界，供应商会排除互动为空的内容。** 不要求Agent猜默认阈值，也不将互动缺失视为采集bug。广告与互动同时指定时均应用。

声量和任务由同一规范化条件编译，筛选进入任务/预检/确认/缓存指纹。改筛选需按新条件重新预检和确认，禁止复用旧预检或旧缓存；原付费请求/任务不修改、不重建。默认配置与旧版“不筛选”请求语义和指纹一致，旧产物仍需原有缓存校验。公开信封data.filters、耗时与交付日志query_filters记录实际条件，不含费用。筛选任务不套用未筛选微博样本的5—20分钟参考区间。

字段映射、示例与验证边界见[筛选参数契约](FILTERS.md)。本版本筛选按官方文档实现并做离线验证，尚无真实供应商过滤前后成对验证；预检仍是估算，不是最终账单或强制下载上限。v0.10.0表达式/时间窗/认证及明确实例下的多平台状态处理见下文；转义传输与歧义实例保持代码阻断。

配置：[config.yaml](../config.yaml)、[api_config.yaml](../api_config.yaml)、[39列模板](../template.yaml)。字段含义/质量规则读取[数据字典说明](DATA-DICTIONARY.md)；执行规则来自[data_dictionary.json](../data_dictionary.json)。输出相对路径以任务配置目录为准。

## 计费发生时点

维护方已确认：统计接口调用失败不扣费，成功按每次调用计费；多平台或分段声量预检按实际成功调用计数。取数任务创建接口成功时费用已经发生，不能等任务处理、下载或导出完成才登记，也不能因后续失败或停止下载假定费用撤销。预检与任务创建都应在相应有效授权内进行；v0.9.6按内部单价和预估/批准数量实施固定预算门禁；供应商实际计费数量未受服务端硬上限约束时，不承诺最终账单绝不超限。

区分已确认失败与结果未知：本地超时、断网、响应丢失或解析错误不证明供应商失败。未知统计结果保留可能费用的预留并核实；未知创建结果复用稳定请求ID先对账，不自动再次创建。确认统计失败后释放该次预留，重试仍按各次真实结果计费且遵守有限重试规则。费用发生与最终账单金额核验分别记录；单价、总费用及内部额度不进入用户可见输出。

## 固定预算门禁（v0.9.6）

同一账户范围与稳定业务请求ID共用内部费用台账，硬编码上限为1000元，无提高/禁用参数。累计已发生及结果未知的统计费用预留，加拟采集费用超过上限即停止；恰好等于上限可通过预算检查，但仍须满足原数量确认、权限和接口条件。不得通过拆单、更换请求ID/内部台账或直接调用底层create_task绕过。

预检前检查计划统计调用的费用空间，每次实际HTTP尝试前事务预留；确认失败释放、成功记费、未知保留。取得每段声量后立即检查已知采集估算，已超限就停止后续统计调用。按各平台内部单价加总，批准数量高于预估时，额外数量按所选平台最高单价预留。approve与create均重检，私有价表变化使旧预检失效。创建的预算预留和本机防重复登记先持久化，再发POST；创建成功即记录费用发生，未知创建仍先对账。已有付费任务的恢复/本地导出不新建任务或重复登记创建费用。

超限返回非零退出码、state=BUDGET_BLOCKED、error=BUDGET_LIMIT_EXCEEDED；error_detail含route_to=upstream_agent、upstream_action=STOP_AND_ESCALATE、retryable=false。调用Agent停止本任务收费动作，向上游原样传递message，不自行联系人员或发送外部消息：

> 您的取数任务涉及数据费用成本过高，超出数据费费控阈值1000元限制，请联系智蓝数据部负责人袁杰松。感谢理解和配合！~

部署方通过环境变量SSJH_PRICING_FILE注入私有JSON价表，通过SSJH_BUDGET_DIR指定独立持久费用台账目录；两者不能放在Skill目录或业务run-dir内。价表最小字段：schema_version=1、currency=CNY、stat_success（十进制字符串）、record_rates（平台到十进制单价字符串的映射）。不提供带实际单价的示例，不将价表、台账或其内容打包。平台价格缺失、配置无效或旧预检无内部费用凭据时拒绝新收费调用，不采用免费默认值。私有存储必须由宿主限制为受信运行身份可读写，环境变量只能由部署方设置；本机文件检查不是多租户访问控制认证。doctor仅报告配置状态，不返回单价、费用或内部路径。

本门禁控制创建前的保守预算，费用台账中的采集金额是预留估算，不是供应商已核对账单。旧版未创建请求须重新按新版门禁预检，既有历史任务仍可恢复且不补造旧费用。禁止把候选包安装或代码修改授权当作真实采集授权。

## 业务请求身份与确认

Agent首次接到一项真实取数请求时，分配并保存一个稳定业务请求ID到 `task.request_id`，或者持久记录 `--request-id`。恢复、超时、换运行目录、重复点击必须复用该ID。用户明确发起另一项取数任务时才分配新ID并走新的预检和数量确认；不要每次执行都生成新ID。

所有运行默认共享 `~/.ssjh-social-task/requests.sqlite3`，可用 `--registry` 指定一处统一的持久登记库。不能给每个run-dir配不同登记库，也不能删除登记库以绕过重复检查。已有运行记住其登记库路径，恢复时不可静默更换。

同一ID绑定规范化查询、账户范围、供应商配置和原确认上限，改变绑定会拒绝执行。SQLite事务在创建POST之前登记未知结果，只有一个本地竞争者能发起创建。远端任务名确定生成为 `SSJH_<请求ID摘要>`，用于对账。这里保证同一共享本机登记库内的防重复；不声称跨机器/多用户分散登记或供应商端幂等。

确认引用是审计记录，不是身份认证：调用Agent负责它确实来自用户。代码修改授权不能作为取数授权。

## 正常流程

优先使用v0.9.7统一入口；首次调用完成声量预检后返回，不在同一次调用中消耗尚未展示结果的确认。业务用户或上游已确认同一条件及数量上限后，再调用一次带确认参数的execute。后续调用由程序识别阶段，不必由Agent自行拼接收费步骤。

```text
python ssjh_social_task.py --action execute --config TASK_CONFIG --cache-root USER_WORKSPACE_CACHE
python ssjh_social_task.py --action execute --config TASK_CONFIG --cache-root USER_WORKSPACE_CACHE --max-records APPROVED_LIMIT --confirmation-ref ACTUAL_CONFIRMATION
python ssjh_social_task.py --action execute --config TASK_CONFIG --cache-root USER_WORKSPACE_CACHE
```

缓存根由调用Agent按使用者工作空间指定，不能借用其他客户目录。查询条件、账户范围和供应商任务配置共同决定缓存子目录；输出路径、模板和格式不参与采集缓存键。也可用`--run-dir`恢复已有目录；它与`--cache-root`互斥。没有request_id时execute仅在新任务第一次进入时生成并持久保存；已有ID不得换号。删除状态/登记库、更换缓存根或跨机器不具有全局去重保证，不以这些方式重新取数。显式刷新数据是新的收费授权事项，本入口没有自动刷新数据的开关。

execute每次有界推进一个阶段：首次预检→等待确认→创建后立即返回job→查询既有任务→就绪后下载/校验/导出。未到最短120秒查询间隔返回已存观察，不重复请求。等待阶段再次进入不重新查声量；预检过期返回错误，只有明确重新执行precheck才查询新声量。预算阻断、失败或未知创建不自动重试整个流程；保留原请求并使用下述恢复/对账入口。

`action_policy.py`固定合法动作和状态：新创建只允许APPROVED_NOT_SUBMITTED；失败状态中的旧批准不可用于新POST。create对已登记job只返回/绑定原job，不把失败/完成状态回退为运行。内部状态写入由工作流负责，禁止调用方编辑state.json“解锁”。这些是本地误操作防护；持有同等文件/凭证权限的进程仍可修改代码或绕开入口，可信授权签发和凭证隔离须由目标Runtime承担。

以下分步接口保留用于诊断、显式预检和历史任务恢复，同样经过预算及状态门禁：

下面的TASK_CONFIG、RUN_DIR、REQUEST_ID等替换为实际值；所有步骤使用同一个登记库，可用 `--api-config` 选择管理员配置。

```text
python ssjh_social_task.py --action plan --config TASK_CONFIG --run-dir RUN_DIR
python ssjh_social_task.py --action precheck --config TASK_CONFIG --run-dir RUN_DIR
python ssjh_social_task.py --action approve --config TASK_CONFIG --run-dir RUN_DIR --max-records APPROVED_LIMIT --confirmation-ref ACTUAL_USER_CONFIRMATION
python ssjh_social_task.py --action create --config TASK_CONFIG --run-dir RUN_DIR --request-id REQUEST_ID
python ssjh_social_task.py --action resume --config TASK_CONFIG --run-dir RUN_DIR
```

1. plan只做本地检查，默认调用不会创建任务。输出配置、权限和服务调用仍按当次授权执行。
2. precheck只查声量；任一分段失败、缺数或结构不符，整个预检不可用于批准。保存请求条件和脱敏计数证据。零量不创建，过量先调整范围再查询。
3. 在当前会话展示全部条件、逐平台/合计声量、拟采用上限及“创建即计费”。用户确认后执行approve；已有有效确认覆盖相同条件与上限时不重复问。默认不发飞书卡片、消息或建立监听。
4. create先查共享登记库：已有jobId则恢复绑定；未知结果则停止并要求对账。新请求必须同时通过参数指纹、预检有效期（默认30分钟）、确认和上限校验，旧auto配置不能绕过。成功立即将jobId先写共享库，再写本地状态。
5. resume查询已有job，默认每120秒轮询，超时保留状态。完成后分页下载并导出。任务数量超过确认上限时停止下载并提示已创建，不能声称已经限制供应商费用。

## 查询与创建对账

```text
python ssjh_social_task.py --action status --run-dir RUN_DIR
python ssjh_social_task.py --action status --refresh --config TASK_CONFIG --run-dir RUN_DIR
python ssjh_social_task.py --action recover --config TASK_CONFIG --run-dir NEW_RUN_DIR --request-id REQUEST_ID
python ssjh_social_task.py --action reconcile --config TASK_CONFIG --run-dir RUN_DIR --request-id REQUEST_ID --job-id VERIFIED_JOB_ID --confirmation-ref SUPPLIER_RECORD_REFERENCE
```

status默认读取本地记录，updated_at不是远端实时保证；refresh发起供应商状态查询，瞬时失败按下文有限重试；已完成任务也会查询，但不覆盖已验证本地产物。recover只查共享登记库并绑定已知job，不创建任务。

创建请求超时、响应丢失或进程退出后，若登记库已有jobId，recover即可恢复。若仍为 `CREATE_OUTCOME_UNKNOWN`，先在供应商侧按登记的确定任务名定位，并核对实际查询条件；取得真实jobId和核对证据后执行reconcile。脚本读取该job的状态详情，校验id和任务名，再绑定原请求。当前详情接口不足以自动核验全部查询条件，调用方必须完成该项核对。不猜jobId、不自动重新POST，不把“未找到”当作一定未创建。没有核对结论就保留未知记录。

供应商是否提供幂等键或按请求ID查询接口仍未确认；本版本不发送虚构参数。

## 分页与导出恢复

v0.10.1在下载与缓存交付前执行[数量偏差门禁](QUANTITY.md)：预检与任务量差≤20条或≤5%放行，差>100条且>20%暂缓并反馈上游，其余告警；总量和各平台分别判断。分平台证据缺失也暂缓。任务量与下载量仍严格相等，批准数量上限不受容差放宽。QUANTITY_REVIEW_REQUIRED不自动继续；显式review-quantity只复查原job，不创建付费任务。阈值配置、零基数及旧缓存恢复详见该规则。

每页落入 `pages/generation-*/`，保存job、请求游标、返回游标及记录，校验文件哈希、ID唯一性和数量；SQLite临时索引限制内存占用。`pages/manifest.json` 是下载检查点。

- 页面已完整写入、检查点尚未更新：恢复时核验并接纳该页，继续下一个未使用的游标。
- 请求可能已经消费游标、响应却未落盘：保留旧代页面，针对同一job开启新下载游标，重新下载到新一代；不拼接无法证明一致的前后页面，不重新创建任务。
- 页面损坏、重复ID、缺ID、异常返回或数量不符：明确失败，保留证据，不改成空成功。尚未证明供应商游标可幂等重放，不能自动重发不确定游标。

完整页面先执行下述返回数据校验，再流式生成原始 `records.json` 和CSV/XLSX。先写同目录临时文件并逐单元格回读核验、校验数量和哈希，再记录 `export.json`，以不覆盖既有文件的方式原子发布；最后写result和COMPLETED状态。文件发布后进程中断，恢复通过导出清单核验已有文件、完成剩余发布，无需重新取数。已有文件发生变化则停止，不覆盖用户修改。发布依赖本机文件系统支持硬链接；不支持时报错，不降级为覆盖写入。


### 供应链覆盖与互动指标说明

依据能力维护方提供的供应链规则：内容采集与互动指标采集并不完全同步。供应商采用分层采集，部分头部达人/账号内容会同时采集互动指标，并按不同周期更新（例如7天、15天或30天；这些是可能的策略示例，不是每条内容的固定承诺）；另有部分内容不采集互动指标。因此，互动指标未提供是正常的供应链覆盖情况，已有值也可能是供应商最近一次采集的快照，不代表查询时实时值。

Agent不得仅因互动字段为空就判断原文丢失、取数失败或Skill故障，也不得因此自动追加付费采集、过滤记录或阻断交付。不增加按互动覆盖率拦截的业务质量门槛。保留缺键、null、空值和0的区别，不填0、不推算不存在的互动值。质量报告仍如实记录覆盖情况；向用户将此解释为“供应商未提供/未覆盖”，避免把常态覆盖限制表述为数据损坏。除非涉及本次分析解释，无需逐条重复提示。

这不豁免程序完整性检查：若原始响应存在数值而导出丢失、字段映射错误、页数/条数/ID异常，仍按实现缺陷或完整性错误处理。进行互动分析时说明使用的是有指标覆盖的内容及其快照，不将未提供指标的内容解释为零互动。


字典说明和逐项规则见[数据字典](DATA-DICTIONARY.md)。预检/创建前检查字典可用性；页面完整后进入VALIDATING，写validation.json。该报告绑定job、页面与查询指纹及字典版本/哈希，分别给出缺键、null、空值、非空率、类型/格式异常、日期范围和数量差异；不复制正文等敏感字段值。

- FAIL：结构、ID、条数或非标准JSON等硬错误阻断交付；保留原任务/页面和错误，不自动删行、去重或重建。
- PASS_WITH_WARNINGS：可选字段缺失、类型/格式异常、预检差异等明确告警，保留原值，不补0、不猜字段别名。导出成功仍需说明影响使用的主要异常；互动指标缺失按上述供应链覆盖说明解释，不因正常覆盖限制宣告取数失败。
- PASS：本轮已执行规则没有发现错误/告警，不表示供应商语义、业务分析适用性或计费均已验证。

result.json和状态事件包含quality的状态、报告路径/哈希、字典版本及错误/告警次数。交付说明应包含数据范围、预检/任务/下载数量、质量结论、主要缺失/异常字段、文件路径；不能只给“下载完成”。默认模板已修正转发/评论/点赞/互动量四项映射；完整官方数据字典、跨平台计量口径及阅读量来源仍待补齐。

## 错误与有限重试

结构化错误包含 code、category、operation、attempt/max_attempts、retryable、http_status/provider_code、retry_after_seconds、outcome_uncertain 和 next_action；只输出固定错误码和指导，不输出异常原文、响应正文、凭证或含 token 的 URL。attempt 字段只在实际传输失败时存在；retryable 表示该类操作具备重试资格，不代表当前预算仍有剩余。

- 仅 status/volume/count 对网络超时、连接失败、429和5xx自动重试。默认共3次、45秒调度预算，配置上限5次/60秒，退避加少量随机延迟。尊重 Retry-After 秒数/HTTP日期；超过剩余预算即停止并返回所需等待，不提前重试。
- status遇401或业务码100000最多刷新一次动态token，计入同一预算；固定token失效、403/100001权限不足、100110账密错误、证书错误、无效JSON或数据结构不重试。不要关闭TLS校验。429/5xx既识别HTTP状态也识别数值业务code。
- create、login和download游标请求只发送一次，关闭自动重定向；未知创建或游标结果沿既有登记/分页恢复流程处理。不得因通用“retryable”标记重新执行整个工作流或生成新请求ID。
- 超时参数是连接/读取不活动限额；本地 requests 无法硬中断持续缓慢返回、DNS或系统阻塞。因此45秒是重试调度预算，不承诺严格墙钟上限。供应商原有最短120秒轮询间隔不变，预算用于单次查询中的瞬时故障恢复。

## 状态解释与当前会话交互

`status`读取不写盘、不创建目录。`updated_at`仅说明本地记录更新；`last_poll_attempt_at`是最近查询尝试；`last_successful_poll_at`仅在供应商状态ID、结构及数量校验通过后更新；`last_progress_at`仅随阶段或数量变化更新。相同状态的重复轮询、重试日志和本地错误不能刷新“实际进展”。旧记录缺少这些时间时显示未知，不根据旧updated_at补造。

摘要给出中文话术、最近观察年龄、超过300秒的过期标记、错误与安全下一步。只有已知task_count时展示下载百分比；不提供推测的整体百分比。符合下述实测范围时，运行中的公开输出data.eta提供参考总时长范围，其他范围不返回估计。显式刷新已完成任务时，若远端状态/数量与本地产物冲突，保留本地COMPLETED和产物，显示remote_result_conflict并交由核对。

中间节点把jobId、数量、阶段、错误和完成记录交上游，不要求直接通知用户。user模式下由调用方处理进度待办，并在真实送达后回执；长等待可使用已用时、最近成功查询时间与适用估时。不能把没有更新解释为正在推进，也不虚构整体百分比。Skill没有自行发送消息、后台监听或唤醒能力，事件已生成不表示用户已知。

## 耗时、通知和中间产物日志（v0.9.8）

程序在run目录下维护三份结构化日志；它们不包含单价、费用、原帖正文、关键词或凭证。关键词等完整查询仍在原本的配置/预检与state契约内，诊断时通过查询指纹关联，不在日志里复制。

| 路径 | 记录内容与使用方式 |
|---|---|
| `logs/timing.json` | 每个采集任务一份当前样本：稳定sample_id、Skill版本、平台/时间窗口/主回帖范围、预检/任务/下载数量、各阶段进入退出时点、创建到首次观察就绪/校验交付的总耗时、原始估时及命中情况、错误与观测间断 |
| `logs/progress.json` | 进度事件及pending/superseded/acknowledged状态，稳定event_id、生成时点、路由对象、话术与回执摘要 |
| `logs/deliveries.json` | 校验通过后的中间产物记录：查询指纹与时间范围、数量、质量报告、文件及哈希、已知使用限制；区分acquisition/cache_reuse/local_reexport |

日志是state.json内observability记录的可再生视图，与业务状态一起原子落盘后再生成；恢复执行会从state重建未写完/损坏的日志视图。不要直接编辑日志修复状态。`events.jsonl`保留逐次运行事件；三份JSON便于按键读取/后续批量分析。日志留在使用者工作空间，不自行集中上传。

耗时基于本机墙钟，从创建意图提交点到实际文件校验交付，包含查询间隔和恢复等待；首次观察就绪不是供应商真实完成时刻。人工确认之前的等待不计入采集总耗时。默认sample_kind=normal；测试或诊断任务应在启动前配置test/diagnostic，开始记录后禁止改标签。未观察到创建、历史任务恢复、未完成、时钟逆跳、采集错误、创建后超过300秒的观测间断均保留样本并标记排除原因，不作为默认估时训练样本。这个筛选是保守的质量标记，不证明其余样本均具有生产代表性。

正常授权任务自动积累记录，不为填充样本发起付费测试。缓存再用和本地再导出不重置采集完成时间，也不生成第二个采集样本；同产物再次验收仅增加verification_count，新导出保存独立delivery_id。后续跨目录汇总按sample_id去重，同时保留不同run_id的观测差异。本版只记录历史数据和现有参考区间的命中情况，不自动训练模型、改写5—20分钟区间或外推其他数量级。

通知采用本地待办，按阶段变化、新错误、恢复和首次超出已有估时上界生成。相同轮询、下载页计数变化不反复生成通知；新进展将未处理的旧事件标记superseded，保留历史，避免任务已完成后仍提示“开始处理”。只有真实导出/缓存校验通过才生成完成通知。

```text
python ssjh_social_task.py --action ack-notification --run-dir RUN_DIR --event-id EVENT_ID --delivery-ref ACTUAL_CONSUMPTION_REFERENCE
```

notifications只读当前pending事件，不读取API配置、不联网、不标已处理。调用方完成工作流消费或实际消息送达后才执行ack-notification；回执仅保存引用哈希，相同回执可重复，未知/已过时事件及冲突回执拒绝，且不修改采集状态。ack表示调用方报告已处理，未经独立送达验证。外部发送成功但未回执时事件仍pending，调用方须用event_id实现接收端去重，不承诺跨系统恰好送达一次。中间模式的事件audience=workflow，交付日志默认不转述给用户。是否启动监听/消息渠道由宿主有效授权决定，包内不创建这些动作。

现行预检凭据contract_policy_version=4，绑定任务及独立估算计划；旧版尚未创建请求须重新预检、确认。已付费请求保留原条件/任务ID，不能重新提交。旧记录未标估算关系时沿用原数量检查，不自动改为不确定放行；详见任务优先估算规则。

状态解析按当前job绑定实例ID、重跑version和schedStart/schedEnd。同周期唯一最高版本为当前实例；旧版本不相加，范围外旧周期忽略，部分重叠/混合周期/相同最高版本多实例/缺身份一律返回固定核对错误。0状态可等待；当前实例失败或errCode非0即停止。明确成功后，无论主任务为1还是2，都通过同job的/count（pLimit=1、不指定dataType）核对完整可读数量；与当前实例dataCount一致才就绪。/search使用同样完整job范围。数量不一致继续原任务等待，超批准数量停止；下载还须数量/唯一ID/导出核验。已完成文件不被远端变化覆盖，实例变更会标记冲突。

此适配已用历史微博+新闻160条响应离线重放至导出，没有新增真实调用。多平台不等于多执行实例；无法确认的多实例仍由代码停止，不让Agent累加或猜选。供应商内部索引延迟与最终计费条数仍不能从预检保证。

同轮906条实测：请求size=100，供应商实际返回500条并给出scrollId。size按请求提示处理，与本地单页硬上限分开；max_response_records默认500且最大500，超过仍拒绝。累计条数不得超过已核对任务量/批准量，ID唯一与分页完整性校验不变。不确定游标先保存旧代并开同job新下载代，不重建计费任务。该差异只有大于100条的真实样本才暴露，原63条回放不构成页大小契约验证。

## 低成本耗时参考与提示

v0.9.7将已有低置信参考纳入程序输出：单平台微博主帖、正数且不超过1000条时，运行阶段data.eta为创建起算的300—1200秒参考总时长，basis=similar_historical_tasks、is_sla=false；不随轮询重置窗口，也不表示剩余时间。超过上界改用延迟话术。其他平台/更大量不自动外推。向用户提供简洁、宽泛且有证据支持的时间范围；供应链任务通道占用未知时不可假称已观测。用户未询问时不主动展开影响因素，但阶段变化、完成、延迟或异常仍按状态交互规则报告。

2026-10-30小额测试共6次，每档1次诊断、2次正常流程：63条耗时8分18秒/14分33秒，906条耗时14分31秒/6分25秒。先用两次正常样本登记的8—20分钟区间，后两次检验1/2命中，未命中为提前完成。测试后修订为 **5—20分钟** 试用参考：最短耗时向下取5分钟边界，最长耗时加25%后向上取5分钟边界。修订利用全部4个正常结果，尚无新样本检验，不是P90或生产SLA。

参考范围仅为同日单关键词微博主帖、相近条件、正数且不超过1,000条任务的低置信试用，其他平台/更大数据量不直接套用。计时从发起创建至本地文件核验完成，不包含声量预检或人工确认。服务端排队/缓存未受控，不按数据量线性外推；后续证据以本版本研发回交及正常任务记录为准。

- 创建后：“已提交取数任务，预估N条。根据同类小额测试，预计约5—20分钟，预计在HH:MM—HH:MM完成；本次以实际返回为准。”仅在符合上述范围且调用方接受试用估计时使用；时间窗口由实际创建时间计算。
- 较长等待：“已用时X分钟，当前处于数据准备阶段，最近一次检查HH:MM。预计完成窗口仍为HH:MM—HH:MM。”只报告真实查询确认的阶段；查询失败时说明核查暂时失败，不沿用旧状态冒称已刷新。
- 超过上界：“本次已超过原预计窗口，数据尚未就绪，正在继续核查原任务。”保留原预测与实际延迟，不每轮把窗口向后重置；需要修订时明确原预测、修订依据及新估计。
- 数据就绪、下载、核验完成或异常时及时说明。整体百分比不按已用时间推算；只有已核实总量的下载阶段才使用下载比例。无背景运行承载时说明当前执行状态，不承诺会自动回来通知。

后续从正常获授权业务任务积累平台、数量、时间范围、提交时点及阶段耗时，按可比条件逐步更新估计。未经授权不为了填满大档位而创建昂贵测试，少量样本不输出P90或生产SLA。


## v0.11.1 导出与恢复

XLSX 遇到回车符（CR/CRLF，自v0.11.6起）、非法控制字符、Excel 长度上限（32767 UTF-16 单位）或保留标识前缀时，主表单元格标明完整内容位置；text_overflow 按主表行/列、part 顺序保存 ASCII JSON 分片和 SHA256。拼接后 JSON 解码可还原全文，程序逐片及还原后校验，禁止静默删字/截断。records.json 保留原始字段值，常规单元格展示不变。

旧 PREPARING 导出只有查询/页/模板/输出完全一致且尚未发布任何目标文件时，保留旧清单后本地迁移；已发布缓存仍须哈希核验，改变输出契约须新路径，不重新创建任务。已有历史日志保留原始版本，当前执行版本单独更新；无阶段标记的旧 transport_event 不作为当前事件输出。
