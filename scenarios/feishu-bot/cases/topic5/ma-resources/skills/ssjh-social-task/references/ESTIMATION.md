# v0.10.2：任务契约与预检估算分离

任务接口是主契约。query_contract.normalize/task_payload校验并保存完整任务条件；precheck_policy.plan仅生成估算请求和解释，不修改任务。`--action plan`可先做纯本地规划，data.estimate公开关系、未决项与统计侧调整，不返回费用。

## 本轮开放与仍有边界

- 关键词/排除词分别按任务200展开组校验。统计每次仍最多50组；包含式51—200组展开后按50组拆批，批次可能重复命中，合计只能作有条件的上界；排除式超过50组时统计不施加排除，但任务保留全部排除词。每批真实调用分别经过预算门禁，不截断任务也不偷偷多创建任务。
- 情感支持0/1/-1任意非空、不重复子集。匹配字段按当前已接入平台的任务字段表检查，支持正文/标题及适用的OCR/ASR/花字等，不因统计不支持就删任务字段。
- 新闻/论坛可指定数字站点ID，统计省略站点以取较宽范围；任务保留newsSite/forumSite。快手short_video.post_types可填video#0、image#0或二者，任务保留kuaishouPostType，统计省略形态。选择视频号时不套用快手形态。
- is_fast=0/1保留到isFast。在线采集会改变数据总体，当前存量统计只能作不确定估算，不能承诺最终费用上限或沿用历史存量耗时区间。日期仍限已结束完整日期、最长12日历月的一次性任务；未来日期/周期任务未接入。
- 可用profiler.weibo_uid、xhs_acc_id、kuaishou_uid、shipinhao_uid指定已选平台账号。关键词可与账号同时传入，或纯账号；每个已选平台必须有关键词或对应账号。统计端账号组合语义未核实，暂用上游估算路径，不将账号从任务删除。
- v0.11.0平台范围以[平台契约](PLATFORMS.md)为准，新增七个平台的映射和分平台计数，私有费率须由管理员补齐；搜狐视频/周期尚未接通，不声称任意官方API参数均已实现。非法语法/类型、任务超过200组、任务日期跨度超限仍拒绝。字面转义的实际创建传输表示尚未可靠确认，继续明确阻断，不能按猜测收费。

## 关系决定规则

| relation | 含义 | 数量检查与创建条件 |
|---|---|---|
| MATCHED | 已开放参数可直接对应，没有本规则识别出的关键语义疑点 | 沿用双向数量容差；不是供应商数据快照/权益/去重已认证 |
| UPPER_BOUND | 仅在统计侧放宽任务筛选或合计重叠批次 | 实际≤估算不判少取；实际超过上界按向上偏差检查。上界以共同基础范围及观察时点为前提，不是最终账单保证 |
| UNCERTAIN | 跨字段/微博title/评论/互动边界/在线采集/部分平台存量/多日期段等语义不充分，或上游提供估算 | 数量差只作告警记录，不冒充同口径PASS或直接判任务失败；创建前须有上游不确定性接受依据，仍走预算与数量确认 |
| UNAVAILABLE | 统计无法提供完整的有效请求集合，如超统计历史窗口、账号组合尚未支持 | 任务配置有效，precheck不调用任何统计接口，返回上游估算需求；提供完整逐平台估算后按UNCERTAIN继续 |

混合平台取最保守的整体关系；已确认的放宽和未决原因都保留。只要存在关键未知，不把放宽自动归为可靠上界。多平台可读计数仍须求和一致、证据完整。无论关系如何，实际下载条数与任务可读量必须一致，批准max_records、唯一ID、分页、导出完整性继续严格检查。

## 上游估算与接受依据

正常先运行precheck，阅读data.estimate及声量。若为UNCERTAIN，上游明确接受本次估算不确定性后，在配置写入真实记录引用，再执行原approve/带确认execute流程：

```yaml
precheck:
  uncertainty_acceptance_ref: "实际上游接受记录引用"
```

这与数量确认引用分别保存；代码保存接受引用摘要，创建前复核。没有非空依据拒绝创建；改依据须重新approve，不以数量确认自动代替不确定性接受。它是调用方声明记录，不是身份认证或中台审批签名。

统计UNAVAILABLE或上游有独立估算时，可以指定完整逐平台数量；下面仅为配置结构示例，不能原样用作真实授权或真实预测：

```yaml
precheck:
  manual_estimate:
    counts:
      weibo: 120
    reference: "实际上游数量估算证据引用"
  uncertainty_acceptance_ref: "实际上游接受该估算不确定性的记录引用"
```

counts键须精确对应全部已选平台：weibo/xiaohongshu/news/forum/kuaishou/shipinhao。数量为非负整数，总量必须正数才能创建。上游估算不调用声量接口，不伪造供应商响应；凭据明确source=upstream_estimate，按相同内部单价/预算门禁计算。它只是被接受的规划估计，不能保证供应商实际账单不超限，不能用于隐瞒已知更高规模以绕过固定门禁。真实来源和接受权由中台承担。

任务指纹不包含估算策略，但预检另外绑定完整计划、统计请求或上游估算及来源摘要；更换估算使旧预检失效。任务条件改变仍使原确认、缓存、请求绑定失效。所有新收费动作仍需当次有效授权。

## 恢复和历史证据

新预检contract_policy_version=4；旧未提交预检须按新计划重新预检/确认。已付费请求不补建、不改任务参数；共享登记记录保存估算关系供跨目录恢复。已有v0.10.1付费记录没有分类时保留原数量检查策略，不自动把历史重大偏差改成不确定放行；维护方先核对原证据。完整缓存复用沿用原记录关系，不联网生成新声量。

原三个月分段的整秒边界本轮没有擅改为未经供应商确认的亚秒语义；存在多段时明确UNCERTAIN。报价/计费硬上限、服务端索引/去重、部分字段与平台语义仍需真实验证；本版为离线候选，不代表供应商端到端验收。
