# 过滤词发现与核验

本文件保留原规则第6节编号；第3.1、第5.0及第5.1的采用门槛见 [generation.md](generation.md)，返回字段见 [contract.md](contract.md)。默认词是Topic5确认的范围约定，不是所有业务的通用规则。

### 6. 过滤词发现、验证与返回

#### 6.1 输入与职责

用户只需明确品牌、活动、统计周期、平台和分析范围，不需要提供全量数据或自行编写排除词。本能力在正式取数前，利用活动主体与范围、品牌歧义知识和 SSJH 有限样本发现噪音，拟定有依据的过滤词建议。全量逐帖消歧不是生成排除词的前置条件。

由活动边界、语言知识、用户历史案例或词云异常线索拟定的词，先记为候选；用本次 SSJH 关联帖子核实后标记验证状态。用户明确给定或认可的过滤词可记为user_confirmed并作为本次口径，但API尚未验证时须同时记录validation_state=not_run；用户确认不等于取数验证完成。

#### 6.1.1 按品牌类型主动带入默认过滤词（2026-11-02 用户确认）

| 品牌类型 | 默认品牌过滤词 |
|---|---|
| 家电品牌，如美的 | `转租\|合租\|中介\|拎包入住\|家电维修\|家电回收` |
| 数码3C品牌，如联想 | `二手\|转转\|爱回收` |

- Supervisor根据已识别的品牌类型主动将对应完整表达式写入`brand_filter`，不要求用户写词，不自行删减，也不将未重跑验证作为改回空过滤词的理由。`|`表示或关系。
- 这些是用户确认的品牌内容范围排除：房源出租、合租/中介、维修服务、回收和二手交易等内容，即使真实提及品牌，也按表达式过滤。仅有真实品牌提及不构成保留理由。
- 品牌类型不在上表（如食品饮料、美妆、汽车、服饰等）时，没有用户确认的默认式：`brand_filter` 留空，不借用家电或数码3C的默认词，也不自行编造类型默认清单。可按 6.2 的品牌歧义和词云异常途径拟定候选，记入 `filter_candidates`（`status=pending_validation`），满足5.1.2新增过滤词核验条件后直接采用并写入 `brand_filter`（`status=adopted`），无需用户确认；用户为新类型确认默认式时，在本表追加并记录日期。
- 在默认词基础上，通过词云和关联帖拟定项目补充词；未达到采用门槛的候选词单独记录，核验通过的补充词自动采用并留痕，不替换或删减默认清单。用户明确指定其他分析范围时按其要求调整并记录，不擅自推定例外。
- 消费者的故障反馈、维修经历、投诉与维修服务广告应区分；不默认另加一个宽泛的`维修`。检查默认式可能连带排除的消费者内容并记录影响，不因误排风险自行撤掉用户确认词。
- 品牌与活动过滤词分别记录；默认品牌过滤词不自动复制到活动过滤词。本规则不等于启用API的广告过滤开关。
- 将规则依据记录为用户确认（`source=user_rule`、`status=user_confirmed`）。规则确认与API验证分开；尚未按完整默认式重查时`validation_state=not_run`，重查后按实际结果更新，不能沿用此前空过滤词的声量作为过滤后声量。
- 用户后来粘贴的缩略表格不自动视为删除原清单。完整默认清单以本节和用户最后明确确认的表达式为准；修改须有明确指令。

#### 6.2 发现噪音的途径

| 方法 | 操作 | 需要核实什么 |
|---|---|---|
| 活动主体与周边品类 | 根据本次推广对象识别周边商品、维修/改装等衍生服务词，再与原检索式组合查看推广内容 | 是否属于本次分析排除范围；适配该新品也不自动属于上市传播范围 |
| 品牌名称歧义 | 根据品牌的普通词义拟定噪音短语，定向查看命中帖 | 联想是品牌还是动词，美的是品牌还是形容词；明星共现不代表品牌指代成立 |
| 词云异常词追查 | 查词云中与已知活动明显不协调的商品、场景或主题词；用原检索式＋异常词查关联原帖 | 为什么命中原式，是正常产品/食谱内容，还是无关商家挂传播话题卖货 |
| 分支单独试查 | 按括号逻辑展开原式的各个或分支，分别查询 | 哪个别名、角色词或话题引入了噪音；不能简单按字符串中每个“|”切分 |
| 不同排序抽样 | 在本环境 SSJH 已支持的排序或分页范围内补充样本 | 热门列表之外的近期、低互动或商家帖子；没有接口支持时记录限制，不编造最新帖查询 |
| 重复文案／账号检查 | 查多个账号是否重复相似文案，或同一账号反复挂话题 | 是否形成无关商品引流内容群及其共同表达；重复本身不能证明噪音 |
| 关联词组合追查 | 将包邮、橱窗、批发等发现的线索与原检索式组合 | 是否在销售无关商品；这些线索也可能出现在正常活动商品帖中 |
| 相近活动检查 | 查同品牌/IP/人物的其他活动名、时间和场地 | 是否混入其他项目、往期活动或其他站点，优先修正关键词边界 |

异常词不是排除词。词云没有显示明显异常也不能证明没有噪音。不能仅检查最热门的几条帖子，发现线索后应定向查询关联原帖。

#### 6.3 定向追查与命中原因

对异常词使用 `(原检索式)+(异常词A|异常词B)`，继承相同日期、平台、内容范围和其他条件。按 SSJH 实际语法构造，不把占位符当成真实词发送。

检查当前检索范围内的标题、正文、话题，解释原式可能命中的品牌词、活动词或分支；接口未给命中字段时不把推断写为事实。本流程不启用OCR检索，不能用返回OCR/ASR字段代替正文关联核验。记录原因属于普通词义、无关商家借话题、其他活动混入，还是用户已纳入的正常传播。

例如 `(联想|Lenovo)+张凌赫` 仍可能命中“看到张凌赫就联想到牛”。这是共现但没有品牌指代的噪音。反之，“联想官宣张凌赫，让我联想到青春校园”同时含品牌指代和普通词义，应保留。

#### 6.4 围绕活动主体拟定过滤词，必要时收紧检索式

先判断噪音能否通过更准确的活动关键词解决。例如金典共用主题口号混入猫咪公益，应缩回候鸟项目/防鸟撞线索，不直接把“猫咪”设成全局排除词。

**用户确认的品类过滤规则**：围绕用户要分析的活动主体，识别并排除周边商品、衍生服务的推广，优先使用直观的品类词。内容涉及品牌或适配该新品，不代表它属于本次分析范围。用户无需自行编写品类清单；Supervisor 根据推广对象拟定，再用词云和关联帖核实、补充。

- 汽车新品上市：`贴膜|维修|改装`，用于排除这类衍生服务内容。
- 手机新品上市：`手机壳|手机膜`，用于排除周边商品推广。
- 这些是按活动范围选择的示例，不是所有项目的通用清单。促销／节日营销、公益、赛事赞助等活动不因类型自动套用新品周边过滤词；无适用规则且无核验支持时`activity_filter`留空。试查发现借话题引流、其他活动混入或范围外商品／服务时，按6.2–6.3追查，再按5.1.2判断。手机壳发布、改装活动、IP联名周边复盘等需求中，相关品类本身可能就是核心对象，不应套用排除。
- 品类词拟定不需要先找到某个商家的固定招揽话术。具体广告短语可作为补充，不能用“只能写很细的短语”的要求阻止用户认可的品类排除。
- 品牌普通词义噪音优先考虑增加产品/业务限定，例如小米品牌词收紧到本次产品；与周边品类排除是两种不同处理。

每个候选记录适用层级（品牌/活动）、来源、实际示例、拟排除的噪音类型、正常内容误排风险和验证状态。

候选状态使用 `pending_validation`（未完成本次验证）、`supported_by_sample`（有本次样本支持，仍有范围限制）、`adopted`（能力自行判断采用，无需用户确认）、`not_adopted`（不采用）或 `user_confirmed`（用户明确给定或认可）。样本支持不等于全量安全；用户已确认的词发生实质修改仍需用户同意，`adopted`的表达可在不改变需求范围的前提下由能力依新证据调整并留痕；改变统计对象、活动边界或排除品类时仍须需求澄清。

#### 6.5 误排检查

1. 使用原检索式＋候选排除词查看关联内容，明确括号并重新计算展开组；词内需字面特殊字符转义时不实际提交，不猜测转义。
2. 需要时对同一检索式做过滤前/后试查，比较结果并记录样本限制。Top列表不再出现某帖可能只是排名变化，不能把所有列表差异都当作已排除量。
3. 检查有无正常品牌提及、官方活动、产品体验、公益参与、投诉等内容也含候选短语。先区分“仍在分析范围内的内容”与“用户明确排除的周边/衍生服务内容”。有品牌或产品提及不自动构成误排。品牌歧义短语与真实活动混合时仍要检查误排；用户已确认按品类过滤时，帖子即使同时提产品也按该表达式排除，并记录可能连带排除车主体验的范围影响。
4. 若候选排除了仍在用户分析范围内的内容，提出调整表达或分支的建议；用户明确认可品类排除时沿用已确认口径，记录影响，不擅自改回空过滤词或强制替换为长广告话术。SSJH 的过滤词可能对整组检索式全局生效；不能把“仅某分支适用”的词悄悄当作全局过滤词。
5. 没有明确范围依据或样本支持且用户未确认时，可保留空过滤词并说明限制，不强行凑排除词清单。此条不适用于 6.1.1 的品牌类型默认过滤词：该默认式已由用户确认，不得以“无样本支持”为由留空。不需要用户提供全量数据来完成以上试查。

除本节用户已确认的品牌类型默认过滤范围外，不默认排除负面评价、投诉、攻略、穿搭、代购、转售、拼单或交换内容；根据用户分析范围判断。仅挂话题但内容关联弱时，要区分“话题命中”与“品牌有效传播”，不能未经确认改变统计范围。

#### 6.6 讨论案例及证据状态

- **联想歧义候选**：`联想到|联想起|联想出|产生联想|引发联想`。这些由普通动词语境提出，是待验证候选，尚未针对具体联想活动完成 SSJH 误排验证。“联想到了”“联想起来”已被更短的候选覆盖，不必重复。不能当作联想所有项目的固定排除清单。
- **美的歧义候选**：`美美的`，如“天气好，心情美美的”。同样待本次样本验证，不直接全局采用。
- **用户提供的锋味派案例**：用户历史试查时，词云出现“竹笋、竹荪、榛蘑、木耳”；查看原帖发现，部分带橱窗/挂车的商家借锋味派传播话题销售自己店铺的无关商品。这个案例支持“词云异常词→追查原帖→核实借话题引流”的发现方法；并非本能力已重新查证的 API 结果。具体候选必须结合当前范围验证，正常食谱也可能出现这些食材。
- 锋味派追查示例：`(本次锋味派原检索式)+(竹笋|竹荪|榛蘑|木耳)`。确认无关商家内容后，再决定采用商品词或更准确的共同噪音短语；不直接照抄四个词作为全部锋味派活动的过滤词。

- **小米澎程上市：用户最终确认**：2026-09-07—2026-10-07，微博、抖音；关键词`(小米|xiaomi)+(澎程|N70|N90)`；过滤词`贴膜|维修|改装`；查询字段`content,title`，关闭OCR。status=user_confirmed、validation_state=not_run，这组广品类过滤口径尚未重新取数验证。此前6组具体商家表达在抖音排除67条的试查属于旧口径，不能作为新过滤词的效果证据。
- **iPhone 18上市：规则示例**：`手机壳|手机膜`作为周边商品过滤词，用户认可的是规则与示例，未提供完整统计范围，未执行本次API验证。

#### 6.7 返回与回写

返回最终采用的品牌与活动两套关键词、分别记录的brand_filter与activity_filter、暂不采用词、理由与实际噪音证据。先沿用适用的已确认规则与用户表达式，再写入满足5.1.2的新增过滤词。无规则且无核验支持时过滤词留空；候选仅放filter_candidates。各项来源、采用决定与API验证状态分别留痕。

采用的关键词和过滤词内部保存到确认单，不向用户逐项展示，用户主动询问时如实解释。记录实际检索字段、OCR关闭状态、作用范围、排除品类、依据、误排影响、验证缺口和导出排除状态。

正式取数后发现新噪音，可在同一需求范围内调整能力自行生成的别名、拼写、限定和过滤表达，保存原式、新式、原因、证据、影响与版本。调整若改变统计对象、活动边界或排除品类，须作为需求澄清处理，不因原式为auto_adopted而跳过。用户明确给定或确认的表达式原样保留，实质变更须取得其同意；旧式结果不冒充新式验证。
