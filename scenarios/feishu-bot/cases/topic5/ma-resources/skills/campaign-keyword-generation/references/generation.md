# 活动边界、表达式生成与采用

输入输出见 [contract.md](contract.md)，过滤词第6节见 [filtering.md](filtering.md)。

## 执行流程

### 1. 理解需求，初判活动类型与范围

先理解用户要复盘的活动，从活动描述识别品牌、主对象、时间、平台、站点或话题边界及业务问题。Topic5不进行品牌整体/具体活动/两者的需求分流；品牌与活动两套取数口径共同服务活动复盘。不能先按出现的人物、产品或“官宣”等字眼套公式；多活动各自处理。

用户明确的活动类型优先；没有明确时，根据活动事实提出有依据的初判。主类型决定取数边界，联名、互动、线下体验等可记为辅助形式，不强制唯一类型，也不限制只能八选一。KOL种草、新闻稿、直播等是传播执行方式，可辅助记录，不能替代活动主对象的判断。

### 2. 秘塔补背景，核实初判

有背景缺失或疑点时，携带品牌、活动描述、年份及已知线索搜索；明确话题、沿用既有口径且无疑点时可不搜索。核实名称、合作对象、参与角色、人物别名、产品、项目主题、场地等。检查具体来源和原文，不把搜索摘要当作已核实事实；不混入往年或同品牌其他活动。

秘塔缺少可靠背景时，记录缺口，可继续用明确的品牌和活动线索试查 SSJH。角色和昵称不凭常识编造，不要求维护无限扩张的固定词库。用户提供的传播帖可作为线索，但当前不得依赖特定环境的浏览器能力；仅使用环境实际支持的读取途径。

### 3. 按类型生成初始检索式

| 活动主类型 | 需核实的线索 | 初始组织方式与边界 |
|---|---|---|
| IP联名 | IP、本次参与角色、别名、组合称呼 | 品牌＋IP/角色/组合称呼；歧义词加限定，IP全部角色不等于本次参与角色 |
| 品牌跨界联名 | 合作品牌、活动专属名称 | 两个品牌组合，补充经核实的活动名；限定产品先单独记录，不因共现自动扩入 |
| 明星代言／合作 | 明星姓名、经核实昵称、合作活动 | 品牌＋人物相关叫法；合作产品单独提取，专属话题经核实再补入 |
| 话题挑战／互动 | 实际活动话题、关联叫法、参与规则 | 以已确认的目标话题及同活动叫法取数；用户不知道话题时先发现候选，多活动或范围不明时针对性确认 |
| 新品发布／产品推广 | 本次推广产品名称、型号、经核实简称 | 产品词为核心，有歧义时加品牌；不强制加发布/首发/开售/新品/发布会，不要求每帖带话题 |
| 促销／节日营销 | 活动专属名称、话题、促销机制 | 品牌＋专属活动名；国庆/618不单独使用，折扣/满减/积分先作分析信息 |
| 线下活动／快闪 | 主体、目标场地、城市、实际站点叫法 | 主体＋场地，或城市＋主体＋活动特征，经核实的分支用“或”补充；检查同城其他场地 |
| 公益／品牌主题 | 项目名称、具体公益行动、主题口号 | 品牌＋项目/具体行动；检查口号是否被多个项目共用，合作机构和艺术家不自动独立扩入 |
| 赛事赞助／合作等其他类型 | 赞助对象、赛事、活动专属叫法 | 按用户关注的赞助活动限定；代言人可作分析人物，不因其代言身份加入独立品牌＋人物分支 |

活动关键词用于识别本次营销活动相关传播；产品词单独供产品分析。当产品本身就是新品推广对象时，同一词可承担活动取数和产品分析两种角色；代言、公益、快闪等活动中涉及的产品不因此变成独立取数分支。

### 3.1 同时生成品牌与活动两套口径

**品牌取数关键词覆盖品牌传播，并纳入可归属于品牌的活动传播。** 每个Topic5活动复盘均须生成品牌取数关键词和活动取数关键词，分别拟定、核验品牌与活动过滤词，单独提取产品分析词；不将两套口径当作可选需求类型。

- 品牌取数式以品牌名称、经核实的品牌别名及必要的业务限定为基础，再用 `|` 纳入本次可明确归属于品牌的活动识别表达式，覆盖没有写品牌名的活动参与帖。保留活动分支原有的括号与 `+` 限定，不能把歧义活动词拆出后独立加入。
- 品牌基础词按本次业务范围核实品牌名、别名、业务、产品与系列；歧义品牌优先使用`(品牌名|核实别名)+(业务词|产品词|系列词)`，必要时补充明确企业主体、技术或品牌合作叫法，避免仅覆盖产品讨论。多业务品牌按本次业务范围选择默认过滤规则，不将某业务默认词无判断地套到整品牌。
- 依据活动介绍、品牌/合作方传播或参与规则核实归属。多品牌共享的平台主题、普通节日词或未核实的话题不直接纳入；品牌口径也不能仅用品牌名与活动词做且关系，否则会漏掉品牌其他传播。
- **并入品牌式的门槛（三项须同时满足）**：① 有明确的归属依据，说明该活动分支属于本品牌；② 不是多品牌共用的名称（如“焕新季”“国庆”，需带品牌限定才可并入，限定后的分支如 `美的+国庆焕新季` 可作为候选）；③ 该分支有实际相关样本支撑、限定合理，经5.1判为A档；有限残余噪音可记录并交执行环节，不要求该分支全量无噪音。未满足并入门槛的分支不加入品牌式；是否进入活动式，先按5.1.1独立判断，C档只保留候选，不进入任何取数式。并入的每个分支及其依据逐条写入确认单“补入品牌关键词的活动关键词”。
- 不要求所有活动词逐字并入品牌式；若原品牌表达式已经覆盖该活动分支，可避免重复。试查时核实覆盖和噪音，字面关系不能代替传播归属判断。
- 品牌过滤词根据品牌指代歧义及品牌整体分析范围拟定；活动过滤词根据本次活动边界拟定。分别试查、核验和记录，不将活动过滤词整组自动套到品牌查询。不能因为某内容不属于本次活动，就认定它不属于品牌传播。
- 原始候选按此规则自行生成，无需用户编写。已有用户确认口径发生实质变化时，另提更新建议并记录确认，不覆盖原式。

启境 × 放假计划示例：品牌取数式 `启境|把卧室搬进风景里`；活动取数式 `把卧室搬进风景里`；产品分析词 `启境GX7|GX7`。活动介绍已说明该话题与启境的关联；“放假计划”为多个品牌共享的平台活动名称，不独立加入启境品牌式。品牌式为用户确认的生成规则示例，尚未按该品牌式完成API验证，不能沿用活动查询的声量作为品牌声量。

### 4. SSJH 探索性试查与热帖扩词

在时间、平台已明确且用户任务涵盖关键词核实时，可在最终需求确认前进行有限的探索性试查。默认只取词云和按互动排序的原文热帖；继承已明确的内容范围，不自动增加平台、不默认过滤广告、不因负面情绪排除帖子。不执行完整统计管线，不创建正式报告项目。

**查询默认关闭 OCR**：每个 SSJH 请求显式设置 `extra_condition[实际source].matchFields=content,title`，覆盖 Skill 可能包含 `cover_ocr_content` 的默认值。关键词、过滤词、词云、热帖及过滤前后统计均继承同一设置；不能把“不读取返回OCR字段”当作关闭OCR检索。无法控制字段时记录依赖限制，不静默使用含OCR的查询。

读取实际帖子标题、正文及其中的话题，不只看摘要。不以OCR或ASR中的文字补充本次文本检索范围。接口仍返回OCR/ASR字段不表示它们参与了本次查询；词云生成使用哪些字段也须单独核实，不能因设置matchFields就宣称词云仅从标题/正文生成。`cloudWord` 是关键词云，不是独立话题云；词云词频不等于话题帖子数，不能据此宣称官方话题排名。

从热帖提取话题和叫法，再通过品牌/合作方内容、活动介绍、参与规则等核实本次关联。官方账号身份也需有可核实依据，不能只凭昵称相似。区分专属活动话题、常驻品牌话题、其他品牌话题、产品词和共享主题。

仅确认一个核心话题后，不停止检查同一活动的其他叫法；发现多个活动或同话题承载不同传播范围时，返回简短澄清问题，不能自行选定。统计“整个月话题传播”不自动改为其中某次抽奖、官宣或赛事活动。

### 5. 灵活组合，验证是否有必要扩词

- `+`是且关系，各词同时命中，不要求连续或固定词序；`|`是或关系；使用英文符号。同层混用必须明确括号；实际提交不支持字面特殊字符转义，不使用不支持的`$`。按5.0校验、去重、计数和规划预检批次。
- 需要多个线索共同限定时适当拆分，用 `+` 匹配不同措辞和标点。例如 `金典+爱生万物+微光向善` 能覆盖口号中插入标点的表达，但该口号是否专属仍需核实。
- 词长不是保留或舍弃的标准。具体项目名通常更准确；短词是否有必要加入，取决于实际覆盖和噪音。
- 补查与核心查询使用相同时间、平台及其他条件，按帖子ID/链接比较差异，检查实际检索范围内的正文、标题、话题是否真正属于本次活动，不能用OCR/ASR把仅图像或语音提及的内容认定为本次文本口径命中。仅不在某个Top热帖列表中，不证明关键词未命中；还要检查检索条件、返回范围或作进一步针对性核实。
- 返回少于100条也不自动等于全量；不得从样本差异计算完整召回率。检索字段可能包含正文截断之外的内容，对本地字面判断的限制要留痕。
- 发现疑似遗漏后优先补充可核实的具体叫法；没有遗漏证据，不必扩大核心范围。核心词和补查词不一定互为包含关系，例如 `金典+候鸟` 不覆盖只提防鸟撞的图片帖。
- 停止条件按5.1.4的具体核验动作与依赖限制执行。若新查询没有新增相关叫法或只增加其他活动，不反复扩大查询。

### 5.0 包含去重、表达式校验与展开组规划

#### 包含去重

- 当前按字面包含检索的口径，同一个或分组且限定关系相同，较短词已覆盖较长词时保留短词。例如`空调|中央空调`简化为`空调`；不能按相似语义删掉不包含的型号、昵称或叫法。
- 跨分支只能在逐分支证明包含后去重。`(格力|GREE)+(空调|电器)`已覆盖`格力电器`；末尾独立`|格力电器`可删除。仅有`(格力|GREE)+空调`则没有覆盖只提格力电器的企业帖，不能同样删除。不得只因电器两个字包含于格力电器，就忽略其他且条件。
- 能力自动生成口径可按上述等价关系精简并留原式、新式、删除依据；用户给定口径原样保存，按已有授权执行调整。品牌与活动词、默认过滤词的用途和已确认范围不能因去重改变。去重不能作为拓宽统计范围的理由。

#### 语法与提交限制

- `+`为且，`|`为或；同一括号层级混用必须加明确括号。`(A|B)+(C|D)`有效；`A+B|C`不直接提交，应按已确定意图写成`(A+B)|C`或`A+(B|C)`，有业务歧义时才澄清。
- 关键词、排除词分别检查展开组数：词项计1，或节点相加，且节点相乘；按语法树计数，不按可见词数或每个竖线字符切分，不先生成无界笛卡尔积。
- 正式取数关键词与排除词各最多200组，分别计数，不能合计200。统计预检每批关键词与排除词各最多50组；关联查帖增加且条件后也须重新计数。接口实际限制以对应运行时契约为准，不能因某次请求成功就忽略上限。
- 字面特殊字符转义尚不支持实际提交。含需转义的字面`+`、`|`、括号或反斜杠，保留原始词与未验证状态，不猜测转义层数、不删除字符后提交；可继续使用已有不依赖该词的合理核心式。若只有该词才能识别主体，交接口维护方核对；正常作为逻辑符号的+、|、括号不属于字面转义。

#### 统计预检拆批与返回

- 去重后先检查200组任务限制，再按统计50组规划批次，保存完整正式口径与每批实际表达式。超过200先作有依据的去重/精简；仍超限由调用方处理，不静默截断或自动创建多份任务。
- 统计包含式51—200组可按完整语义展开为有界批次（每批≤50），同一帖子可命中多个批次；批次数量不能直接相加当作精确总声量或互动量。没有实际去重或服务端联合结果时，按统计估算契约记录上界/不确定性。
- 统计排除词超过50组不能简单拆批后相加。按执行能力既有预检策略处理（如统计侧不施加排除而标注放宽估算），完整正式排除式仍保留。没有可用估算方案时记录预检缺口，不自行改变用户范围。
- 输出`expression_validation`与`precheck_plan`，包括组数、限额、括号/转义状态、去重记录、批次及估算关系；规划完成不等于API已调用。原式结果不冒充新式验证结果，不重复取数仅为证明去重形式不同。

### 5.1 采用门槛与降级

关键词和过滤词由能力判断后直接采用，内部留痕，不主动向用户逐项展示或索取确认；用户主动询问时如实展示和解释。核心关键词可采用与新增过滤词可采用分别判断，残余噪音不自动阻塞。采用状态、需求边界与API验证状态分别记录，不以有限样本宣称全量准确。

#### 5.1.1 取数关键词：核心口径可执行即可继续

| 档位 | 条件 | 处理 |
|---|---|---|
| A 样本支持后采用 | 主体和归属明确；实际相关标题、正文及其中话题支持核心式；歧义已作合理限定；没有命中明显偏离或已知核心覆盖错误。有限残余噪音不影响采用 | 写入对应取数式；记录样本范围、已知残余噪音和执行环节处理动作，不宣称全量无噪音 |
| B 核心口径采用 | 用户明确描述或可靠依据已确定主体/范围，核心限定合理；依赖、样本或核验不足，或残余噪音还需执行环节识别，但已有可用核心式 | 采用已明确的核心词继续；不增加未经核实的别名、角色或独立话题；记录验证缺口与残余噪音，不因去噪未完成暂停 |
| C 该候选暂不采用 | 该候选主体/归属无法确定，共用名称缺少必要限定，或命中明显偏离且无法合理限定 | 仅该候选不进入取数式，其他可用A/B核心式仍继续；只有没有任何可用核心式时才按原因澄清或阻塞 |

- 帖子数量不是定档标准。一条帖子配合明确用户描述或可靠活动介绍，与只有一条普通帖猜测归属不同；根据证据能否支持主体、归属和相关性判断。
- 优先处理能通过合理限定或核验过滤词解决的噪音，不为了升档堆砌固定短语。品牌歧义仍优先使用灵活的`(品牌名|核实别名)+(业务词|产品词|系列词)`。收紧会漏掉正常内容或过滤存在明显误排时，不采用该调整；保留合理核心式，把残余噪音交执行环节处理。已知核心覆盖错误须修正或补充有依据的分支，不能用“允许残余噪音”掩盖主体/范围错误。
- 试查无结果或很少：核对日期、平台、拼写和条件后，不据此否定用户明确名称，不盲目扩词。有明确主体、归属可停在B；仍不清楚则按需求澄清处理。
- 秘塔不是每次调用的必经步骤。已知信息足够且无背景疑点时可不搜索；有缺失或需核实的角色、别名、活动归属时再搜索。缺少秘塔结果本身不强制降档，SSJH不可用且本次必要核验未完成时最高B。
- 活动分支先按本节判断能否采用，再按3.1判断是否并入品牌式。未满足并入门槛不代表活动式可自动采用；C档不得进入任何取数式。

#### 5.1.2 新增过滤词：核验后采用，不设 B 档

新增过滤词采用须同时满足：①拟排除内容确实在本次分析范围外；②原检索式与候选词的关联帖子支持此判断；③已检查可能误排的范围内正常内容，未发现尚未解决的明显误排；④全局或分支作用范围与实际接口一致。满足时记A及`adopted`；尚缺核验则记C及`pending_validation`，发现误排无法解决则记C及`not_adopted`。不得因依赖缺失而保守采用新增过滤词。

“相关帖支持”对关键词是指纳入内容相关；对过滤词是指关联帖支持范围外内容的排除，不能混用判断条件。新增过滤词未通过，只是不采用该过滤候选，不把核心关键词降为C或暂停整个流程；保留已确认默认词及其他已采用过滤词。无适用规则且无新增过滤词通过核验时，过滤字段留空，不强行凑词。

#### 5.1.3 已确认规则与已给定口径单独沿用

用户明确给定的表达式，以及6.1.1的完整品牌类型默认过滤规则，在适用范围内原样沿用，不受新增词A/B/C门槛降级。`tier=null`、`decision=carried`，写明来源与适用依据，API验证状态独立记录。缺少本次样本不能撤掉默认式或改为空。用户已确认口径发生实质变更仍须取得用户同意。

#### 5.1.4 最低核验动作与停止条件

- 检查主要检索分支和表达式语法，区分品牌、活动与产品用途。
- 查看相关热帖，以及词云异常线索的关联原帖；没有异常也记录检查范围。词云不可用或字段来源不明时如实记缺口。
- 核实新增叫法的主体、活动归属、共享名称和时间关联。
- 检查新增过滤词的范围外内容证据、范围内内容误排与实际作用层级；已确认默认词沿用并记录影响。
- 已知噪音按实际情况分为已处理、过滤候选不采用、交执行环节继续识别；每项记录证据与下一步，不要求本阶段全部解决。已知核心覆盖错误优先修正，不能仅以未进入某个Top列表判断遗漏。
- 按实际执行记录剩余限制和未完成动作；B档缺口不写为已完成核验。

品牌与活动主体/范围明确、两套必填核心口径均限定合理且可执行时即返回ready，Supervisor自动进入后续交接或执行，不因残余噪音反复试查、结束对话等待用户或要求用户写词。生成阶段在可安全处理的问题已处理、其他问题已记录具体执行动作后完成；不要求全量无噪音，不计算未经验证的准确率/召回率。单个候选C不阻塞已有A/B口径。确需暂停时说明具体缺项/偏离/依赖故障、恢复动作及由谁负责，不能只说“未通过”。

残余噪音交接：记录噪音类型、实际帖子证据、未采用过滤词及误排原因、执行环节识别动作和统计限制。执行环节如取得原帖，可按既有去噪流程识别并保留处理记录；只有完成相应数据去噪与重算后才能称为清洗后统计。只有聚合结果或样本时，记录口径限制，不用样本比例直接扣减聚合声量。不能把待处理事项写成已处理，也不因交接噪音自动扩大取数/预算。

用户沟通：用户已提供完整需求时，说明需求已明确及正在继续处理；无需用户补充关键词/过滤词。默认不主动展示表达式，用户要求看输出时展示实际采用的完整词及简短限制。
