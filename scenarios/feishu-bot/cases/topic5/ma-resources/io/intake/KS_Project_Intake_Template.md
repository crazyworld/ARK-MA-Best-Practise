## 使用方式

收到初始Topic5需求即调用Skill，直接传入用户原话、会话日期/时区和已有状态，字段不齐也调用。由Skill理解、判断缺项并提出最多两个关键问题；同会话直接提问，隔离执行时Supervisor转达一次，不重复发问。用户补充后携带prior_result继续执行，已明确信息不重问，可选信息未提供按默认处理。已有需求描述不发模板。

用户调用时尚未描述需求，直接发送以下模板（一段自然语言的填空写法，不是字段表单），不做其他邀请话术。用户的回复可以是自由文本，自然语言与任何写法均进入同一流程，Supervisor 负责转换为需求确认单，不要求用户按字段名、分组格式或检索语法重写。关键词与过滤词由 Supervisor 生成并直接采用，模板不要求用户填写，用户自己提供已有确认口径时才提取。

```
请用一段话描述你的复盘需求，可以参考这个写法：

我想复盘【品牌】在【起止日期】期间，在【平台，如小红书、抖音、微博】上的【活动名称或简单描述】活动，希望了解【最关心的问题，如声量变化、口碑、哪类内容效果好】。

示例：
我想复盘美的在 2026-09-01 至 2026-09-30 期间，在小红书和抖音上的“国庆焕新季”活动，希望了解活动带来的声量变化和用户口碑。

说清楚活动描述、起止日期和平台即可；活动所属品牌能从描述识别时无需另填，不明确时再补充。检索关键词、过滤词、活动类型由我生成。如果有多个活动，请分别写明各自的起止日期。
```

## 注意事项

- **活动时间** 是用户确认的统计窗口，直接作为 SSJH start/end。实际举办期可另记用于解释预热/活动前段，不能自动覆盖用户窗口。
- **品牌取数关键词/过滤词 vs 活动取数关键词/过滤词**：两组字段分别对应品牌聚合查询（SSJH-Social-Stat）与活动原帖抓取（ssjh-social-task），须分别生成、核验和记录；品牌取数关键词覆盖品牌传播，并纳入可归属于品牌的活动传播；活动范围排除词不自动套用到品牌查询。用户可自然描述，Supervisor 整理对应关系
- **活动取数关键词/过滤词（多活动场景）**：多活动时由 Supervisor 将自然语言整理成 `[活动名称]` 分组，名称与「分析对象」字段保持一致，同时记录各活动执行周期并写入需求确认单，Producer Step 2.5按组逐活动调用ssjh-social-task抓取原帖；Step 7.3的词云查询仅作辅助，不替代原帖抓取
- **取数关键词 vs 产品关键词**：前者用于拉取数据，后者用于标注阶段识别产品维度，两者可以重叠但用途不同
- 用户不需要自行拟定关键词或过滤词。产品词与活动类型由能力根据证据整理；过滤词无噪音依据留空，产品类别/目标未明确由 Planner 推断，内容范围未明确默认“全部”。
- 收到用户自然语言描述或模板内容后，将信息及分析重点同步写入需求确认单（`marketing-activity-review_template.md`）
- 本文件与 `KS_Report_Required_Fields_List.md` 覆盖不同维度、均需读取：本文件是自然语言解析的字段参考及备选收集模板，取数操作类字段（目标平台/取数关键词/过滤词）以本文件为准；业务属性类字段（产品类别/活动类型/活动核心目标）的"必填/可选"判定及推断策略以 `KS_Report_Required_Fields_List.md` 为准。新增或修改字段时两份文件需同步检查，避免某个字段只在一份文件里出现

## 自然语言解析规则

- 从活动描述识别品牌、活动主体与边界，同时生成两套关键词；品牌名、活动名不自动等同于检索式。加载项目关键词生成Skill（规则基线v1.11），按取数词A/B/C与新增过滤词独立门槛直接采用，内部保存，不要求用户审词；已有用户表达式原样保留。
- 明确完整日期可标准化；缺年份、相对日期或“全平台”等歧义项须确认。交付截止与活动周期分别记录。
- 每个活动的时间、关键词和过滤词独立记录。未指定内容范围默认“全部”，未提供产品类别/目标交给 Planner；活动类型先由能力核实，标明推断依据与状态，不冒充用户明确事实。
- 分析重点、用户关注问题、交付截止和限制条件写入需求确认单；在“五、需求理解与来源记录”保留原文、依据、默认项和更正记录。
- 已知字段不重复收集。品牌、活动描述、日期、平台须明确，两套关键词须均可执行；缺失、需求冲突未解决或能力blocked时保持草稿。ready后HC-T5-0仅展示业务解析结果，随后进入下一阶段，无需用户审词或回复。

## 关键词能力调用

Supervisor加载项目内 `../../Skills/campaign-keyword-generation/SKILL.md`，按其 `references/contract.md` 调用能力 `campaign_keyword_generation`。活动类型、检索逻辑、扩词/补查、过滤规则和证据约定集中维护在Skill及其references；旧KS仅转接。初始需求即调用，缺项由Skill判断并提问，增量补充携带prior_result；完整结果及调用元数据写入需求目录的关键词生成/keyword_generation_result.json，确认单按原四个字段消费。日期和平台明确后可作有限探索性词云/热帖试查，记录证据；能力本身不创建项目或正式取数，项目目录与正式执行按Phase1流程处理。

SSJH探索查询显式设置`matchFields=content,title`，不检索OCR；返回OCR字段不表示开启检索。用户已确认的品类过滤词按确认范围保留，不能因未完成API验证而静默清空。

必须生成品牌与活动两套取数关键词，分别判断两套过滤词；不得以“仅活动”为由将品牌字段记为不适用。ready要求品牌与各活动两套必填取数口径均已有可执行A/B核心式或用户给定式；任一套尚不可执行时，按缺项/边界歧义返回need_clarification，按无可用核心式或必需依赖故障返回blocked。新增过滤词未通过或残余噪音不单独阻塞。 status使用ready/need_clarification/blocked，依赖状态单独记录；B档可交接但不冒充完成验证。已确认品牌类型默认式按适用范围完整沿用。自动修改表达不改变需求范围；改变对象、活动边界或排除品类须需求澄清。
