# 脚本验证规则

> **版本**: v0.1
> **更新日期**: 2026-03-27

---

## 一、逻辑正确规则

| 规则ID | 规则描述 | 严重度 |
|--------|----------|--------|
| S-01 | 筛选条件必须与需求完全一致 | 高 |
| S-02 | 聚合维度必须与需求一致 | 高 |
| S-03 | 时间范围必须与需求一致 | 高 |
| S-04 | 排序/分组逻辑必须正确 | 中 |

**输出模板**：
```
L{行号}: 筛选条件缺"{条件}"
L{行号}: 聚合维度应为"{正确}"非"{错误}"
L{行号}: 时间范围与需求不符({实际} vs {需求})
```

---

## 二、计算准确规则

| 规则ID | 规则描述 | 严重度 |
|--------|----------|--------|
| S-05 | 增长率公式: (新-旧)/旧 × 100% | 高 |
| S-06 | 占比公式: 部分/总量 × 100% | 高 |
| S-07 | 均值公式: 总量/数量 | 中 |
| S-08 | 除法必须处理除零情况 | 高 |
| S-09 | 浮点计算需控制精度 | 中 |
| S-10 | 单位必须统一（元/分、亿/万） | 高 |

**常见公式错误**：
| 错误 | 正确 |
|------|------|
| (新-旧)/新 | (新-旧)/旧 |
| 部分/部分 | 部分/总量 |
| SUM/COUNT(*) | SUM/COUNT(非空) |

**输出模板**：
```
L{行号}: {公式名}公式错误(应为{正确公式})
L{行号}: 除法未处理除零
L{行号}: 单位不一致({单位1}/{单位2})
```

## 三、数据完整规则

| 规则ID | 规则描述 | 严重度 |
|--------|----------|--------|
| S-11 | JOIN类型必须符合业务需求 | 高 |
| S-12 | NULL值处理策略必须明确 | 中 |
| S-13 | 去重逻辑必须正确 | 中 |
| S-14 | 数据过滤必须有业务依据 | 中 |

**JOIN类型选择**：
| 场景 | 推荐JOIN |
|------|----------|
| 必须匹配 | INNER JOIN |
| 保留主表 | LEFT JOIN |
| 全量合并 | FULL OUTER JOIN |

**输出模板**：
```
L{行号}: {JOIN类型}应为{正确类型}，可能导致数据{丢失/重复}
L{行号}: NULL值处理策略不明确
L{行号}: 去重逻辑可能导致数据丢失
```

## 四、抽检规则

| 规则ID | 规则描述 | 严重度 |
|--------|----------|--------|
| S-15 | 必须进行结果抽检 | 高 |
| S-16 | 抽检差异≤1%为通过 | - |
| S-17 | 抽检差异1-5%为警告 | 中 |
| S-18 | 抽检差异>5%为失败 | 高 |
| S-19 | 总量校验必须通过 | 高 |
| S-20 | 边界值必须验证 | 中 |

**抽检数量**：
| 数据量 | 抽检数 |
|--------|--------|
| <100 | 全量 |
| 100-1K | 10 |
| 1K-10K | 20 |
| >10K | 30+边界 |

**输出模板**：
```
抽检: {样本ID}, {字段}={脚本值}, 验证值={验证值}, 差异{差异}%
抽检: 总量校验{通过/失败}(汇总={值1}, 明细={值2})
```

## 五、异常处理规则

| 规则ID | 规则描述 | 严重度 |
|--------|----------|--------|
| S-21 | NULL值必须显式处理 | 中 |
| S-22 | 零值除法必须保护 | 高 |
| S-23 | 负值必须检查合理性 | 中 |
| S-24 | 异常值必须过滤或标记 | 中 |

**异常值判定**：
| 字段类型 | 异常条件 |
|----------|----------|
| 金额 | <0 或 >合理上限 |
| 数量 | <0 或 >合理上限 |
| 占比 | <0% 或 >100% |
| 增长率 | <-100% 或 >1000% |

**输出模板**：
```
L{行号}: 未处理NULL值
L{行号}: 除数可能为0，缺保护
L{行号}: {字段}存在负值({值})
L{行号}: {字段}存在异常值({值})
```
