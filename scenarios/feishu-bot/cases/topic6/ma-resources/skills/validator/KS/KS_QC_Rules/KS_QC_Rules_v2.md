# 质检规则库 v2

> 本文件是 Step2（Supervisor）质检的唯一规则来源。质检时必须逐项执行，不得跳过、不得凭记忆补充规则。全部规则判断完成后再输出/处理问题；
> 
> **执行顺序**：需求一致性（P0）→ 源头一致性（P0）→ 数据准确性 → 专业内容 → 逻辑错误 → 结构问题 → 基础错误 → 可视化 → 合规风险
> 
> **处理方式说明**：
> - Planner改写 = 将问题反馈给 Planner，由 Planner 修改后重新提交
> - 人工处理 = 暂停流程，等待人工决策
> 
> **问题分级**：最终处理策略由用户确定，本环节仅作标注分类
> - P0：必须修复
> - P1：应当修复
> - P2：建议优化
>
> **版本**：v2（2026-03-05）
> **变更说明**：数据准确性校验中 Variable ID 相关规则增加「条件触发」机制——仅当方案中实际出现了具体字段编号时才执行编号校验，描述性方案（无编号）不主动要求补充编号

---

## 需求一致性校验（P0 — 最高优先级，优先于所有其他质检项）

> **豁免规则**：Planner 因数据源限制或业务合理性对需求做出调整，且同时满足以下全部条件时，不视为 P0 违规：
> 1. 调整有明确理由（元数据不支持 / 样本量不足 / 业务合理性）
> 2. 方案中已显式标注偏离点和调整理由
> 3. 调整方向未改变需求的业务目标
> 
> 满足条件 → 降为 P1（建议优化标注）；未满足 → 仍为 P0。

| 通用 | ALL | 需求一致性 | 人群数量变更 | 方案中人群数量与需求确认单不一致（如8组→6组） | 恢复需求确认单定义的人群数量；或生成需求偏差报告待用户确认 | Planner改写 | P0 |
| 通用 | ALL | 需求一致性 | 圈选条件变更 | 人群圈选条件与需求确认单不一致且未标记 | 恢复需求确认单的圈选条件；或显式标注差异并说明理由 | Planner改写 | P0 |

## 源头一致性校验（P0 — 与需求一致性同优先级）

> **说明**：本环节对比**需求确认单 vs 原始用户输入**，用于捕获 Step 1 引入的偏差。
> 需求确认单本身可能在 Step 1 阶段就引入了错误（如遗漏人群、缩小城市范围、条件性质变更），
> 仅对比"方案 vs 需求确认单"无法发现这类错误。

## 数据准确性问题

> **⚠️ Variable ID 校验触发条件（v2 新增）**：
> 
> 本节中与 Variable ID（字段编号）相关的校验规则，采用**条件触发**机制：
> 
> - **方案中包含具体 Variable ID**（如 `34.04.01`、`Q12_A3` 等编号格式）→ **触发**编号相关校验（编号存在性、编号重复、编号与路径匹配等）
> - **方案为描述性表达**（如"消费偏好-品牌偏好"、"触媒习惯"等文字描述，未附带编号）→ **跳过**编号相关校验，**不主动要求 Planner 补充编号**
> 
> 判断标准：扫描方案全文，是否存在符合编号格式的 Variable ID 引用。存在 → 全量校验；不存在 → 仅校验维度越界、标准指标缺失、真实性等与编号无关的规则。
>
> **理由**：描述性方案阶段的核心目标是需求对齐和维度覆盖，编号精确化属于后续细化阶段的工作。
