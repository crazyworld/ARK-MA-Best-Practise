# 商业问题审计能力

> **层级**: L2 能力层
> **加载**: 审计商业问题清单时加载
> **行数上限**: ~120行

---

## 一、审计目标

检查商业问题清单质量：切中要害、覆盖关键、优先级合理。

---

## 二、检查维度

| 维度 | 检查点 | 典型问题 |
|------|--------|----------|
| **切题度** | 问题是否切中行业/品牌痛点 | 泛泛而谈、隔靴搔痒 |
| **覆盖度** | 是否覆盖关键商业维度 | 遗漏核心维度 |
| **优先级** | P0/P1/P2判定是否合理 | 优先级错位 |
| **独立性** | 问题间是否有重复/包含 | 重复、嵌套 |
| **可操作性** | 问题是否可指导决策 | 过于抽象、无法行动 |

---

## 三、检查规则

### 3.1 切题度

**规则**：问题必须是行业主要玩家的共性痛点，非个例

**问题模式**：
- 问题过于宽泛，任何行业都适用
- 问题仅针对个别品牌，非行业共性
- 问题与研究主题关联度低

**输出示例**：
```
Q3: "如何提升用户体验" 过于宽泛
Q5: 仅适用于单一品牌，非行业问题
```

### 3.2 覆盖度

**规则**：必须覆盖核心商业维度

**必检维度**（按行业调整）：
- 商业模式/盈利模式
- 市场格局/竞争态势
- 用户增长/留存
- 产品/技术壁垒
- 风险/合规

**输出示例**：
```
缺失: 商业模式维度
缺失: 合规风险维度
```

### 3.3 优先级

**规则**：P0必须是当前最紧迫的战略问题

**判定标准**：
- P0：影响生存/核心增长，需立即决策
- P1：影响中期竞争力，需规划
- P2：值得关注，可后续跟进

**输出示例**：
```
Q2: 应为P0，影响核心营收
Q4: 应降为P2，非紧迫问题
```

### 3.4 独立性

**规则**：问题间不重复、不嵌套

**问题模式**：
- 两个问题实质相同，表述不同
- A问题包含B问题
- 问题间有强依赖

**输出示例**：
```
Q2+Q5: 实质重复
Q3包含Q7: 合并处理
```

### 3.5 可操作性

**规则**：问题应可指导具体决策或行动

**问题模式**：
- 问题过于抽象，无法落地
- 问题是现象描述，非决策问题
- 缺乏明确的决策主体

**输出示例**：
```
Q4: 现象描述，非决策问题
Q6: 过于抽象，无法行动
```

---

## 四、输出格式

```markdown
## 商业问题审计 - {清单名}

| 问题 | 问题描述 | 严重度 |
|------|----------|--------|
| Q3 | 过于宽泛 | 中 |
| Q2+Q5 | 实质重复 | 中 |
| - | 缺商业模式维度 | 高 |
```

---

## 五、严重度判定

| 级别 | 条件 |
|------|------|
| **高** | 缺失核心维度、P0判定错误、问题偏离主题 |
| **中** | 优先级微调、轻度重复、表述待优化 |
| **低** | 措辞建议、格式问题 |

---

## 六、案例库

### 6.1 问题过于宽泛

**原问题**: "如何提升Roguelike游戏的用户体验？"

**输出**: `Q3: 过于宽泛，任何游戏都适用`

### 6.2 缺失核心维度

**清单**: 5个问题均围绕用户增长，无商业模式问题

**输出**: `缺失: 商业模式/盈利模式维度`

### 6.3 优先级错位

**原问题**: "P2: 头部产品的付费率下滑趋势"

**输出**: `Q4: 应为P0，直接影响营收`

### 6.4 实质重复

**Q2**: "如何提升用户付费转化？"
**Q5**: "如何优化付费漏斗？"

**输出**: `Q2+Q5: 实质重复，合并`
