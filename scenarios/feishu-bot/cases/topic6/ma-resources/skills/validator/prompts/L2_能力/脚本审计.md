# 脚本审计能力

> **层级**: L2 能力层
> **加载**: 审计数据处理脚本/计算结果时加载
> **行数上限**: ~150行

---

## 一、审计目标

检查数据处理脚本质量：逻辑正确、计算准确、结果可验证。

---

## 二、检查维度

| 维度 | 检查点 | 典型问题 |
|------|--------|----------|
| **逻辑正确** | 处理逻辑是否符合需求 | 逻辑错误、边界遗漏 |
| **计算准确** | 公式/算法是否正确 | 公式错误、精度丢失 |
| **数据完整** | 输入输出是否完整 | 数据丢失、过滤错误 |
| **结果抽检** | 抽样验证计算结果 | 结果异常、与预期不符 |
| **异常处理** | 边界/异常是否处理 | 空值、异常值未处理 |

---

## 三、检查规则

### 3.1 逻辑正确

**规则**：处理逻辑必须与需求一致

**问题模式**：
- 筛选条件与需求不符
- 聚合维度错误
- 排序/分组逻辑错误
- 时间范围不匹配

**输出示例**：
```
L45: 筛选条件缺"状态=已完成"
L67: 聚合维度应为"品牌"非"SKU"
L89: 时间范围与需求不符(7天 vs 30天)
```

### 3.2 计算准确

**规则**：公式/算法必须正确

**问题模式**：
- 公式错误（如增长率公式）
- 除法未处理除零
- 精度丢失（浮点数问题）
- 单位换算错误

**输出示例**：
```
L56: 增长率公式错误(应为(新-旧)/旧)
L78: 除法未处理除零情况
L90: 金额单位未统一(分/元混用)
```

### 3.3 数据完整

**规则**：输入输出数据必须完整

**问题模式**：
- 数据被意外过滤
- JOIN导致数据丢失
- 空值被错误处理
- 重复数据未去重

**输出示例**：
```
L34: LEFT JOIN应为INNER JOIN，数据丢失
L56: 空值被过滤，影响{N}条记录
L78: 存在重复数据未去重
```

### 3.4 结果抽检

**规则**：必须抽样验证计算结果

**抽检方法**：
| 方法 | 适用场景 | 操作 |
|------|----------|------|
| 手工复算 | 简单计算 | 抽3-5条手工验证 |
| 边界验证 | 有范围限制 | 检查最大/最小/边界值 |
| 总量校验 | 汇总计算 | 验证合计数是否一致 |
| 趋势校验 | 时序数据 | 检查趋势是否合理 |

**输出示例**：
```
抽检: ID=12345, 计算值=150, 手工复算=145, 差异3.4%
抽检: 总量校验失败(汇总=1000万, 明细合计=980万)
抽检: 最大值异常(9999999, 疑似脏数据)
```

### 3.5 异常处理

**规则**：必须处理边界和异常情况

**必检项**：
- 空值(NULL/None)处理
- 零值处理（除法场景）
- 负值处理（不应为负的字段）
- 异常值处理（超出合理范围）

**输出示例**：
```
L45: 未处理NULL值，可能导致计算错误
L67: 除数可能为0，缺保护逻辑
L89: 负值未过滤(销量=-5)
```

---

## 四、抽检规范

### 4.1 抽检比例

| 数据量 | 抽检数量 |
|--------|----------|
| <100条 | 全量验证 |
| 100-1000条 | 10条 |
| 1000-10000条 | 20条 |
| >10000条 | 30条 + 边界值 |

### 4.2 抽检策略

```
1. 随机抽样: 随机选取N条
2. 分层抽样: 按关键维度分层抽取
3. 边界抽样: 最大/最小/首尾记录
4. 异常抽样: 可疑数据优先验证
```

### 4.3 抽检记录

```markdown
## 抽检记录 - {脚本名}

| 样本ID | 字段 | 脚本值 | 验证值 | 结果 |
|--------|------|--------|--------|------|
| 12345 | GMV | 150.00 | 150.00 | ✅ |
| 67890 | 增长率 | 15% | 12% | ❌差异3% |
```

---

## 五、输出格式

```markdown
## 脚本审计 - {脚本名}

### 代码问题

| 位置 | 问题 | 严重度 |
|------|------|--------|
| L45 | 筛选条件缺失 | 高 |
| L67 | 除零未处理 | 高 |

### 抽检结果

| 样本 | 结果 | 备注 |
|------|------|------|
| 随机5条 | ✅通过 | 差异<1% |
| 边界值 | ⚠️异常 | 最大值疑似脏数据 |
| 总量校验 | ❌失败 | 差异2% |
```

---

## 六、严重度判定

| 级别 | 条件 |
|------|------|
| **高** | 公式错误、逻辑错误、抽检差异>5% |
| **中** | 异常未处理、抽检差异1-5%、边界问题 |
| **低** | 代码规范、抽检差异<1% |

## 七、案例库

### 7.1 公式错误

**代码**: `growth_rate = (new - old) / new * 100`

**输出**: `L56: 增长率公式错误(除数应为old非new)`

### 7.2 数据丢失

**代码**: `SELECT * FROM orders JOIN products ON ...`

**输出**: `L34: INNER JOIN导致无商品订单丢失，建议LEFT JOIN`

### 7.3 抽检失败

**场景**: GMV汇总计算

**输出**:
```
抽检: 总量校验失败
- 报表GMV: 1000万
- 明细合计: 980万
- 差异: 2%(20万)
```
