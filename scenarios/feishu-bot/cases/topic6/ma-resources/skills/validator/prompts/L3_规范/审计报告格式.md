# 审计报告格式规范

> **层级**: L3 规范层
> **加载**: 输出审计报告时加载
> **行数上限**: ~80行

---

## 一、格式原则

```
极简 · 定位精准 · 不辅导
```

---

## 二、标准报告格式（模式B）

```markdown
## 审计 - {文件名}

| 位置 | 问题 | 严重度 |
|------|------|--------|
| L{行号} | {问题描述} | 高/中/低 |
```

---

## 三、位置标记规范

| 场景 | 格式 | 示例 |
|------|------|------|
| 单行问题 | `L{行号}` | `L156` |
| 多行关联 | `L{行号}+L{行号}` | `L45+L230` |
| 连续区间 | `L{起}-L{止}` | `L100-L120` |
| 推理链条 | `L{起}→L{止}` | `L156→L162` |
| 整体缺失 | `-` | `-` |
| 特定问题 | `Q{编号}` | `Q3` |

---

## 四、问题描述规范

**要求**：一句话，≤15字，直指问题

**格式模板**：
- 数据类：`{指标}与L{行号}矛盾`
- 逻辑类：`{结论}无支撑`
- 格式类：`{问题类型}`
- 缺失类：`缺{维度}`

**正例**：
```
增长率与L234矛盾
"持续增长"无支撑
半角逗号混入中文
缺商业模式维度
```

**反例**：
```
❌ 这里的增长率数据与前文第234行提到的数据存在不一致的情况，建议核实
❌ 建议将此处的结论补充相应的数据支撑
```

---

## 五、严重度标记

| 标记 | 含义 |
|------|------|
| **高** | 阻断交付，必须修正 |
| **中** | 建议修正 |
| **低** | 可选修正 |

---

## 六、意图审计格式

```markdown
## 意图审计 - {项目ID}

| 检查项 | 状态 |
|--------|------|
| 需求完整性 | ✅/⚠️/❌ |
| 理解准确性 | ✅/⚠️/❌ |
| 假设显性化 | ✅/⚠️/❌ |
| 拆解覆盖度 | ✅/⚠️/❌ |
| 遗漏检测 | ✅/⚠️/❌ |

**问题**: {一句话，多项用分号分隔}
**结论**: ✅通过 / ⚠️需确认 / ❌阻断
```

---

## 七、阻断报告格式

```markdown
## 阻断 - {文件名}

**原因**: {一句话}
**处理**: 人工介入 / Supervisor决策 / 重新研究
```

---

## 八、无问题时

```markdown
## 审计 - {文件名}

✅ 无问题
```
