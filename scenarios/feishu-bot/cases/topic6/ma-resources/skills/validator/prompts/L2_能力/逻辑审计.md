# 逻辑审计能力

> **层级**: L2 能力层
> **加载**: 审计研究报告/分析文档时加载
> **行数上限**: ~150行

---

## 一、审计目标

检查输出内容的逻辑质量：结论有据、推理连贯、因果成立。

---

## 二、检查维度

| 维度 | 检查点 | 典型问题 |
|------|--------|----------|
| **结论支撑** | 每个结论是否有数据/论据支撑 | 凭空结论、数据不足 |
| **推理连贯** | 论证链条是否完整 | A→C缺B、逻辑跳跃 |
| **因果关系** | 因果判断是否成立 | 相关当因果、倒果为因 |
| **一致性** | 前后观点是否矛盾 | 自相矛盾、数据打架 |
| **边界合理** | 泛化程度是否恰当 | 个例推全局、过度外推 |

---

## 三、检查规则

### 3.1 结论支撑

**规则**：每个结论必须有≥1个明确支撑

**问题模式**：
- 结论无任何数据引用
- 支撑数据与结论不相关
- 支撑力度不足以得出结论

**输出示例**：
```
L245: "市场将持续增长" 无支撑
L302: 结论与L298数据不匹配
```

### 3.2 推理连贯

**规则**：论证链条A→B→C必须完整

**问题模式**：
- 中间步骤缺失
- 隐含假设未说明
- 跳跃过大难以跟随

**输出示例**：
```
L156→L162: 推理跳跃，缺中间论证
L200: 隐含"用户偏好不变"假设未说明
```

### 3.3 因果关系

**规则**：因果判断需有依据，相关性≠因果性

**问题模式**：
- 仅凭相关性推因果
- 时序关系当因果
- 倒果为因

**输出示例**：
```
L89: "A导致B" 仅有相关性，无因果证据
L134: 因果方向存疑
```

### 3.4 一致性

**规则**：同一文档内观点/数据不得矛盾

**问题模式**：
- 前后结论相反
- 同一指标数值不一致
- 立场漂移

**输出示例**：
```
L45+L230: 结论矛盾
L112与L340: 增长率不一致(15% vs 12%)
```

### 3.5 边界合理

**规则**：泛化需有足够样本，外推需说明条件

**问题模式**：
- 单一案例推全行业
- 短期趋势推长期
- 局部现象推整体

**输出示例**：
```
L267: 仅1案例，不足以推"行业普遍"
L301: 3个月数据推5年趋势，外推过度
```

---

## 四、输出格式

```markdown
## 逻辑审计 - {文件名}

| 位置 | 问题 | 严重度 |
|------|------|--------|
| L245 | "持续增长"无支撑 | 高 |
| L45+L230 | 结论矛盾 | 高 |
| L156→L162 | 推理跳跃 | 中 |
```

---

## 五、严重度判定

| 级别 | 条件 |
|------|------|
| **高** | 影响核心结论、结论与数据矛盾、自相矛盾 |
| **中** | 推理有跳跃但可补、边界判断欠妥 |
| **低** | 表述不够严谨但不影响结论 |

## 六、案例库

### 6.1 结论无支撑

**原文**: "Roguelike品类将在未来3年保持30%以上增长"（无任何数据引用）

**输出**: `L245: "30%增长"无数据支撑`

### 6.2 推理跳跃

**原文**: "用户平均时长下降 → 因此需要加入社交功能"

**输出**: `L156→L162: 时长下降→社交功能，缺中间论证`

### 6.3 因果混淆

**原文**: "头部产品都有抽卡系统，说明抽卡是成功关键"

**输出**: `L89: 相关性≠因果，幸存者偏差`

### 6.4 自相矛盾

**原文**:
- L45: "市场已趋饱和"
- L230: "仍有大量增长空间"

**输出**: `L45+L230: 结论矛盾`
