# 变更记录

## 2.1.0 — 2026-09-21

依据是同一批 121 个块的四方对照（微博，1811 条）：固定分块层、只换判定层，
所以差异能干净归因。

### 空词命中改成「先重命名一次，仍不合格才拆」

原先直接拆成单条，理由是「名字必须靠空词才能覆盖成员，说明这批成员不该在一起」。
**该推理只在空词承重时成立**，而实测触发的绝大多数是装饰性后缀：

| 被毁掉的聚类 | 去掉空词后 |
|---|---|
| `LPL决赛AL夺冠及相关话题` 25 条 | `LPL决赛AL夺冠` 完全具体 |
| `苹果折叠屏iPhone Duo发布及相关讨论` 27 条 | `苹果折叠屏iPhone Duo发布` |
| `电视剧《刺棠》开机及相关动态` 9 条 | `电视剧《刺棠》开机` |

拿 27 个真实案例回归：**24 个重命名后合格，3 个仍被拆**。仍被拆的那 3 个恰好是承重的
（`杨洋近期动态引发关注`、`OpenAI近期动态` 剥完只剩主体名），**拆分的保护作用不变**。

| 指标 | 改前 | 改后 |
|---|---|---|
| `SPLIT_FROM_EMPTY_WORD` | 93 条 | **10 条** |
| 多成员事件 | 216 | **240** |
| 单成员率 | 73.2% | **67.9%** |
| 带二级角度的多成员事件 | 108 | **123** |

重命名过的事件标 `RENAMED_FROM_EMPTY_WORD`，自动进 `human_review.csv`。
重命名的花费单独报一行 `[07_rename]`——归档走缓存时主 relay 是 0 次调用，
混进去就看不见了。

### x3 进入单平台执行序列

**一件事的记录数超过 cap 时必然落在两个块里，块内看不到彼此。** 实测《早春晴朗》65 条
落进 2 个都满了 60 的块，产出 10 个事件、最大那个只覆盖 63%。

**分块层修不了，六种改法都试过（纯离线测量，零模型调用）：**

| 改法 | 共块率均值 | 早春晴朗 |
|---|---|---|
| 现状（embedding 分数排序 + cap 60） | 91% | 65% |
| 排序键换字符 3-gram | 90% | 54% |
| 排序键换分词 + IDF | 75% | 52% |
| 三信号加权 | 92% | 52% |
| 互为 Top-K 剪边 | 85% | 35% |
| cap 提到 80 | 93% | 65% |
| cap 提到 150 | 94% | 71% |

两条反直觉结论：**分词+IDF 两两区分度最高（6.7 倍 vs 向量化 1.1 倍）却分块最差**，
IDF 会因稀有词巧合烧掉 cap 名额；**剪边更差**，剪掉了维系整组的传递桥。提 cap 只让无关
记录进来（cap80 时新进的是肖战、王一博、易烊千玺），一条该进的也没拉回。

**接 x3 后早春晴朗 63% → 82%、探针碎片数 24 → 22，微博一周 $0.62。**
四个早春晴朗事件锚点都是「早春晴朗」，走 x3 的「归一后锚点相同」通道直接命中。
x3 不是只会合：实测微博单平台 737 → 770 个事件（改名 50、拆出 64、四个事件并成一个）。

实验脚本 `skill-patch-验证/exp_block_order.py`。

### 这一轮测出的准确度基线

首次用探针法测出归类准确度（7 个「本周只发生一次」的事件，理想值 7 个事件）：

| 版本 | 碎片数 | 最大簇覆盖均值 |

## 2.0.0 — 2026-09-18

**1.x = 本次之前的未编号状态**，此前没有版本号，这是第一次编号。定为 2.0.0 是因为
有一处破坏性改动（向量化维度变了，旧缓存全部失效）。

依据是 2026-09-07~13 四平台全量实跑（原始 3762 条 → 2805 条进流水线 → 1544 个事件），
以及针对每处改动的对照实验。所有数字都是实测，不是估算。

### 破坏性

- **向量化默认模型 `text-embedding-3-small` → `Doubao-embedding`**。旧模型要出海，
  实测 1.01~2.53 条/秒；新模型 50.8 条/秒，1816 条从 20~30 分钟降到 15.8 秒。
  召回质量双平台复验持平略优（微博 68.4%→69.8%、知乎 93.4%→93.9%，且基准偏向旧模型）。
  **维度 2560 与 1536 不通用，已有 `embeddings_cache.json` 不再命中，需重算。**

### 修复

- **顶到分块上限的块会随机失败**，此前会让整个阶段报错、需要人工跑 x1 再重跑。
  现在 ⑦ 内部分流：空返回走长退避重试（5 次 / 30 秒窗口，旧版 3 次 / 3 秒），
  截断先原样重试一次、仍截断才在块内对半拆（`block_id` 不变，断点键不受影响）。
  实测 121 个块只剩 1 个需要重跑一次，且重跑时其余 120 个全走缓存。
  **推翻了旧结论「截断重试无用」**——输出长度是随机的，同块重跑能从 16000 token
  掉到 11K。
- **向量化超时 120 秒会误杀正常的慢请求**。对照实验：955 条真实标题，
  timeout=120 在 1232 秒时中断（只取到 832 条），timeout=600 完整跑完。
- **微博清洗规则会插入顿号**，误改率 69%（`库克 华为` → `库克、华为`，实际是
  「库克评价华为」）。根因是规则原文写着「判不准就用顿号」。已把默认值反过来，
  并给本地校验加 `NEW_SEPARATOR` 拦截——顿号不是汉字、躲过了 `NEW_CHAR`，
  但加顿号是在断言一层原文没有的并列关系。
- **事件命名规则是单向的**，只防「太空」不防「太细」，结果模型拿单条剧情细节当
  53 条记录的名字（`栾念为了见尚之桃飞西北20次`）——它满足了原规则的每一条。
  改成双向约束后同一个块重跑，命名为 `剧集《早春晴朗》播出及口碑讨论`，
  并顺带分出了被误并的 5 条（`井柏然刘雯恋情及婚讯曝光`）。
- **凭据只认 `ANTHROPIC_API_KEY`**，而 Claude Code 环境通常只导出
  `ANTHROPIC_AUTH_TOKEN`，导致每条命令都要手动加前缀。现在两个都认。
- **`references/pipeline.md` 与代码相反**：它写「截断不要重试」，流程图把 x1 画成
  常规路径。已同步。

### 已知遗留

- 空返回类失败**压不到零**，只能压到「重跑一次就好」。根因是「长生成 × 并发」：

  服务端机制看不到，客户端只有重试和缩短单次生成两个手段。
