# 未决容错与原热点保留

依据用户2026-10-14确认：完整流程后无法识别就保留原热点；C2不以100%识别或100%合并为交付要求。

## 执行位置与范围

统一入口在归档、成员筛查、合并与拆分复核成功之后，历史关联和正式导出之前执行 retain_original 阶段。按需补证仍有预算和停止条件，不以无限补证追求消除所有未决。未调用补证时，不声称“补证后仍未解决”。

当前判据为事件性仍是 UNCERTAIN 或 needs_evidence=true。x3只提出组级合并/拆分，不是逐条解除未决的证据；不能用一次KEEP或高归属分数覆盖已有未决，尤其不能覆盖review_holds。若后续有充分证据，可在新修订运行前置重判、解除未决后正常合并。

含未决记录的合并组保守拆回各原始热点，原已确定的关联成员也单列为“GROUP_DEPENDS_ON_UNRESOLVED_MEMBER”。不把原组生成的名字、描述和事实转嫁给剩余成员；不受影响的组保持不变。这会增加漏合，属于本版明确接受的代价，需从original_retained.json中分别统计未决数与连带拆分数。

## 输出与验收

- 保留源行顺序、原始标题、原始热度与已有源列；七列接口不变。
- 每条保留项有独立事件ID、一级事件名等于原标题、成员数1、状态“独立热点”、空角度/置信度，说明为“归档复核后保留原热点，未确认合并关系”及原因。
- 不带未经确认的事件描述、Identity Core、key_facts、关系；不将其确认成新政策、商业合作或当前发生的历史事件。
- 快照有ORIGINAL_RETAINED标记，锚点向量为空；新跨窗口匹配排除这些未确认身份，历史快照仍保留。
- original_retained.json为非阻断性处置清单；c2_quality.json同时报告业务处置、技术覆盖和未测量的语义质量。ACCEPTED_WITH_ORIGINALS不等于准确率100%。
- 非事件排除审核仍须检查误排；最终名称审核不因仅有这些保留项而停等。混合批次中的其他实际错误仍需处理。

热度或标题长度不是容错开关。重点热点、影响报告主要结论的内容可以优先补证，但未验证前不能断言长尾热点对报告没有影响，也不跨平台加总热度。

## 不属于此容错的情况

漏返、连接失败、技术降级、重复归属、未知ID、源行丢失仍是执行或结构问题，不能改名为语义未决后放行。已发现的事实抽取错误需要修正、撤回错误字段，或经明确审核改作原热点保留；当前自动阶段不会自行发现所有事实错误。

out中的07/x2/x3文件是历史阶段诊断材料；最终业务归属以record_to_event.csv、event_registry.csv、热点明细_含事件归属.csv和registry_snapshot.jsonl为准。original_retained.json记录后续撤回的组与关系，避免把中间归并当成最终结果。
