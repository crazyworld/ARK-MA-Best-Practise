# BlueFocus 社媒热点网页报告规范

本目录是已定稿的参考站点。后续报告必须在替换内容时保留这套结构、品牌视觉、交互和响应式逻辑。

## 生成入口

```bash
node build-report.mjs /absolute/path/report.source.json /absolute/path/index.html
```

省略参数时，优先读取工程外层的 W32 源数据；在独立复制的模板中则使用 `source.example.json`。输入必须是 UTF-8 JSON 块数组，参考 `source.example.json` 中的 `className`、`text`、`tables`、`links` 和 `images` 字段。

## 内容原则

- 用户提供的文案和数据是唯一事实源；不增删、改写、翻译或补造内容。飞书导出若将 `•` 单独作为普通段落前缀，视为结构标记而非正文，不得单独渲染；真实列表项必须保留。
- 原文链接必须保留，在新窗口打开。同时识别 `话题（平台）` 与 `话题 · 平台 · 热度值` 格式。营销观察若含 `原始热点：` 与单独的 `链接：URL`，应把“原始热点”内容本身渲染为蓝色链接，并隐藏独立 URL 行。
- 缺失的日期、平台、热度值、链接或图片不得猜测；需要时向用户询问。
- 周刊/月刊只按页头「数据周期」的周期标签判定（`YYYY-Www` → 周刊；`YYYY年M月` 等 → 月刊），分别使用 `title-weekly.png` 或 `title-monthly.png`；正文中出现的月份不影响判定。
- 复制模板前必须运行 Skill 根目录的 `scripts/validate-template-assets.mjs`，禁止在 PNG、JPEG 或 TTF 素材无效时继续构建。

## 页面结构

- Hero：BlueFocus AI 反白 Logo、标题切图、日期毛玻璃胶囊、数据平台 Logo，保持既定标题区高度；背景切图保持原始宽高比，背景层延伸到约半屏高度并渐隐至 0%，以 6% 正常混合显示。背景层必须处在 Hero 内部的 0 层，Hero 正文本身处于 1 层；Hero 本体保持透明，让页面 Canvas 渐变连续贯穿。不得使用负 z-index 或单独的非透明 Hero 底色，以避免 iframe 或移动端 WebView 出现顶部纯色断层、分层。
- 字体：英文和数字使用内嵌 Poppins；中文优先 `Noto Sans SC` / `Source Han Sans SC`，再回退到系统中文字体。默认不内嵌完整中文字体家族，以免单文件报告逼近 50 MiB 上传限制。
- 导航：从文档一级主板块提取，去除章节序号后，标题不超过 5 个字时必须原样使用；超过 5 个字时提炼为语义准确的 4 字标签。导航滚动后置顶，当前项使用白色胶囊。
- 主板块：白色外卡、独立渐变标题区、纯白正文区，最小中文字号 12px，正文以 13px 为主。
- 页尾：居中的热度值说明卡和 `Copyright@Bluefocus, 2026`。

## 数据卡与图表

- TOP/排名系列始终一行一卡。前 3 名使用 `assets/rank-1.svg` 至 `rank-3.svg`；其他排名统一使用仅包含数字的普通圆标，不显示“TOP”字样，第 4 名起使用蓝灰色标记与标题渐变。
- 行业 TOP10：卡片左侧约 40% 放排名、行业标题、热点总计和热度值；右侧约 60% 放主要驱动话题，两列两行。900px 以下改为上下排列。
- 行业 TOP10 使用卡片容器断点：可用卡片宽度小于 940px 时强制转为上下结构，不依赖发布环境的总页面宽度，以防标题、总计与热度值相互挤压。
- 平台热点词 TOP3：使用排名 SVG；热度值显示标题与进度条；具体热搜必须纵向排列。
- 热门事件 TOP 系列：以卡片容器宽度为断点。宽度低于 980px 时，排名/标题、热点总计、热度值分三行稳定呈现，具体热搜为两列；低于 520px 时具体热搜为单列。标题与指标行换行后的纵向间距维持紧凑（桌面/平板约 6px、手机约 7px），但不能用压缩间距替代自然换行。
- 导航：601–1140px 优先减少内边距并让四项均匀利用宽度；仍不足时允许导航自身横向滚动，禁止裁断任一导航文本。
- 中宽卡片：行业驱动话题在容器宽度达到 520px 时使用两列；热门事件卡在 521–980px 将热度与热点总计同行放置，以释放标题可用宽度。
- 行业卡头部：520–939px 时，排名、行业名称、热点总计与热度值保持同一行，避免热度值独占第二行；空间继续缩小时再堆叠且左对齐。
- 平台热点词：具体热搜在容器宽度达到 520px 时使用两列，低于 520px 时单列且左对齐，禁止在存在可用右侧空间时固定为单列。
- 热搜网格：使用内容驱动的 `auto-fit` 网格（单列最小宽度 220px），根据可用空间自动增加列数；不得因固定列数造成无必要换行。
- 极窄热门事件：热点总计与热度值仍与标题列对齐，不得退回排名图标左侧的整行起点。
- 热门事件标题对齐：容器宽度达到 521px 时，排名符号与主标题固定处于第一行，热点总计与热度固定处于第二行；主标题折行时，排名符号必须与标题文字块垂直居中，不得顶对齐或垂直居中到整个卡片头部。由于排名资产高于中文标题行，应用 8px 上移的光学校正。
- 排名差异校正：前三名奖牌 SVG 保持 8px 上移；第 4 名及之后的紧凑圆形排名标签使用 4px 上移。容器宽度达到 680px 时，热门事件标题必须单行展示，避免在有可用空间时无必要折行。
- 平台热点词头部：容器宽度达到 420px 时，排名、标题和热度值应在同一行利用右侧空间；不足时再将热度移至标题列下一行并左对齐。
- 上周节点汇总卡：以每一张节点卡自身宽度判断。单卡宽度达到 420px 时，节点名称与热点总计位于左侧，热度值与进度条位于右侧同一标题行；不得使用双列网格的总宽度判断子卡布局。更窄时回落为左对齐的上下结构，禁止将节点名称压成竖排。
- 热度条：使用现有 10 档冷暖色方案，数值写在进度条内，不在条后重复。
- 具体热搜与具体热搜·平台·热度值：列表正文使用纯文本，不添加点、短横线或竖线分隔装饰。主要驱动话题是唯一例外：项目项目前保留与正文同色的小圆点，不使用竖线；包括第一项在内的每项均保留 10px 左侧文字间距。
- 品牌合作动态：卡片标题区仅展示行业标签，不展示“事件”或“合作事件”通用标签。
- 行业气泡图：横轴为热点数量，纵轴为中位热度分，气泡大小代表热点数量，气泡与图例使用多色渐变，悬浮显示数值。
- 品牌舆情风险：不使用排名色逻辑，每张卡片使用不同柔和渐变；原始热搜保留链接。风险类型分组与事件卡固定使用纵向单列，避免风险影响和多条热搜在双列中被压缩。
- 营销观察：桌面端一行两卡，左文右图，图片 1:1；标题字号 18px，案例名称前不添加 Emoji 图标。案例图必须置于 1:1 容器，以 `object-fit: cover`、`object-position: center` 居中裁切；桌面端和移动端都不得改为完整缩放或留下大面积留白。
- 营销观察的每个 `docx-grid-block` 必须在自身 `images[0].src` 中指向当期源文档里的原始案例图片。禁止使用任何 AI 图片生成、网络搜图、模板旧图或自制占位图代替。飞书内容必须同时读取 `rawContent` 和 blocks，根据图片块的 image token 下载原图，再将本地路径或 Data URL 写入 `images[0].src`。可使用 `data:image/...`、`file://`、绝对路径，或相对输入 JSON 的本地路径；不得保留仅在原浏览器会话有效的 `blob:` 地址。如果无法下载源文档原图，必须停止并向用户索取文档导出或原始图片。（Topic6 例外：配图只来自 HC3 人工上传，缺图渲染「配图待补充」占位、非阻断，见 SKILL.md 顶部 Topic6 说明。）
- 消费洞察：白色外卡、柔和渐变标题区和无内嵌小卡的白色正文区。

## 响应式与可用性

- 至少检查 390px、768px、1024px 和桌面宽度。
- 移动端导航不得造成页面水平溢出；卡片头部、热度条和元数据允许换行，不得撑破卡片。
- 移动端必须保持整页纵向触摸滚动；导航和 Tab 的触摸区域不得拦截纵向手势，不显示系统点击高亮或残留 hover 色块。
- 平台新鲜事卡片标题使用“行业名称丨事件标题”格式，不再单独显示行业标签。热门事件 TOP 5 的三条具体热搜在宽度足够时使用三列一行，移动端使用两列两行；移动端热点总计与热度值位于标题下一行，超窄屏时热度值再独立一行。
- 行业热点卡片在手机端使用内容驱动换行：短行业名称与热点总计保持同排；行业名称较长时仍优先完整占据第一行，热点总计进入第二行。热度值在第二行空间充足时与热点总计同排，否则进入第三行，且不得相互叠压。
- 平台热点词卡片在手机端将热度组件与标题左边缘对齐。
- 移动端页尾热度值说明保持横向结构并在容器内垂直居中，“热度值说明：”不得折行，说明正文可以自然换行。
- 交互元素使用语义 HTML、清晰焦点态和至少 44px 触控区。
- 链接默认不显示下划线，hover/键盘聚焦时显示。
- 尊重 `prefers-reduced-motion`，打印时隐藏导航、进度与回到顶部控件。

## 必须验证

```bash
node <skill-directory>/scripts/validate-template-assets.mjs
node --check build-report.mjs
node build-report.mjs /absolute/path/report.source.json /absolute/path/index.html
```

验证周刊/月刊标题选择、导航置顶、所有链接、Tab 切换、图表悬浮、TOP 排名、热度条、案例图片、移动端无水平溢出和页尾居中。构建后必须运行 `validate-rendered-content.mjs`，确认每个有效源段落、表格值、链接与案例标题均被呈现，且案例数与源文档一致。
